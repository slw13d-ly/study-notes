# 02. 화면 설계

## SECTION 011. 사용자 인터페이스

### 1. 사용자 인터페이스(UI, User Interface)의 개요
- **사용자 인터페이스(UI)** - 사용자와 시스템 간의 상호작용이 원활하게 이루어지도록 도와주는 **장치나 소프트웨어**
- 좁은 의미
  - 정보 기기나 소프트웨어의 **화면 등에서 사람이 접하게 되는 표현 방식**
- 넓은 의미
  - 사용자와 시스템 사이의 상호작용을 가능하게 하는 **물리적·가상적 매개체 전체**

#### 사용자 인터페이스의 세 가지 분야
- 정보 제공과 전달을 위한 **물리적 제어**
- 콘텐츠의 상세 표현과 전체적인 구성
- 모든 사용자가 편리하고 간편하게 사용할 수 있도록 하는 기능

> ⭐ `UI = 사용자 ↔ 시스템의 상호작용을 위한 매개체`

---

### 2. 사용자 인터페이스(UI)의 특징
- 사용자의 만족도에 가장 큰 영향을 미치는 중요한 요소
- 소프트웨어 영역 중 **변경이 가장 많이 발생**
- 사용자의 편리성과 가독성을 높여 작업 시간을 단축시킴
- 최소한의 노력으로 원하는 결과를 얻을 수 있도록 함
- **사용자 중심**으로 설계되어야 함
- 수행 결과의 오류를 줄일 수 있음
- 사용자의 작업 기능에 대해 **구체적인 방법을 제시**
- 정보 제공자와 공급자의 **의사소통 매개 역할**
- UI를 설계하기 위해서는 **소프트웨어 아키텍처를 반드시 숙지**해야 함

> ⭐ `UI 핵심 = 사용자 중심 + 편리성 + 의사소통 + 오류 감소`

---

### 3. 사용자 인터페이스의 구분

| 구분 | 핵심 |
|---|---|
| **CLI(Command Line Interface)** | 명령과 출력이 **텍스트 형태**로 이루어지는 인터페이스 |
| **GUI(Graphical User Interface)** | 아이콘이나 메뉴를 마우스로 선택하여 작업을 수행하는 **그래픽 환경** |
| **NUI(Natural User Interface)** | 사용자의 **말이나 행동**으로 기기를 조작 |
| **VUI(Voice User Interface)** | 사용자의 **음성**으로 기기를 조작 |
| **OUI(Organic User Interface)** | 사물과 사용자 사이의 자연스러운 상호작용을 위한 인터페이스 |

> ⭐ `CLI = 문자`  
> ⭐ `GUI = 그래픽`  
> ⭐ `NUI = 말·행동`  
> ⭐ `VUI = 음성`

---

### 4. 사용자 인터페이스의 기본 원칙

| 원칙 | 핵심 |
|---|---|
| **직관성** | 누구나 쉽게 이해하고 사용할 수 있어야 함 |
| **유효성** | 사용자의 목적을 정확하고 완벽하게 달성해야 함 |
| **학습성** | 누구나 쉽게 배우고 익힐 수 있어야 함 |
| **유연성** | 사용자의 요구사항을 최대한 수용하고 실수를 최소화해야 함 |

> ⭐ UI 기본 원칙 → `직·유·학·유`  
> `직관성 / 유효성 / 학습성 / 유연성`

---

### 5. 사용자 인터페이스의 설계 지침

| 설계 지침 | 핵심 |
|---|---|
| **사용자 중심** | 사용자가 쉽게 이해하고 편리하게 사용할 수 있는 환경 제공 |
| **사용성** | 사용자가 소프트웨어를 쉽고 빠르게 이해하고 사용할 수 있도록 함 |
| **일관성** | 버튼, 메뉴, 용어, 레이아웃 등을 일관성 있게 사용 |
| **단순성** | 조작 방법을 단순화하여 인지적 부담 최소화 |
| **결과 예측 가능** | 사용자가 수행한 기능의 결과를 쉽게 예측할 수 있도록 함 |
| **가시성** | 주요 기능을 메인 화면에 노출하여 쉽게 찾도록 함 |
| **표준화** | 기능 구조와 디자인을 표준화하여 학습 후 쉽게 사용 |
| **접근성** | 연령, 성별 등 다양한 사용자가 이용할 수 있도록 설계 |
| **명확성** | 사용자가 개념적으로 쉽게 이해할 수 있도록 설계 |
| **오류 발생 해결** | 오류가 발생한 경우 사용자가 쉽게 인지하고 해결할 수 있도록 함 |

> ⭐ `UI 설계 지침 = 사용자 중심 + 일관성 + 단순성 + 예측 가능 + 접근성`

---

### 6. 사용자 인터페이스 개발 시스템의 기능
- 사용자의 입력을 **검증**
- 에러 처리와 관련된 **에러 메시지를 표시**
- 도움과 프롬프트(**Prompt**)를 제공

> ⭐ `UI 시스템 기능 = 입력 검증 + 오류 메시지 + 도움/Prompt`

---

## SECTION 012. UI 설계 도구

### 1. UI 설계 도구
- 사용자의 요구사항에 맞게 **UI의 화면 구조나 화면 배치 등을 설계할 때 사용하는 도구**
- 종류
  - 와이어프레임
  - 목업
  - 스토리보드
  - 프로토타입
  - 유스케이스

> ⭐ UI 설계 도구 → `와·목·스·프·유`

---

### 2. 와이어프레임(Wireframe)
- **기획 단계의 초기에 제작**
- 페이지에 대한 개략적인 레이아웃이나 **UI 요소 등에 대한 뼈대**를 설계
- 화면의 영역 구분, 콘텐츠, 텍스트 배치 등을 표현
- 개발자와 디자이너가 레이아웃을 협의하거나 현재 진행 상태를 공유하는 용도로 사용
- 대표 도구
  - 손그림
  - 파워포인트
  - 키노트
  - 스케치
  - 일러스트
  - 포토샵 등

> ⭐ `Wireframe = 화면의 뼈대 / 초기 레이아웃`

---

### 3. 목업(Mockup)
- 디자인, 사용 방법, 평가 등을 위해 **실제 화면과 유사하게 만든 정적인 형태의 모형**
- 시각적으로만 구성 요소를 배치한 것으로 **실제로 구현되지는 않음**
- 대표 도구
  - 파워 목업
  - 발사믹 목업 등

> ⭐ `Mockup = 실제 화면처럼 보이지만 동작 X`

---

### 4. 스토리보드(Story Board)
- 와이어프레임에
  - 콘텐츠 설명
  - 페이지 간 이동 흐름

  등을 추가한 문서
- 개발자와 디자이너 간의 작업 지침서
- 서비스 구축을 위한 정책, 프로세스, 콘텐츠 구성, 와이어프레임, 기능 정의 등을 포함
- 화면 간 이동·분기 등을 **디스크립션(Description)**으로 기록
- 디스크립션에는
  - 화면 설명
  - 전반적인 로직
  - 분기 처리
  - 예외 처리

  등을 상세히 작성
- 대표 도구
  - 파워포인트
  - 키노트
  - 스케치
  - Axure 등

> ⭐ `Storyboard = Wireframe + 설명 + 화면 흐름`

---

### 5. 프로토타입(Prototype)
- 와이어프레임이나 스토리보드 등에 **인터랙션을 적용하여 실제 구현된 것처럼 테스트 가능한 동적인 모형**
- 사용성 테스트나 작업 방식 검증에 사용
- 작성 방법
  - **페이퍼 프로토타입**
  - **디지털 프로토타입**
- 대표 도구
  - HTML/CSS
  - Axure
  - Flinto
  - 네이버 프로토나우
  - 카카오 오븐 등

> ⭐ `Prototype = 실제처럼 동작하는 테스트용 모형`

---

### 6. 유스케이스(Use Case)
- 사용자의 측면에서 **요구사항을 표현한 것**
- 사용자가 원하는 목표를 달성하기 위해 수행할 내용을 기술
- 사용자의 요구사항을 빠르게 파악하여 시스템의 기능적 요구를 결정하고 문서화
- 자연어로 작성된 요구사항을 **구조적으로 표현**
- 일반적으로 다이어그램으로 작성
- 각각의 유스케이스에 대해 **유스케이스 명세서**를 작성

> ⭐ `Use Case = 사용자 관점의 기능적 요구사항 표현`

---

### 7. UI 설계 도구 비교

| 도구 | 핵심 |
|---|---|
| **Wireframe** | 화면 뼈대 |
| **Mockup** | 정적 화면 모형 |
| **Storyboard** | 화면 뼈대 + 설명 + 이동 흐름 |
| **Prototype** | 실제처럼 동작하는 동적 모형 |
| **Use Case** | 사용자 관점의 기능·요구 표현 |

> ⭐ `와뼈 / 목정 / 스흐 / 프동 / 유요`

---

## SECTION 013. 품질 요구사항

### 1. 품질 요구사항
- **소프트웨어 품질** - 소프트웨어의 기능, 성능, 만족도 등 소프트웨어에 대한 요구사항을 얼마나 충족하는지를 나타내는 특성
- 소프트웨어 품질을 객관적으로 평가하기 위한 **국제 표준**이 사용됨

---

### 2. ISO/IEC 9126
- 소프트웨어 품질 특성과 평가를 위한 국제 표준
- 주요 품질 특성
  - **기능성(Functionality)**
  - **신뢰성(Reliability)**
  - **사용성(Usability)**
  - **효율성(Efficiency)**
  - **유지보수성(Maintainability)**
  - **이식성(Portability)**

> ⭐ ISO/IEC 9126 → `기·신·사·효·유·이`

---

### 3. ISO/IEC 25010
- 소프트웨어 제품 품질에 관한 국제 표준
- ISO/IEC 9126을 개정하여 발전시킨 모델
- 주요 특성
  - 기능 적합성
  - 성능 효율성
  - 호환성
  - 사용성
  - 신뢰성
  - 보안성
  - 유지보수성
  - 이식성

> ⭐ `ISO/IEC 25010 = 9126을 확장·개선`

---

### 4. 기능성(Functionality)
- 소프트웨어가 사용자의 요구사항을 **정확하게 만족하는 기능을 제공하는지**를 나타냄

| 세부 품질 요구사항 | 핵심 |
|---|---|
| **적절성/적합성(Suitability)** | 지정된 작업과 사용자 목적에 적절한 기능 제공 |
| **정밀성/정확성(Accuracy)** | 사용자가 요구하는 결과를 정확하게 산출 |
| **상호 운용성(Interoperability)** | 다른 시스템과 상호 교환할 수 있는 능력 |
| **보안성(Security)** | 정보에 대한 접근을 권한에 따라 허용·차단 |
| **준수성(Compliance)** | 기능 관련 표준·규정을 준수 |

> ⭐ `기능성 = 적정상보준`

---

### 5. 신뢰성(Reliability)
- 소프트웨어가 요구된 기능을 정확하고 안정적으로 수행할 수 있는 정도

| 세부 품질 요구사항 | 핵심 |
|---|---|
| **성숙성(Maturity)** | 결함으로 인한 고장을 피할 수 있는 능력 |
| **고장 허용성(Fault Tolerance)** | 결함 또는 인터페이스 오류에도 지정된 성능 수준 유지 |
| **회복성(Recoverability)** | 고장 발생 시 성능 수준을 회복하고 데이터를 복구 |

> ⭐ `신뢰성 = 성숙 / 고장 허용 / 회복`

---

### 6. 사용성(Usability)
- 사용자가 소프트웨어를 **이해·학습·운용하고 선호할 수 있는 정도**

| 세부 품질 요구사항 | 핵심 |
|---|---|
| **이해성(Understandability)** | 사용 방법을 이해할 수 있는 정도 |
| **학습성(Learnability)** | 사용 방법을 학습하기 쉬운 정도 |
| **운용성(Operability)** | 사용자가 소프트웨어를 운용·제어하기 쉬운 정도 |
| **친밀성(Attractiveness)** | 사용자가 소프트웨어를 선호할 수 있도록 하는 능력 |

> ⭐ `사용성 = 이·학·운·친`

---

### 7. 효율성(Efficiency)
- 사용자가 요구하는 기능을 **할당된 시간 동안 한정된 자원으로 얼마나 빨리 처리할 수 있는지**

| 세부 품질 요구사항 | 핵심 |
|---|---|
| **시간 효율성(Time Behaviour)** | 적절한 반응 시간과 처리율을 제공 |
| **자원 효율성(Resource Behaviour)** | 적절한 자원의 양과 종류를 사용 |

> ⭐ `효율성 = 시간 + 자원`

---

### 8. 유지보수성(Maintainability)
- 환경 변화나 새로운 요구사항 발생 시 소프트웨어를 **개선·확장할 수 있는 정도**

| 세부 품질 요구사항 | 핵심 |
|---|---|
| **분석성(Analyzability)** | 결함·고장의 원인이나 수정할 부분을 식별 |
| **변경성(Changeability)** | 결함 제거 또는 변경을 쉽게 수행 |
| **안정성(Stability)** | 변경으로 인한 예상치 못한 결과를 최소화 |
| **시험성(Testability)** | 변경된 소프트웨어를 검증하기 쉬움 |

> ⭐ `유지보수성 = 분·변·안·시`

---

### 9. 이식성(Portability)
- 소프트웨어가 다른 환경에서도 **얼마나 쉽게 적용될 수 있는지**

| 세부 품질 요구사항 | 핵심 |
|---|---|
| **적용성(Adaptability)** | 원래 목적과 다른 환경에서도 적용 가능 |
| **설치성(Installability)** | 지정된 환경에 쉽게 설치 |
| **대체성(Replaceability)** | 동일 환경에서 다른 소프트웨어를 대신할 수 있음 |
| **공존성(Co-existence)** | 동일 환경에서 다른 소프트웨어와 자원을 공유하며 공존 |

> ⭐ `이식성 = 적·설·대·공`

---

## SECTION 014. UI 상세 설계

### 1. UI 시나리오 문서의 개요
- **UI 상세 설계** - UI 설계서를 바탕으로 실제 설계 및 구현을 위해 모든 화면에 대한 자세한 설계를 진행하는 단계
- UI 상세 설계를 할 때는 **UI 시나리오 문서** 작성
- UI 시나리오 문서는 사용자가 최종 목표를 달성하기 위해 수행하는 방법의 순서를 구체적으로 표현
- UI 설계자는 UI 시나리오 문서를 작성하고, 디자이너나 개발자가 이를 바탕으로 구현

> ⭐ `UI 상세 설계 = UI 시나리오 문서를 구체적으로 작성`

---

### 2. UI 시나리오 문서 작성 원칙
- 개발자가 전체적인 UI 기능과 작동 방식을 **한눈에 이해할 수 있도록 구체적으로 작성**
- 보통 **Tree 구조 또는 Flow Chart** 표기법 사용
- 모든 기능에 공통으로 적용될 **UI 요소와 인터랙션을 일반 규칙으로 정의**
- 대표 화면의 레이아웃과 그 화면에서 수행할 기능을 정의
- 인터랙션 흐름을 정의하며 다음 항목을 사용
  - **Sequence**
  - **Branch**
  - **Condition**
  - **Loop**
- 예외 상황에서 인터랙션의 흐름을 정의
- UI 일반 규칙을 지키면서 기능별 상세 기능 시나리오 정의
- UI 시나리오 규칙을 지정

> ⭐ `UI 시나리오 = 화면 구조 + 인터랙션 흐름 + 예외 상황`

---

### 3. UI 시나리오 문서 작성을 위한 일반 규칙

| 규칙 | 핵심 |
|---|---|
| **주요 키의 위치와 기능** | 모든 화면에 공통적으로 배치되는 주요 키의 위치·기능 설명 |
| **공통 UI 요소** | 체크박스, 라디오 버튼, 텍스트 박스 등 공통 UI 요소 정의 |
| **기본 스크린 레이아웃** | 공통적으로 나타나는 제목·버튼·메뉴 등의 위치 정의 |
| **기본 인터랙션 규칙** | 클릭·선택·이동 등 인터랙션 방식 정의 |
| **공통 단위 태스크 흐름** | 사용자가 특정 기능을 수행할 때의 공통 흐름 정의 |
| **케이스 문서** | 다양한 상황에서의 예외적 인터랙션 사례 정의 |

> ⭐ `주요 키 / 공통 UI / 레이아웃 / 인터랙션 / 태스크 흐름 / 케이스`

---

### 4. UI 요소

| UI 요소 | 핵심 |
|---|---|
| **체크 박스(Check Box)** | 여러 선택지 중 **0개 이상 복수 선택** 가능 |
| **라디오 버튼(Radio Button)** | 여러 항목 중 **1개만 선택** |
| **텍스트 박스(Text Box)** | 사용자가 텍스트를 입력 |
| **콤보 박스(Combo Box)** | 입력하거나 목록에서 선택할 수 있는 방식 |
| **목록 상자(List Box)** | 목록에 표시된 항목 중 하나 이상의 항목 선택 |

> ⭐ `Check Box = 복수 선택`  
> ⭐ `Radio Button = 단일 선택`

---

### 5. UI 시나리오 문서의 요건

| 요건 | 핵심 |
|---|---|
| **완전성(Complete)** | 누락 없이 상세히 기술 / 모든 기능보다 UI에 집중하여 작성 |
| **일관성(Consistent)** | 서비스 목표, 시스템·사용자 요구사항, UI 스타일 등이 일관되어야 함 |
| **이해성(Understandable)** | 누구나 쉽게 이해할 수 있도록 설명 |
| **가독성(Readable)** | 문장을 쉽게 읽을 수 있고, 표준 형식·용어를 사용 |
| **수정 용이성(Modifiable)** | 시나리오 수정이 쉬워야 함 |
| **추적 용이성(Traceable)** | 변경 사항과 요구사항 간 관계를 쉽게 추적할 수 있어야 함 |

> ⭐ `UI 시나리오 요건 = 완·일·이·가·수·추`

---

### 6. UI 시나리오 문서로 인한 기대 효과
- 요구사항이나 의사소통에 대한 오류 감소
- 개발 과정에서의 재작업 감소 및 혼선 최소화
- 불필요한 기능 최소화
- 소프트웨어 개발 비용 절감
- 개발 속도 향상

> ⭐ `시나리오 문서 = 오류↓ / 재작업↓ / 비용↓ / 개발 속도↑`

## SECTION 015. HCI / UX / 감성공학

### 1. HCI(Human Computer Interaction or Interface)
- 사람이 시스템을 보다 **편리하고 안전하게 사용할 수 있도록 연구·개발하는 학문**
- 최적의 사용자 경험(UX)을 만드는 것이 목표
- 단순히 컴퓨터뿐만 아니라
  - 서비스
  - 디지털 콘텐츠

  등과의 상호작용도 포함
- 어떤 제품이 좋은 제품인지, 어떻게 하면 좋은 제품을 만들 수 있는지 연구

> ⭐ `HCI = 사람과 시스템의 상호작용을 연구 → 최적 UX 목표`

---

### 2. UX(User Experience)
- 사용자가 시스템이나 서비스를 이용하면서 느끼고 생각하게 되는 **총체적인 경험**
- 기술 자체뿐 아니라
  - 상품
  - 서비스
  - 회사와의 상호작용

  을 통해 얻게 되는 모든 경험 포함
- 삶의 질 향상과 관련
- 제품 사용 전·중·후에 느끼는 모든 경험을 포함

#### UX의 특징

| 특징 | 핵심 |
|---|---|
| **주관성(Subjectivity)** | 사람의 개인적·신체적·인지적 특성에 따라 다름 |
| **정황성(Contextuality)** | 경험이 일어나는 상황 또는 주변 환경에 영향을 받음 |
| **총체성(Holistic)** | 개인이 느끼는 총체적인 심리적·감성적 결과 |

> ⭐ `UX = 주·정·총`  
> `주관성 / 정황성 / 총체성`

---

### 3. 감성공학
- 제품이나 작업환경을 **사용자의 감성에 알맞도록 설계·제작하는 기술**
- 인간의 삶을 편리하고 안전하며 쾌적하게 만드는 것이 목적
- 인간의 감성을 제품 설계에 적용
- 인간과 컴퓨터의 상호작용을 나타내는 HCI 설계에서 인간의 특성과 감성을 반영
- 관련 요소
  - 공학적 접근
  - 인간 감성의 정성적·정량적 측정
  - 제품 설계 적용

#### 감성공학의 요소 기술
- **기초 기술**
  - 제품 설계에 적용할 인간의 특성을 파악
- **구현 기술**
  - 인간의 특성에 맞는 인터페이스 구현
- **응용 기술**
  - 인간에 맞는 새로운 감성을 창출

> ⭐ `감성공학 = 인간 감성 → 제품·인터페이스 설계에 반영`
