# 05. 데이터 전환

## SECTION 090. 데이터 전환

### 1. 데이터 전환의 개요
- **데이터 전환(Data Conversion)** - 운영 중인 기존 정보 시스템에 축적되어 있는 데이터를 추출(Extraction)하여 새로 개발할 정보 시스템에서 운영 가능하도록 **변환(Transformation)한 후 적재(Loading)**하는 일련의 과정
- 데이터 전환은 **ETL(Extraction, Transformation, Load)**, 즉 **추출 → 변환 → 적재** 과정이라고도 함
- **데이터 이행(Data Migration)** 또는 **데이터 이관**이라고도 함

> ⭐ `데이터 전환 = 기존 시스템 데이터 → 추출 → 변환 → 새 시스템에 적재`  
> ⭐ `ETL = Extraction → Transformation → Load`

### 2. 데이터 전환 계획서
- **데이터 전환 계획서** - 데이터 전환이 필요한 대상을 분석하여 데이터 전환 작업에 필요한 **모든 계획을 기록하는 문서**

#### 데이터 전환 계획서의 주요 항목

| 항목 | 세부 항목 |
|---|---|
| **데이터 전환 개요** | 데이터 전환 목표 / 주요 성공 요인 / 전제조건 및 제약조건 |
| **데이터 전환 대상 및 범위** | 전환할 데이터의 대상과 범위 |
| **데이터 전환 환경 구성** | 원천 시스템 구성도 / 목적 시스템 구성도 / 전환 단계별 DISK 사용량 |
| **데이터 전환 조직 및 역할** | 데이터 전환 조직도 / 조직별 역할 |
| **데이터 전환 일정** | 데이터 전환 전체 일정 |
| **데이터 전환 방안** | 데이터 전환 규칙 / 절차 / 방법 / 설계 / 전환 프로그램 개발 및 테스트 계획 / 데이터 전환 계획 / 데이터 검증 방안 |
| **데이터 정비 방안** | 데이터 정비 대상 및 방법 / 데이터 정비 일정 및 조직 |
| **비상 계획** | 종합상황실 및 의사소통 체계 |
| **데이터 복구 대책** | 데이터 전환 오류·장애에 대비한 복구 대책 |

> ⭐ 데이터 전환 계획서는 단순 일정표가 아니라 **대상·환경·조직·일정·전환·정비·비상·복구**까지 포함

### 3. 데이터 전환에서 자주 구분하는 시스템
- **원천 시스템(Source System)** - 전환할 데이터가 현재 존재하는 기존 시스템
- **목적 시스템(Target System)** - 변환된 데이터를 적재하여 새롭게 사용할 시스템

> ⭐ `원천 = 기존 / 목적 = 신규`

## SECTION 091. 데이터 전환 방안

### 1. 데이터 전환 방안
- 데이터 전환 방안에는 다음 내용을 포함

```text
데이터 전환 규칙
→ 데이터 전환 절차
→ 데이터 전환 방법
→ 데이터 전환 설계
→ 전환 프로그램 개발 및 테스트 계획
→ 데이터 전환 계획
→ 데이터 검증 방안
```

### 2. 데이터 전환 규칙
- 데이터 전환 과정에서 **공통적으로 적용해야 할 규칙**을 기술

> ⭐ `전환 규칙 = 전환 과정 전체에 공통 적용`

### 3. 데이터 전환 절차
- 데이터 전환 작업이 진행되는 절차를 **체계적으로 상세하게 기술**
- 데이터 전환 절차 수립 시 작업의 이해를 돕기 위해 **데이터 흐름도**를 작성

#### 데이터 전환 절차의 흐름
```text
전환 준비
→ 전환 설계/개발
→ 전환 테스트
→ 전 데이터 전환
→ 최종 전환 및 검증
```

> ⭐ `준비 → 설계/개발 → 테스트 → 전 데이터 전환 → 최종 전환·검증`

### 4. 데이터 전환 방법
- **단위 업무별**로 데이터 전환 방법을 기술
- 데이터 전환 시 업무별로 요구되는 **전제 조건도 함께 기술**

> ⭐ `전환 방법 = 업무별 방법 + 전제 조건`

### 5. 데이터 전환 설계
- 업무별로
  - **전환 대상**
  - **전환 제외 내용**

  을 기술
- 관련 시스템의 테이블과 목적 시스템 테이블의 **매핑 정의서**를 작성

> ⭐ `전환 설계 = 무엇을 옮길지 결정 + 원천/목적 테이블 매핑`

### 6. 전환 프로그램 개발 및 테스트 계획
- **전환 프로그램 개발 계획 + 전환 프로그램 테스트 계획**을 수립

#### 전환 프로그램 개발 계획
- 전환 프로그램은 목록별로 다음 정보를 작성
  - 프로그램 입력 정보
  - 중간 생성 정보
  - 출력 정보
  - 프로그램 위치
  - 담당자 등
- 원천 시스템에서 사용하는 데이터를 목적 시스템으로 전환하기 위한 **세부 데이터 항목을 정의**
- 담당자 등을 포함하여 관리

#### 전환 프로그램 테스트
- 전환 프로그램을 **시나리오를 기반으로 실시**
- 실제 전환 시나리오에 반영하여 테스트

> ⭐ `전환 프로그램 = 입력 / 중간 생성 / 출력 / 위치 / 담당자`  
> ⭐ `테스트 = 시나리오 기반`

### 7. 데이터 전환 계획
- 데이터 전환 시간을 단축하기 위해 **사전 전환 / 본 전환 / 후 전환**으로 구분하여 계획 수립

#### 사전 전환
- 일자별 거래 내역, 일자별 근태 내역처럼 **대량의 데이터 테이블을 사전에 전환**

#### 본 전환
- 실제 본 전환에 대한 세부 절차를 **시간대별로 상세하게 작성**
- 본 전환 이전의 전환을 수행하여 **본 전환 소요 시간을 측정**
- 실제 전환 작업의 소요 시간을 파악

#### 후 전환
- 본 전환 이후부터 **전환 종료 시점까지 발생한 신규 내용** 등을 정의하여 전환

#### 전체 작업 관리
- 전환 작업 준비부터
  - 전 전환
  - 본 전환
  - 전환 점검
  - 시스템 오픈
  - 후 전환

  등 작업을 진행
- 작업 담당자, 관리자 등을 지정하여 체계적으로 수행

> ⭐ `전환 시간 단축 = 사전 전환 → 본 전환 → 후 전환`

### 8. 데이터 검증 방안
- 데이터 전환 **이전**
  - 전환 데이터의 **정합성 검증**
- 데이터 전환 **과정**
  - 발생 가능한 문제에 대응할 수 있도록 단계별 **데이터 전환 검증 방안** 수립

> ⭐ `검증 방안 = 전환 전 정합성 확인 + 전환 단계별 검증`

## SECTION 092. 데이터 검증

### 1. 데이터 검증
- **데이터 검증** - 원천 시스템의 데이터를 목적 시스템의 데이터로 전환하는 과정이 **정상적으로 수행되었는지 여부를 확인하는 과정**
- 데이터 전환 검증은
  - **검증 방법**
  - **검증 단계**

  에 따라 분류할 수 있음

> ⭐ `데이터 검증 = 전환이 정상적으로 수행되었는지 확인`

### 2. 검증 방법에 따른 분류

| 검증 방법 | 핵심 |
|---|---|
| **로그 검증** | 데이터 전환 과정에서 작성되는 **추출·전환·적재 로그** 검증 |
| **기본 항목 검증** | 로그 검증 외에 **별도로 요청된 검증 항목** 검증 |
| **응용 프로그램 검증** | **응용 프로그램을 통한 데이터 전환의 정합성** 검증 |
| **응용 데이터 검증** | 사전에 정의된 **업무 규칙**을 기준으로 데이터 전환 정합성 검증 |
| **값 검증** | 숫자 항목의 **합계**, 코드 데이터의 **범위**, 속성 변경에 따른 **값** 검증 |

> ⭐ `로그 = 추출·전환·적재 기록`  
> ⭐ `응용 프로그램 = 프로그램으로 확인`  
> ⭐ `응용 데이터 = 업무 규칙 기준`  
> ⭐ `값 = 합계·범위·속성값`

### 3. 검증 단계에 따른 분류
- 원천 데이터 추출부터 전환 완료 후까지 단계별로 목적과 검증 방법을 달리하여 데이터 전환의 정합성을 검증

| 검증 단계 | 목적 | 검증 방법 |
|---|---|---|
| **추출** | 원천 시스템 데이터에 대한 **정합성 확인** | 로그 검증 |
| **전환** | 매핑 정의서 내용의 정확한 반영 여부 / **매핑 정의서 오류 여부 확인** | 로그 검증 |
| **DB 적재** | SAM 파일 적재 과정에서 발생 가능한 **오류·데이터 누락 여부 확인** | 로그 검증 |
| **DB 적재 후** | 적재 완료 후 **정합성 확인** | 기본 항목 검증 |
| **전환 완료 후** | 추가 검증을 통한 데이터 전환의 **정합성 검증** | 응용 프로그램 검증 / 응용 데이터 검증 |

> ⭐ `추출·전환·DB적재 = 로그 검증`  
> ⭐ `DB 적재 후 = 기본 항목 검증`  
> ⭐ `전환 완료 후 = 응용 프로그램·응용 데이터 검증`

### 4. 정합성
- **정합성** - 데이터가 서로 모순 없이 **일관되게 일치하는 성질**

> ⭐ `정합성 = 데이터가 서로 모순 없이 일치`

## SECTION 093. 오류 데이터 측정 및 정제

### 1. 오류 데이터 측정 및 정제의 개요
- **오류 데이터 측정 및 정제** - 고품질의 데이터를 운영·관리하기 위해 수행
- 진행 순서

```text
데이터 품질 분석
→ 오류 데이터 측정
→ 오류 데이터 정제
```

> ⭐ `품질 분석 → 오류 측정 → 오류 정제`

### 2. 데이터 품질 분석
- 오류 데이터를 찾기 위해 **원천 및 목적 시스템 데이터의 정합성 여부를 확인**하는 작업

### 3. 원천 시스템 데이터의 대표적인 정합성 점검 항목
- 필수 항목에 해당하는 데이터가 **모두 존재하는가?**
- 문자형·숫자형·날짜형 등 데이터의 **유형이 올바르게 관리되는가?**
- 날짜는 **유효한 날짜 형태인가?**
- 금액은 **유효한 값의 범위인가?**
- 계좌번호·카드·코드값은 **정상적으로 존재하는 번호인가?**
- 영업점은 **실제로 존재하는가?**
- 업무 규칙에 위배되는 **잘못된 정보는 없는가?**
- 보고서값과 실제 데이터값이 **일치하는가?**
- 잔액은 회계 정보와 **일치하는가?**

> ⭐ 원천 데이터 품질 → `필수값 / 자료형 / 날짜 / 범위 / 코드 / 존재 여부 / 업무 규칙 / 보고서 / 잔액`

### 4. 목적 시스템 데이터의 대표적인 정합성 점검 항목
- 과목별 **잔액·건수 및 잔액** 확인
- 특정 기준으로 분류한 **건수 및 잔액** 확인
- 보고서 항목 또는 **통계 수치** 확인
- 계좌 및 고객을 **샘플링하여 해당 사항 확인**
- 특수 관계의 고객에 대한 **데이터 확인**

> ⭐ 목적 데이터 품질 → `잔액·건수 / 통계 / 샘플링 / 특수 관계 데이터`

### 5. 오류 데이터 측정
- 데이터 품질 분석을 기반으로 **정상 데이터와 오류 데이터의 수를 측정**
- 오류 관리 목록을 작성

#### 정상 데이터 측정
- 전환 대상 범위의 데이터를
  - 업무 영역별
  - 테이블별

  로 구분하여 **수량을 측정·기재**

#### 오류 데이터 측정
- 업무별로
  - 오류 위치
  - 오류 유형

  을 확인하여 **수량을 측정·기재**

> ⭐ `정상 데이터 = 업무·테이블별 수량`  
> ⭐ `오류 데이터 = 업무별 오류 위치·유형별 수량`

### 6. 오류 데이터 정제
- 오류 관리 목록의 각 항목을 분석하여
  - **원천 데이터를 정제**하거나
  - **전환 프로그램을 수정**

  하는 과정

> ⭐ `오류 정제 = 원천 데이터 수정 OR 전환 프로그램 수정`

### 7. 오류 데이터 분석
- 오류 관리 목록의 오류 데이터를 분석하여 다음 내용을 확인·기재
  - **오류 상태**
  - **심각도**
  - **해결 방안**

### 8. 오류 상태

| 상태 | 의미 |
|---|---|
| **Open** | 오류가 보고만 되고 **분석되지 않은 상태** |
| **Assigned** | 오류의 영향 분석 및 수정을 위해 **개발자에게 오류를 전달한 상태** |
| **Fixed** | **개발자가 오류를 수정한 상태** |
| **Closed** | 수정된 오류를 다시 테스트했을 때 **오류가 발견되지 않은 상태** |
| **Deferred** | 오류 수정을 **연기한 상태** |
| **Classified** | 보고된 오류를 관련자들이 확인했을 때 **오류가 아니라고 확인된 상태** |

> ⭐ 오류 상태 흐름 핵심  
> `Open → Assigned → Fixed → Closed`  
> ⭐ `Deferred = 연기 / Classified = 오류 아님`

### 9. 오류 심각도

| 심각도 | 의미 |
|---|---|
| **상** | **데이터 전환을 수행할 수 없는 오류** |
| **중** | 데이터 전환 **전반에 영향을 미치는 오류** |
| **하** | 데이터 전환에 직접적인 영향은 없지만 **상황에 맞지 않는 용도 및 배치 오류** |

> ⭐ `상 = 전환 불가 / 중 = 전체 영향 / 하 = 직접 영향 X`

### 10. 해결 방안
- **수정 가능한 오류**
  - 오류 해결 방안을 작성
- **수정 불가능한 오류**
  - 고객과 협의하여 **협의 결과를 기재**

### 11. 오류 관리 목록
- 오류 관리 목록에는 오류 데이터의 추적·관리를 위해 다음 항목 등을 기록

| 항목 | 내용 |
|---|---|
| **순번** | 오류 순서 |
| **오류ID** | 오류 식별 번호 |
| **정제ID** | 정제 작업 식별 번호 |
| **오류원인** | 오류 발생 원인 |
| **해결방안** | 오류 처리 방법 |
| **심각도** | 상 / 중 / 하 |
| **상태** | Open / Assigned / Fixed / Closed / Deferred / Classified |
| **발생일자** | 오류 발생 시점 |
| **예상 해결일자** | 예상 처리 완료 시점 |
| **담당자** | 오류 처리 담당자 |

> ⭐ 오류 관리는 단순 발견으로 끝나는 것이 아니라 **원인 → 해결방안 → 심각도 → 상태 → 일정 → 담당자**까지 추적
