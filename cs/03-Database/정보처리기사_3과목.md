## SECTION 060. 데이터베이스 설계

### 1. 데이터베이스 설계

- **데이터베이스 설계** - 사용자 요구를 분석해 데이터베이스 구조로 변환하고 특정 DBMS로 구현하는 과정.

#### 설계 고려사항

- 무결성(Integrity)
- 일관성(Consistency)
- 회복(Recovery)
- 보안(Security)
- 효율성(Efficiency)
- 데이터베이스 확장

- **무결성** - 삽입·삭제·갱신 후에도 데이터가 정해진 제약 조건을 만족하도록 유지.
- **일관성** - 저장 데이터와 질의 결과가 모순 없이 일정한 상태를 유지.
- **회복** - 장애 발생 시 장애 이전 상태로 복구할 수 있도록 고려.
- **보안** - 불법적인 데이터 노출·변경·손실로부터 데이터를 보호.
- **효율성** - 응답 시간·처리 성능·저장 공간의 효율을 고려.
- **데이터베이스 확장** - 운영에 큰 영향을 주지 않으면서 데이터를 계속 추가할 수 있도록 설계.

**암기:** `무·일·회·보·효·확`


#### 설계 순서 ★★★

**요구 조건 분석 → 개념적 설계 → 논리적 설계 → 물리적 설계 → 구현**

**암기:** `요 → 개 → 논 → 물 → 구`

##### 요구 조건 분석
- 사용자 요구 수집·분석
- 데이터 종류·용도·처리 형태·흐름·제약조건
- **요구 조건 명세서 작성**

##### 개념적 설계
- **DBMS 독립적**
- 개념 스키마
- 트랜잭션 모델링
- **E-R 모델**

##### 논리적 설계
- 사용할 데이터 모델 결정
- 목표 DBMS에 맞는 논리 스키마
- 트랜잭션 인터페이스
- 관계형 DB라면 **테이블 설계**

##### 물리적 설계
- 논리 구조 → 실제 저장 구조
- 레코드 형식·순서
- 접근 경로
- 트랜잭션 처리 시간
- 디스크 용량

##### 구현
- 특정 DBMS의 **DDL**
- DB 파일 생성
- 트랜잭션·응용 프로그램 작성

## SECTION 061. 데이터 모델의 개념

### 2. 데이터 모델

- **데이터 모델** - 현실 세계의 정보를 컴퓨터에 표현하기 위해 구조·연산·제약 조건으로 추상화한 모형.

#### 구성 요소

- 개체(Entity)
- 속성(Attribute)
- 관계(Relationship)

- **개체(Entity)** - 데이터베이스에 표현하려는 사람·사물·개념 등의 대상.
- **속성(Attribute)** - 개체의 특성을 나타내는 가장 작은 논리적 데이터 항목.
- **관계(Relationship)** - 둘 이상의 개체 또는 속성 사이의 논리적 연관성.

**암기:** `개·속·관`

#### 데이터 모델에 표시할 요소

- 구조(Structure)
- 연산(Operation)
- 제약 조건(Constraint)

**암기:** `구·연·제`

##### Structure
> 데이터 구조·관계

##### Operation
> 실제 데이터 처리 작업

##### Constraint
> 저장 가능한 데이터의 논리적 제한

### 3. 개념적·논리적 데이터 모델

##### 개념적 데이터 모델

> 현실 세계의 인식 → 추상적 개념

- 정보 모델
- 대표: **E-R 모델**

##### 논리적 데이터 모델

> 개념적 구조 → 컴퓨터가 처리 가능한 논리 구조

종류:
- 관계 데이터 모델
- 계층 데이터 모델
- 네트워크 데이터 모델

## SECTION 062. E-R(개체-관계) 모델

### 4. E-R 모델 ★★★

> **Peter Chen / 1976 / 개체·관계·속성 / DBMS 독립**

##### E-R 다이어그램 기호

| 기호 | 의미 |
|---|---|
| 사각형 | **개체(Entity)** |
| 마름모 | **관계(Relationship)** |
| 타원 | **속성(Attribute)** |

| 밑줄 속성 | 기본키 속성 |
| 여러 타원 연결 | 복합 속성 |

| 선 | Link |

- **Cardinality** - 개체 사이의 대응 수를 나타내며 `1:1`, `1:N`, `N:M` 형태로 표현.

**암기:** `사개 / 마관 / 타속`

> **E. F. Codd / 1970 / 모든 데이터를 Relation(Table)로 표현**

##### Relation

> 행과 열의 2차원 테이블

##### Relation Schema
> 릴레이션의 구조

##### Relation Instance
> 특정 시점의 실제 Tuple 집합

### 6. Tuple / Attribute / Domain ★★★

##### Tuple
- **행(Row)**
- Record
- Tuple 수 = **Cardinality**

##### Attribute
- **열(Column)**
- Field
- Attribute 수 = **Degree**

##### Domain
> 한 Attribute가 가질 수 있는 **원자값의 범위**

**암기:**  
`Tuple = 행 = Record = Cardinality`  
`Attribute = 열 = Field = Degree`

### 7. 릴레이션 특징

- 동일 Tuple 중복 X
- Tuple 순서 X
- Attribute 순서 X
- Attribute 이름은 유일
- Attribute 값은 중복 가능
- 값은 **Atomic Value**
- Tuple 식별을 위해 Key 사용

## SECTION 064. 관계형 데이터베이스의 제약 조건 - 키(Key)

### 8. 키(Key) ★★★

종류:

- 후보키(Candidate)
- 기본키(Primary)
- 대체키(Alternate)
- 슈퍼키(Super)
- 외래키(Foreign)


#### 후보키

> **유일성 + 최소성**

- 모든 Tuple을 유일하게 식별
- 하나 이상의 후보키 존재

##### 유일성
> 하나의 Key 값으로 하나의 Tuple 식별

##### 최소성
> 꼭 필요한 최소 Attribute로 구성


#### 기본키

> 후보키 중 대표

- 중복 X
- NULL X


#### 대체키

> **후보키 - 기본키**


#### 슈퍼키

> 유일성 O / 최소성은 X일 수 있음


#### 외래키

> **다른 Relation의 기본키 참조**

- 참조 관계 표현
- 참조 대상 PK에 없는 값 입력 X

## SECTION 066. 관계대수 및 관계해석

### 10. 관계대수

> 원하는 결과를 얻기 위해 **연산 순서를 명시하는 절차적 언어**

결과도 Relation.

##### 순수 관계 연산자

- Select
- Project
- Join
- Division

**암기:** `셀·프·조·디`

##### 일반 집합 연산자

- UNION
- INTERSECTION
- DIFFERENCE
- CARTESIAN PRODUCT

### 11. Select / Project / Join / Division ★★★

##### Select

> **행(Row) 선택 / σ(시그마)**

- 조건 만족 Tuple 추출
- 수평 연산

##### Project

> **열(Column) 선택 / π(파이)**

- Attribute 추출
- 중복 Tuple 제거
- 수직 연산

##### Join

> 공통 Attribute 중심으로 두 Relation 결합

- 기호: `⋈`

##### Natural Join

> 동등 Join 결과에서 **중복 공통 Attribute 제거**

##### Division

> S의 **모든 조건을 만족**하는 R의 값을 추출

**암기:**  
`Select = 행`  
`Project = 열`  
`Join = 결합`  
`Division = 모두 만족`

### 12. 집합 연산

##### UNION
> R 또는 S에 존재

##### INTERSECTION
> R과 S에 공통

##### DIFFERENCE
> R에는 있고 S에는 없음

##### CARTESIAN PRODUCT

> R의 모든 Tuple × S의 모든 Tuple

- Cardinality = `|R| × |S|`
- Degree = `Degree(R) + Degree(S)`

##### 합병 가능(Union Compatible)

합집합·교집합·차집합을 하려면:

> 대응 Attribute의 **Domain이 같아야 함**

### 13. 관계해석

> **비절차적**

- 원하는 정보가 **무엇인지**만 정의
- 처리 과정을 직접 명시 X
- Tuple 관계해석
- Domain 관계해석

논리 기호:
- `∀` → 모든 Tuple
- `∃` → 조건 만족 Tuple 존재

**암기:**  
`관계대수 = 절차적`  
`관계해석 = 비절차적`

## SECTION 067. 정규화(Normalization)

### 14. 정규화(Normalization) ★★★★★

> 중복을 줄이고 이상(Anomaly)을 방지하기 위해 Relation을 분해

- 논리적 설계 단계
- 일관성·정확성·단순성·비중복성·안정성 향상
- 너무 지나치면 Join 증가 가능

### 15. 이상(Anomaly)

##### 삽입 이상
> 불필요한 값까지 같이 삽입

##### 삭제 이상
> 원하지 않는 다른 정보까지 함께 삭제

##### 갱신 이상
> 일부만 갱신되어 데이터 불일치

**암기:** `삽·삭·갱`

### 16. 함수적 종속

`X → Y`

- X = 결정자(Determinant)
- Y = 종속자(Dependent)

##### 완전 함수적 종속
> 복합 결정자 **전체**에 의해서만 결정

##### 부분 함수적 종속
> 복합 결정자의 **일부**만으로 결정

##### 이행 함수적 종속

`X → Y`, `Y → Z` 이면 `X → Z`

##### 다치 종속
`A →→ B`

##### 조인 종속
> 분해 후 Join으로 원래 Relation 복원 가능

### 17. 정규형 순서 ★★★★★

**비정규 → 1NF → 2NF → 3NF → BCNF → 4NF → 5NF**

제거 대상:

**도메인 원자값 → 부분 함수 종속 → 이행 함수 종속 → 후보키 아닌 결정자 → 다치 종속 → 조인 종속**

**암기:** `도 → 부 → 이 → 결 → 다 → 조`

##### 1NF
> 모든 Attribute 값이 **원자값**

##### 2NF
> 1NF + **부분 함수 종속 제거**

##### 3NF
> 2NF + **이행 함수 종속 제거**

##### BCNF
> 모든 결정자가 **후보키**

##### 4NF
> **다치 종속 제거**

##### 5NF
> **조인 종속**이 후보키를 통해서만 성립

## SECTION 069. 시스템 카탈로그

저장 정보 = **Metadata**

- Table
- Index
- View
- 사용자 ID·권한
- PK·FK·NULL
- Function / Procedure / Trigger 정보 등

##### 특징

- 사용자가 SQL로 **조회 가능**
- INSERT / DELETE / UPDATE로 직접 변경 X
- DBMS가 자동 생성·유지·갱신

**암기:** `조회 O / 직접 갱신 X / DBMS 자동 관리`

### 21. 카탈로그 관련 DBMS 내부 모듈

##### DDL Compiler
> DDL → Metadata를 갖는 테이블로 변환

##### DML Compiler
> 응용 프로그램의 DML을 처리 가능한 형태로 변환

##### Data Directory
> 실제 데이터 접근에 필요한 정보 관리  
> **시스템만 접근 가능**

##### Query Optimizer
> **최적 질의 처리 전략 선택**

##### Transaction Processor
> 여러 Transaction의 동시 처리 관리

## SECTION 070. 트랜잭션 분석 / CRUD 분석

### 22. 트랜잭션(Transaction) ★★★★★

> DB 상태를 변화시키는 **논리적 작업 단위**

##### 상태

정상:

**Active → Partially Committed → Committed**

오류:

**Failed → Aborted**

- **Active** - 트랜잭션이 실행 중인 상태.
- **Partially Committed** - 모든 연산을 끝내고 Commit 직전인 상태.
- **Committed** - 모든 연산과 Commit이 정상적으로 완료된 상태.
- **Failed** - 실행 중 오류가 발생해 더 이상 진행할 수 없는 상태.
- **Aborted** - Rollback을 수행해 트랜잭션을 철회한 상태.

### 23. ACID ★★★★★

##### Atomicity 원자성
> 모두 반영하거나 모두 취소

- Commit or Rollback

##### Consistency 일관성
> 완료 후 DB는 일관된 상태

##### Isolation 독립성·격리성
> 동시에 실행돼도 서로 연산에 끼어들지 않음

##### Durability 영속성
> Commit된 결과는 영구 반영

**암기:** `원·일·독·영`

### 24. CRUD

- C = Create
- R = Read
- U = Update
- D = Delete

##### CRUD Matrix

> **행 = Process / 열 = Table**

각 셀에 C/R/U/D 표시.

대표 작업 우선순위:

`C → D → U → R`

## SECTION 071. 인덱스 설계

### 25. 인덱스(Index)

> 빠른 접근을 위한 `<Key, Pointer>` 구조

##### 장점
- 검색 속도 ↑

##### 단점
- 별도 저장 공간 필요
- 삽입·삭제·갱신 시 관리 비용
- 너무 많이 만들면 오버헤드

**암기:** `검색↑ / 저장공간·갱신비용↑`

### 26. Clustered / Non-Clustered Index ★★★

##### Clustered

> **데이터 자체가 Index Key 순서로 물리적 정렬**

- 검색 범위 넓을 때 효율
- 삽입·삭제 시 데이터 재배치
- 제한적으로 사용

##### Non-Clustered

> 실제 데이터 순서 변경 X  
> **별도 Index가 데이터 위치를 가리킴**

- 여러 개 생성 가능

**암기:**  
`Clustered = 데이터 자체 정렬`  
`Non-Clustered = 별도 Index + Pointer`

### 27. B Tree / B+ Tree

##### B Tree
- Root → 하위 노드 탐색
- 모든 Leaf 깊이 동일
- Branch Block + Leaf Block

##### B+ Tree

> **Index Set + Sequence Set**

- Index Set → 경로 제공
- Sequence Set → 실제 데이터 주소
- Leaf만 이용한 순차 처리 가능

**암기:** `B+ = 인덱스 세트(경로) + 순차 세트(주소)`

### 28. 기타 인덱스

##### Bitmap Index
- 0 / 1
- 저장 공간 작음
- 여러 조건 조합 Query에 유리
- 삽입·삭제 빈번하면 성능↓

##### Function-Based Index
> Column 값 대신 **함수·수식 결과** 저장

##### Bitmap Join Index
> 여러 Join된 객체로 구성

##### Domain Index
> 개발자가 직접 정의하는 **확장형 인덱스**

### 29. 인덱스 대상 Column

적합:
- 검색 자주
- 분포도 적절
- 수정 적음
- ORDER BY / GROUP BY / UNION 자주
- PK / UNIQUE
- 특정 범위 조회 자주

**암기:** `검색 자주 / 수정 적게 / 정렬·그룹 자주`

## SECTION 074. 분산 데이터베이스 설계

### 34. 분산 데이터베이스

> **논리적으로 하나 / 물리적으로 여러 Site**

구성:
- 분산 처리기
- 분산 DB
- 통신 Network

- **분산 처리기** - 지리적으로 분산된 시스템에서 실제 처리를 수행하는 장치.
- **분산 DB** - 여러 위치에 분산되어 있지만 하나의 논리 구조를 갖는 데이터 집합.
- **통신 Network** - 분산 처리기들을 연결해 하나의 시스템처럼 동작하도록 하는 통신망.

### 35. 분산 DB 투명성 ★★★

- 위치 투명성
- 중복 투명성
- 병행 투명성
- 장애 투명성

**암기:** `위·중·병·장`

##### 위치
> 실제 위치 몰라도 논리 이름으로 접근

##### 중복
> 여러 Site에 복제돼도 하나처럼 사용

##### 병행
> 여러 Transaction 동시 수행해도 일관성 유지

##### 장애
> 장애 발생해도 Transaction 정확히 처리

### 36. 분산 DB 설계

방법:
- Table 위치 분산
- Fragmentation
- Allocation

##### Fragment 규칙

- 완전성(Completeness)
- 재구성(Reconstruction)
- 상호 중첩 배제성(Disjointness)

- **완전성** - 전체 데이터를 빠짐없이 분할해야 함.
- **재구성** - 분할된 데이터를 다시 결합해 원래 데이터로 복원할 수 있어야 함.
- **상호 중첩 배제성** - 한 분할의 데이터가 다른 분할에 중복되지 않아야 함.

##### 수평 Fragment
> Row

##### 수직 Fragment
> Column

##### Allocation
> 분할 데이터를 **어느 Site에 둘지 결정**

## SECTION 076. 데이터베이스 보안 - 접근통제

### 39. 접근통제 ★★★★★

- **접근통제** - 데이터 객체와 사용 주체 사이의 정보 흐름을 제한해 비인가 접근을 막는 것.

- 군사·정부
- 사용자가 임의 변경 어려움

##### RBAC

> **Role에 따라 권한 부여**

`사용자 → 역할 → 권한`

**암기:**  
`DAC = 신원·소유자`  
`MAC = 등급·강제`  
`RBAC = 역할`

### 40. 접근통제 보안 모델 ★★★★★

#### Bell-LaPadula

> **기밀성(Confidentiality)**

- **No Read Up**
- **No Write Down**

**암기:** `벨라 = 기밀 / 위로 읽기 X / 아래로 쓰기 X`

#### Biba

> **무결성(Integrity)**

- **No Read Down**
- **No Write Up**

**암기:** `비바 = 무결 / 아래 읽기 X / 위 쓰기 X`

#### Clark-Wilson

> 상업용 **무결성 중심**  
> 사용자가 객체에 직접 접근 X / 프로그램을 통해 접근

#### Chinese Wall

> 이해 충돌 관계의 객체 간 정보 접근 통제

### 41. Access Control List / Capability List

##### ACL

> **객체 기준**

- 어떤 주체가 어떤 행위를 할 수 있는지

##### Capability List

> **주체 기준**

- 자신이 접근 가능한 객체와 권한

### 42. Access Control Matrix

> **행 = Subject / 열 = Object / 셀 = Right**

## SECTION 077. 데이터베이스 백업

### 44. 로그 파일

> DB 복구의 핵심 자료

- Transaction 시작·완료
- Insert / Update / Delete
- Before Image
- After Image

##### UNDO

> **이전 상태로 복구**

##### REDO

> 완료된 변경 내용을 **다시 적용**

### 45. 복구 알고리즘

##### NO-UNDO / REDO
- 완료 전 변경은 DB 기록 X → UNDO 불필요
- Commit 후 미기록분 → REDO

##### UNDO / NO-REDO
- 완료 전 장애 → UNDO
- 완료된 변경은 이미 DB 기록 → REDO 불필요

##### UNDO / REDO
- 미완료 → UNDO
- 완료했지만 미기록 → REDO

##### NO-UNDO / NO-REDO
- 별도 영역 사용
- 둘 다 불필요

### 46. 물리 백업 vs 논리 백업

##### 물리 백업

> **DB 파일 자체**

- 빠름
- 단순
- 원인 파악 어려울 수 있음

##### 논리 백업

> **DB의 논리 객체**

- DBMS Utility 이용
- 원인 파악·해결 수월
- Backup/Restore 시간 많이 소요

- 자동 처리

##### Procedure vs Trigger

- Procedure → **직접 호출**
- Trigger → **자동 실행**

### 71. Trigger 핵심 문법

##### BEFORE
> Table 변경 **전**

##### AFTER
> 변경 **후**

##### NEW
> 새로 들어올 값

##### OLD
> 변경·삭제되기 전 값

##### FOR EACH ROW
> 각 Tuple마다 실행

##### WHEN
> Trigger 적용 조건

**시험:** `BEFORE/AFTER + INSERT/UPDATE/DELETE + NEW/OLD`

## SECTION 088. 사용자 정의 함수

### 72. 사용자 정의 함수(UDF)

> Procedure와 유사하지만 **RETURN으로 하나의 값 반환**

- 출력 Parameter 없음
- DML 안에서 반환값 사용
- 교재 기준 SELECT 조회 작업

##### Procedure vs Function

| 구분 | Procedure | Function |
|---|---|---|
| 반환값 | 없거나 여러 개 가능 | **1개** |
| Parameter | IN / OUT | **입력만** |
| 사용 | 실행문 | **DML 안** |
| 핵심 | 직접 실행 | **RETURN** |

## SECTION 089. DBMS 접속 기술

### 73. DBMS 접속 구조

> **사용자 → Web Server → WAS → DBMS**

### 74. JDBC / ODBC / MyBatis ★★★

##### JDBC

> **Java + DB 표준 API**

- java.sql
- javax.sql
- DBMS Driver 필요

##### ODBC

> **언어 독립적 + 표준 개방형 API**

- Microsoft
- Driver 필요

##### MyBatis

> **JDBC 간소화 + SQL Mapping + XML**

- Open Source Framework
- SQL을 XML 등에 분리

**암기:**  
`JDBC = Java`  
`ODBC = 언어 독립`  
`MyBatis = SQL Mapping`

### 75. Static SQL vs Dynamic SQL

##### Static SQL

- 실행 전 SQL 확정
- 빠름
- 사전 검사 O
- 구조 고정

##### Dynamic SQL

- SQL을 문자열 변수에 저장
- 실행 중 조건에 따라 변경
- 유연
- 느릴 수 있음
- 사전 검사 X

**암기:**  
`정적 = 빠름·검사 O`  
`동적 = 유연·느림·검사 X`

## SECTION 091. 데이터 전환 방안

### 79. 데이터 전환 방안

순서:

**전환 규칙 → 전환 절차 → 전환 방법 → 전환 설계 → 프로그램 개발·테스트 계획 → 전환 계획 → 검증 방안**

### 80. 데이터 전환 절차 ★★★

**전환 준비 → 전환 설계/개발 → 전환 테스트 → 전 데이터 전환 → 최종 전환 및 검증**

**암기:** `준 → 설개 → 테 → 전 → 최검`

### 81. 데이터 전환 방법·설계

##### 전환 방법
> 업무별 전환 방법 + 전제 조건

##### 전환 설계
> 전환 대상·제외 내용 + **원천/목적 Table Mapping**

### 82. 데이터 전환 프로그램

관리 항목:
- 입력 정보
- 중간 생성 정보
- 출력 정보
- 프로그램 위치
- 담당자

테스트:
> **전환 시나리오 기반**

### 83. 사전 / 본 / 후 전환

##### 사전 전환
> 대량 데이터를 미리 전환

##### 본 전환
> 실제 최종 전환  
> 시간대별 상세 절차 작성

##### 후 전환
> 본 전환 후 발생한 신규 데이터 등을 추가 전환

**암기:** `전환 시간 단축 = 사전 → 본 → 후`

## SECTION 092. 데이터 검증

### 84. 데이터 검증

> 데이터 전환이 **정상적으로 수행되었는지 확인**

### 85. 데이터 검증 방법 키워드 ★★★

##### 로그 검증
> 추출·전환·적재 **로그**

##### 기본 항목 검증
> 별도로 요청된 기본 검증 항목

##### 응용 프로그램 검증
> 프로그램을 통해 정합성 확인

##### 응용 데이터 검증
> **업무 규칙** 기준

##### 값 검증
> 합계·범위·코드·Attribute 변경 값

### 86. 검증 단계별 방법 ★★★

##### 추출
> 로그 검증

##### 전환
> 로그 검증

##### DB 적재
> 로그 검증

##### DB 적재 후
> **기본 항목 검증**

##### 전환 완료 후
> **응용 프로그램 + 응용 데이터 검증**

**암기:**  
`추·전·적 = 로그`  
`적재 후 = 기본`  
`완료 후 = 응용`

### 89. 원천 데이터 품질 점검

### 91. 오류 상태 ★★★

**Open → Assigned → Fixed → Closed**

- Deferred → 수정 연기

### 92. 오류 심각도

##### 상

> 데이터 전환 전반에 영향

##### 하
> 직접 영향은 없지만 상황에 맞지 않는 오류

**암기:** `상=전환 불가 / 중=전체 영향 / 하=직접 영향 X`
