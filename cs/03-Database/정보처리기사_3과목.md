# 정보처리기사 3과목

# SECTION 060. 데이터베이스 설계

## 1. 데이터베이스 설계

- **데이터베이스 설계** - 사용자 요구를 분석해 데이터베이스 구조로 변환하고 특정 DBMS로 구현하는 과정.

### 설계 고려사항

- 무결성(Integrity(무결성))
- 일관성(Consistency(일관성))
- 회복(Recovery(회복))
- 보안(Security(보안))
- 효율성(Efficiency(효율성))
- 데이터베이스 확장

- **무결성** - 삽입·삭제·갱신 후에도 데이터가 정해진 제약 조건을 만족하도록 유지.
- **일관성** - 저장 데이터와 질의 결과가 모순 없이 일정한 상태를 유지.
- **회복** - 장애 발생 시 장애 이전 상태로 복구할 수 있도록 고려.
- **보안** - 불법적인 데이터 노출·변경·손실로부터 데이터를 보호.
- **효율성** - 응답 시간·처리 성능·저장 공간의 효율을 고려.
- **데이터베이스 확장** - 운영에 큰 영향을 주지 않으면서 데이터를 계속 추가할 수 있도록 설계.

**암기:** `무·일·회·보·효·확`


### 설계 순서 ★★★

**요구 조건 분석 → 개념적 설계 → 논리적 설계 → 물리적 설계 → 구현**

**암기:** `요 → 개 → 논 → 물 → 구`

#### 요구 조건 분석
- 사용자 요구 수집·분석
- 데이터 종류·용도·처리 형태·흐름·제약조건
- **요구 조건 명세서 작성**

#### 개념적 설계
- **DBMS 독립적**
- 개념 스키마
- 트랜잭션 모델링
- **E-R 모델**

#### 논리적 설계
- 사용할 데이터 모델 결정
- 목표 DBMS에 맞는 논리 스키마
- 트랜잭션 인터페이스
- 관계형 DB라면 **테이블 설계**

#### 물리적 설계
- 논리 구조 → 실제 저장 구조
- 레코드 형식·순서
- 접근 경로
- 트랜잭션 처리 시간
- 디스크 용량

#### 구현
- 특정 DBMS의 **DDL**
- DB 파일 생성
- 트랜잭션·응용 프로그램 작성

# SECTION 061. 데이터 모델의 개념

## 2. 데이터 모델

- **데이터 모델** - 현실 세계의 정보를 컴퓨터에 표현하기 위해 구조·연산·제약 조건으로 추상화한 모형.

### 구성 요소

- 개체(Entity(개체))
- 속성(Attribute(속성))
- 관계(Relationship(관계))

- **개체(Entity(개체))** - 데이터베이스에 표현하려는 사람·사물·개념 등의 대상.
- **속성(Attribute(속성))** - 개체의 특성을 나타내는 가장 작은 논리적 데이터 항목.
- **관계(Relationship(관계))** - 둘 이상의 개체 또는 속성 사이의 논리적 연관성.

**암기:** `개·속·관`

### 데이터 모델에 표시할 요소

- 구조(Structure(구조))
- 연산(Operation(연산))
- 제약 조건(Constraint(제약 조건))

**암기:** `구·연·제`

#### Structure(구조)
> 데이터 구조·관계

#### Operation(연산)
> 실제 데이터 처리 작업

#### Constraint(제약 조건)
> 저장 가능한 데이터의 논리적 제한

## 3. 개념적·논리적 데이터 모델

#### 개념적 데이터 모델

> 현실 세계의 인식 → 추상적 개념

- 정보 모델
- 대표: **E-R 모델**

#### 논리적 데이터 모델

> 개념적 구조 → 컴퓨터가 처리 가능한 논리 구조

종류:
- 관계 데이터 모델
- 계층 데이터 모델
- 네트워크 데이터 모델

# SECTION 062. E-R(개체-관계) 모델

## 4. E-R 모델 ★★★

> **Peter Chen / 1976 / 개체·관계·속성 / DBMS 독립**

#### E-R 다이어그램 기호

| 기호 | 의미 |
|---|---|
| 사각형 | **개체(Entity(개체))** |
| 마름모 | **관계(Relationship(관계))** |
| 타원 | **속성(Attribute(속성))** |
| 이중 타원 | 다중값 속성 |
| 밑줄 속성 | 기본키 속성 |
| 여러 타원 연결 | 복합 속성 |
| 1 / N / M | Cardinality(카디널리티/튜플 수) |
| 선 | Link(연결선) |

- **Cardinality(카디널리티/튜플 수)** - 개체 사이의 대응 수를 나타내며 `1:1`, `1:N`, `N:M` 형태로 표현.

**암기:** `사개 / 마관 / 타속`

# SECTION 063. 관계형 데이터베이스의 구조

## 5. 관계형 데이터베이스

> **E. F. Codd / 1970 / 모든 데이터를 Relation(Table(테이블))로 표현**

#### Relation(릴레이션)

> 행과 열의 2차원 테이블

#### Relation(릴레이션) Schema(릴레이션 스키마)
> 릴레이션의 구조

#### Relation(릴레이션) Instance(릴레이션 인스턴스)
> 특정 시점의 실제 Tuple(튜플) 집합

## 6. Tuple(튜플) / Attribute(속성) / Domain(도메인) ★★★

#### Tuple(튜플)
- **행(Row(행))**
- Record(레코드)
- Tuple(튜플) 수 = **Cardinality(카디널리티/튜플 수)**

#### Attribute(속성)
- **열(Column(열))**
- Field(필드)
- Attribute(속성) 수 = **Degree(차수)**

#### Domain(도메인)
> 한 Attribute가 가질 수 있는 **원자값의 범위**

**암기:**  
`Tuple(튜플) = 행 = Record(레코드) = Cardinality(카디널리티/튜플 수)`  
`Attribute(속성) = 열 = Field(필드) = Degree(차수)`

## 7. 릴레이션 특징

- 동일 Tuple(튜플) 중복 X
- Tuple(튜플) 순서 X
- Attribute(속성) 순서 X
- Attribute(속성) 이름은 유일
- Attribute(속성) 값은 중복 가능
- 값은 **Atomic Value(원자값)**
- Tuple(튜플) 식별을 위해 Key(키) 사용

# SECTION 064. 관계형 데이터베이스의 제약 조건 - 키(Key(키))

## 8. 키(Key(키)) ★★★

종류:

- 후보키(Candidate(후보키))
- 기본키(Primary(기본키))
- 대체키(Alternate(대체키))
- 슈퍼키(Super(슈퍼키))
- 외래키(Foreign(외래키))


### 후보키

> **유일성 + 최소성**

- 모든 Tuple을 유일하게 식별
- 하나 이상의 후보키 존재

#### 유일성
> 하나의 Key(키) 값으로 하나의 Tuple(튜플) 식별

#### 최소성
> 꼭 필요한 최소 Attribute로 구성


### 기본키

> 후보키 중 대표

- 중복 X
- NULL(널/값 없음) X


### 대체키

> **후보키 - 기본키**


### 슈퍼키

> 유일성 O / 최소성은 X일 수 있음


### 외래키

> **다른 Relation의 기본키 참조**

- 참조 관계 표현
- 참조 대상 PK에 없는 값 입력 X

# SECTION 066. 관계대수 및 관계해석

## 10. 관계대수

> 원하는 결과를 얻기 위해 **연산 순서를 명시하는 절차적 언어**

결과도 Relation(릴레이션).

#### 순수 관계 연산자

- Select(셀렉트/선택)
- Project(프로젝트/투영)
- Join(조인/결합)
- Division(디비전/나눗셈)

**암기:** `셀·프·조·디`

#### 일반 집합 연산자

- UNION(합집합)
- INTERSECTION(교집합)
- DIFFERENCE(차집합)
- CARTESIAN PRODUCT(카티션 프로덕트/곱집합)

## 11. Select(셀렉트/선택) / Project(프로젝트/투영) / Join(조인/결합) / Division(디비전/나눗셈) ★★★

#### Select(셀렉트/선택)

> **행(Row(행)) 선택 / σ(시그마)**

- 조건 만족 Tuple(튜플) 추출
- 수평 연산

#### Project(프로젝트/투영)

> **열(Column(열)) 선택 / π(파이)**

- Attribute(속성) 추출
- 중복 Tuple(튜플) 제거
- 수직 연산

#### Join(조인/결합)

> 공통 Attribute(속성) 중심으로 두 Relation(릴레이션) 결합

- 기호: `⋈`

#### Natural Join(자연 조인)

> 동등 Join(조인/결합) 결과에서 **중복 공통 Attribute(속성) 제거**

#### Division(디비전/나눗셈)

> S의 **모든 조건을 만족**하는 R의 값을 추출

**암기:**  
`Select(셀렉트/선택) = 행`  
`Project(프로젝트/투영) = 열`  
`Join(조인/결합) = 결합`  
`Division(디비전/나눗셈) = 모두 만족`

## 12. 집합 연산

#### UNION(합집합)
> R 또는 S에 존재

#### INTERSECTION(교집합)
> R과 S에 공통

#### DIFFERENCE(차집합)
> R에는 있고 S에는 없음

#### CARTESIAN PRODUCT(카티션 프로덕트/곱집합)

> R의 모든 Tuple(튜플) × S의 모든 Tuple(튜플)

- Cardinality(카디널리티/튜플 수) = `|R| × |S|`
- Degree(차수) = `Degree(R) + Degree(S)`

#### 합병 가능(Union Compatible(합병 가능))

합집합·교집합·차집합을 하려면:

> 대응 Attribute의 **Domain이 같아야 함**

## 13. 관계해석

> **비절차적**

- 원하는 정보가 **무엇인지**만 정의
- 처리 과정을 직접 명시 X
- Tuple(튜플) 관계해석
- Domain(도메인) 관계해석

논리 기호:
- `∀` → 모든 Tuple(튜플)
- `∃` → 조건 만족 Tuple(튜플) 존재

**암기:**  
`관계대수 = 절차적`  
`관계해석 = 비절차적`

# SECTION 067. 정규화(Normalization)

## 14. 정규화(Normalization) ★★★★★

> 중복을 줄이고 이상(Anomaly)을 방지하기 위해 Relation을 분해

- 논리적 설계 단계
- 일관성·정확성·단순성·비중복성·안정성 향상
- 너무 지나치면 Join(조인/결합) 증가 가능

## 15. 이상(Anomaly)

#### 삽입 이상
> 불필요한 값까지 같이 삽입

#### 삭제 이상
> 원하지 않는 다른 정보까지 함께 삭제

#### 갱신 이상
> 일부만 갱신되어 데이터 불일치

**암기:** `삽·삭·갱`

## 16. 함수적 종속

`X → Y`

- X = 결정자(Determinant(결정자))
- Y = 종속자(Dependent(종속자))

#### 완전 함수적 종속
> 복합 결정자 **전체**에 의해서만 결정

#### 부분 함수적 종속
> 복합 결정자의 **일부**만으로 결정

#### 이행 함수적 종속

`X → Y`, `Y → Z` 이면 `X → Z`

#### 다치 종속
`A →→ B`

#### 조인 종속
> 분해 후 Join으로 원래 Relation(릴레이션) 복원 가능

## 17. 정규형 순서 ★★★★★

**비정규 → 1NF → 2NF → 3NF → BCNF → 4NF → 5NF**

제거 대상:

**도메인 원자값 → 부분 함수 종속 → 이행 함수 종속 → 후보키 아닌 결정자 → 다치 종속 → 조인 종속**

**암기:** `도 → 부 → 이 → 결 → 다 → 조`

#### 1NF
> 모든 Attribute(속성) 값이 **원자값**

#### 2NF
> 1NF + **부분 함수 종속 제거**

#### 3NF
> 2NF + **이행 함수 종속 제거**

#### BCNF
> 모든 결정자가 **후보키**

#### 4NF
> **다치 종속 제거**

#### 5NF
> **조인 종속**이 후보키를 통해서만 성립

# SECTION 068. 반정규화(Denormalization)

## 18. 반정규화(Denormalization)

> **성능 향상을 위해 의도적으로 정규화 원칙을 위배**

방법:
- 테이블 통합
- 테이블 분할
- 중복 테이블 추가
- 중복 Attribute(속성) 추가

주의:
- 성능↑ 가능
- 일관성·정합성↓ 가능
- 지나치면 오히려 성능↓ 가능

## 19. 테이블 분할

#### 수평 분할

> **Row(행) 기준**

#### 수직 분할

> **Column(열) 기준**

**암기:** `수평 = 행 / 수직 = 열`

# SECTION 069. 시스템 카탈로그

## 20. 시스템 카탈로그

> DBMS의 **데이터 객체 정의·명세 정보**를 저장하는 시스템 DB

저장 정보 = **Metadata(메타데이터)**

- Table(테이블)
- Index(인덱스)
- View(뷰)
- 사용자 ID·권한
- PK·FK·NULL(널/값 없음)
- Function(함수) / Procedure(프로시저) / Trigger(트리거) 정보 등

#### 특징

- 사용자가 SQL로 **조회 가능**
- INSERT(삽입) / DELETE(삭제) / UPDATE로 직접 변경 X
- DBMS가 자동 생성·유지·갱신

**암기:** `조회 O / 직접 갱신 X / DBMS 자동 관리`

## 21. 카탈로그 관련 DBMS 내부 모듈

#### DDL Compiler(DDL 컴파일러)
> DDL → Metadata를 갖는 테이블로 변환

#### DML Compiler(DML 컴파일러)
> 응용 프로그램의 DML을 처리 가능한 형태로 변환

#### Data Directory(데이터 디렉터리)
> 실제 데이터 접근에 필요한 정보 관리  
> **시스템만 접근 가능**

#### Query Optimizer(질의 최적화기)
> **최적 질의 처리 전략 선택**

#### Transaction(트랜잭션) Processor(트랜잭션 처리기)
> 여러 Transaction의 동시 처리 관리

# SECTION 070. 트랜잭션 분석 / CRUD 분석

## 22. 트랜잭션(Transaction(트랜잭션)) ★★★★★

> DB 상태를 변화시키는 **논리적 작업 단위**

#### 상태

정상:

**Active(활동) → Partially Committed(부분 완료) → Committed(완료)**

오류:

**Failed(실패) → Aborted(철회)**

- **Active(활동)** - 트랜잭션이 실행 중인 상태.
- **Partially Committed(부분 완료)** - 모든 연산을 끝내고 Commit 직전인 상태.
- **Committed(완료)** - 모든 연산과 Commit이 정상적으로 완료된 상태.
- **Failed(실패)** - 실행 중 오류가 발생해 더 이상 진행할 수 없는 상태.
- **Aborted(철회)** - Rollback을 수행해 트랜잭션을 철회한 상태.

## 23. ACID ★★★★★

#### Atomicity(원자성) 원자성
> 모두 반영하거나 모두 취소

- Commit or Rollback

#### Consistency(일관성) 일관성
> 완료 후 DB는 일관된 상태

#### Isolation(독립성/격리성) 독립성·격리성
> 동시에 실행돼도 서로 연산에 끼어들지 않음

#### Durability(영속성) 영속성
> Commit된 결과는 영구 반영

**암기:** `원·일·독·영`

## 24. CRUD

- C = Create(생성)
- R = Read(읽기)
- U = Update(갱신)
- D = Delete(삭제)

#### CRUD Matrix(CRUD 매트릭스)

> **행 = Process(프로세스) / 열 = Table(테이블)**

각 셀에 C/R/U/D 표시.

대표 작업 우선순위:

`C → D → U → R`

# SECTION 071. 인덱스 설계

## 25. 인덱스(Index(인덱스))

> 빠른 접근을 위한 `<Key(키), Pointer(포인터)>` 구조

#### 장점
- 검색 속도 ↑

#### 단점
- 별도 저장 공간 필요
- 삽입·삭제·갱신 시 관리 비용
- 너무 많이 만들면 오버헤드

**암기:** `검색↑ / 저장공간·갱신비용↑`

## 26. Clustered(클러스터드) / Non-Clustered(비클러스터드) Index(인덱스) ★★★

#### Clustered(클러스터드)

> **데이터 자체가 Index(인덱스) Key(키) 순서로 물리적 정렬**

- 검색 범위 넓을 때 효율
- 삽입·삭제 시 데이터 재배치
- 제한적으로 사용

#### Non-Clustered(비클러스터드)

> 실제 데이터 순서 변경 X  
> **별도 Index가 데이터 위치를 가리킴**

- 여러 개 생성 가능

**암기:**  
`Clustered(클러스터드) = 데이터 자체 정렬`  
`Non-Clustered(비클러스터드) = 별도 Index(인덱스) + Pointer(포인터)`

## 27. B Tree(B 트리) / B+ Tree(B+ 트리)

#### B Tree(B 트리)
- Root(루트) → 하위 노드 탐색
- 모든 Leaf 깊이 동일
- Branch Block(브랜치 블록) + Leaf Block(리프 블록)

#### B+ Tree(B+ 트리)

> **Index(인덱스) Set(인덱스 세트) + Sequence Set(순차 세트)**

- Index(인덱스) Set(인덱스 세트) → 경로 제공
- Sequence Set(순차 세트) → 실제 데이터 주소
- Leaf만 이용한 순차 처리 가능

**암기:** `B+ = 인덱스 세트(경로) + 순차 세트(주소)`

## 28. 기타 인덱스

#### Bitmap Index(비트맵 인덱스)
- 0 / 1
- 저장 공간 작음
- 여러 조건 조합 Query에 유리
- 삽입·삭제 빈번하면 성능↓

#### Function-Based Index(함수 기반 인덱스)
> Column(열) 값 대신 **함수·수식 결과** 저장

#### Bitmap Join(조인/결합) Index(비트맵 조인 인덱스)
> 여러 Join된 객체로 구성

#### Domain(도메인) Index(도메인 인덱스)
> 개발자가 직접 정의하는 **확장형 인덱스**

## 29. 인덱스 대상 Column(열)

적합:
- 검색 자주
- 분포도 적절
- 수정 적음
- ORDER BY(정렬) / GROUP BY(그룹화) / UNION(합집합) 자주
- PK / UNIQUE(유일성)
- 특정 범위 조회 자주

**암기:** `검색 자주 / 수정 적게 / 정렬·그룹 자주`

# SECTION 073. 파티션 설계

## 31. Partition(파티션)

> 논리적으로 하나의 Table을 **물리적으로 여러 구역**으로 분할

#### 장점
- 접근 범위 감소 → 성능↑
- 디스크 I/O 분산
- Backup/Recovery(회복) 빠름
- 장애 영향 감소
- 가용성↑

## 32. Partition(파티션) 종류 ★★★

#### Range(범위)

> **값의 범위**

- 날짜·숫자 등 연속값

#### Hash(해시)

> **Hash(해시) 함수 결과**

- 균등 분산

#### Composite(복합)

> **2개 이상 방식 결합**

#### List(목록)

> 미리 정한 **값 목록**

- 국가·지역·부서

#### Round Robin(라운드 로빈)

> 레코드를 **순차적으로 균등 분배**

**암기:**  
`Range(범위)=범위 / Hash(해시)=균등 / Composite(복합)=혼합 / List(목록)=목록 / Round Robin(라운드 로빈)=순차 균등`

## 33. Index(인덱스) Partition(파티션)

#### Local(로컬)

#### Global(글로벌)

> Table(테이블) Partition과 **독립**

#### Prefixed(프리픽스형)

> Index의 **첫 Column이 Partition(파티션) Key(키)**

#### Non-Prefixed(비프리픽스형)

> 첫 Column이 Partition(파티션) Key와 다름

# SECTION 074. 분산 데이터베이스 설계

## 34. 분산 데이터베이스

> **논리적으로 하나 / 물리적으로 여러 Site(사이트)**

구성:
- 분산 처리기
- 분산 DB
- 통신 Network(네트워크)

- **분산 처리기** - 지리적으로 분산된 시스템에서 실제 처리를 수행하는 장치.
- **분산 DB** - 여러 위치에 분산되어 있지만 하나의 논리 구조를 갖는 데이터 집합.
- **통신 Network(네트워크)** - 분산 처리기들을 연결해 하나의 시스템처럼 동작하도록 하는 통신망.

## 35. 분산 DB 투명성 ★★★

- 위치 투명성
- 중복 투명성
- 병행 투명성
- 장애 투명성

**암기:** `위·중·병·장`

#### 위치
> 실제 위치 몰라도 논리 이름으로 접근

#### 중복
> 여러 Site에 복제돼도 하나처럼 사용

#### 병행
> 여러 Transaction(트랜잭션) 동시 수행해도 일관성 유지

#### 장애
> 장애 발생해도 Transaction(트랜잭션) 정확히 처리

## 36. 분산 DB 설계

방법:
- Table(테이블) 위치 분산
- Fragmentation(단편화)
- Allocation(할당)

#### Fragment 규칙

- 완전성(Completeness(완전성))
- 재구성(Reconstruction(재구성))
- 상호 중첩 배제성(Disjointness(상호 중첩 배제성))

- **완전성** - 전체 데이터를 빠짐없이 분할해야 함.
- **재구성** - 분할된 데이터를 다시 결합해 원래 데이터로 복원할 수 있어야 함.
- **상호 중첩 배제성** - 한 분할의 데이터가 다른 분할에 중복되지 않아야 함.

#### 수평 Fragment
> Row(행)

#### 수직 Fragment
> Column(열)

#### Allocation(할당)
> 분할 데이터를 **어느 Site에 둘지 결정**

## 39. 접근통제 ★★★★★

- **접근통제** - 데이터 객체와 사용 주체 사이의 정보 흐름을 제한해 비인가 접근을 막는 것.

> 상업용 **무결성 중심**  
> 사용자가 객체에 직접 접근 X / 프로그램을 통해 접근

### Chinese Wall

> 이해 충돌 관계의 객체 간 정보 접근 통제

# SECTION 077. 데이터베이스 백업

## 44. 로그 파일

> DB 복구의 핵심 자료

- Transaction(트랜잭션) 시작·완료
- Insert / Update(갱신) / Delete(삭제)
- Before Image(변경 전 이미지)
- After Image(변경 후 이미지)

#### UNDO(되돌리기)

> **이전 상태로 복구**

#### REDO(재실행)

> 완료된 변경 내용을 **다시 적용**

## 45. 복구 알고리즘

#### NO-UNDO / REDO(재실행)
- 완료 전 변경은 DB 기록 X → UNDO(되돌리기) 불필요
- Commit 후 미기록분 → REDO(재실행)

#### UNDO(되돌리기) / NO-REDO
- 완료 전 장애 → UNDO(되돌리기)
- 완료된 변경은 이미 DB 기록 → REDO(재실행) 불필요

#### UNDO(되돌리기) / REDO(재실행)
- 미완료 → UNDO(되돌리기)
- 완료했지만 미기록 → REDO(재실행)

#### NO-UNDO / NO-REDO
- 별도 영역 사용
- 둘 다 불필요

## 46. 물리 백업 vs 논리 백업

#### 물리 백업

> **DB 파일 자체**

- 빠름
- 단순
- 원인 파악 어려울 수 있음

#### 논리 백업

> **DB의 논리 객체**

- DBMS Utility(유틸리티) 이용
- 원인 파악·해결 수월
- Backup/Restore 시간 많이 소요

#### 하
> 직접 영향은 없지만 상황에 맞지 않는 오류

**암기:** `상=전환 불가 / 중=전체 영향 / 하=직접 영향 X`

## 93. 오류 관리 목록

- **오류 관리 목록** - 발견된 오류의 원인·해결 방안·상태·일정·담당자를 지속적으로 추적하기 위한 목록.

관리:
- 오류 ID
- 정제 ID
- 오류 원인
- 해결 방안
- 심각도
- 상태
- 발생일
- 예상 해결일
- 담당자

> 오류 발견에서 끝 X → **원인·해결·상태·일정·담당자까지 추적**
