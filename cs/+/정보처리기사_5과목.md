> 소프트웨어 개발·유지보수에 필요한 작업 방법과 순서를 체계적으로 정리

목적:

- 품질 향상

대표:

- 정보공학
- 객체지향

- 애자일

## 2. 구조적 방법론

> **처리 중심 + 분할과 정복(Divide and Conquer)**

- 정형화된 분석 절차
- 사용자 요구사항 파악·문서화
- 이해·검증 쉬운 프로그램 코드 생성 목적

절차:

**타당성 검토 → 계획 → 요구사항 → 설계 → 구현 → 시험 → 운용/유지보수**

**암기:** `구조적 = 처리 중심 + 분할정복`

---

## 3. 정보공학 방법론

> **자료(Data) 중심 + 대규모 정보 시스템**

- 계획
- 분석
- 설계
- 구축
- ERD 활용

절차:

**정보 전략 계획 수립 → 업무 영역 분석 → 업무 시스템 설계 → 업무 시스템 구축**

**암기:** `정보공학 = Data 중심 + ERD + 대규모`

---

## 4. 객체지향 방법론

> 현실 세계의 개체(Entity)를 **Object로 표현**

- 객체의 속성 + 메소드
- 객체지향 기법으로 분석·설계

주요 모델링:
- Package Diagram
- State Transition Diagram

절차:

**요구 분석 → 설계 → 구현 → 테스트 및 검증 → 인도**

---

## 9. 소프트웨어 재공학(Reengineering)

#### 주요 활동

| 활동 | 핵심 |
|---|---|
| Analysis | 기존 SW 명세 확인·대상 선정 |
| Restructuring | 코드 재구성 / **기능·외적 동작 변경 X** |

**암기:** `역공학 = 하위 코드 → 상위 설계·명세`

## 12. LOC(Line of Code) ★★★

예측치:

`(낙관치 + 4×기대치 + 비관치) / 6`

#### 공식

`노력(인월) = 개발 기간 × 투입 인원`

`노력(인월) = LOC / 1인당 월평균 생산 코드 라인 수`

`개발 비용 = 노력 × 단위 비용`

`개발 기간 = 노력 / 투입 인원`

`생산성 = LOC / 노력`

**암기:** `LOC → 노력 → 비용·기간·생산성`

## 15. COCOMO ★★★

> **Boehm + LOC + Man-Month**

#### 개발 유형

##### Organic
- 약 50KDSI 이하
- 비교적 작은 프로젝트
- 경험 있는 소규모 조직

##### Semi-Detached
- 약 300KDSI 이하
- 중간 규모
- 컴파일러·인터프리터 등

##### Embedded
- 300KDSI 이상
- 대형
- OS·대형 Transaction
- HW/SW/운영 조건 강하게 결합

**암기:** `조직형 → 반분리형 → 내장형`  
→ 규모·복잡도 증가

---

## 16. COCOMO 공식

#### Organic
`MM = 2.4 × (KDSI)^1.05`

`TDEV = 2.5 × (MM)^0.38`

#### Semi-Detached
`MM = 3.0 × (KDSI)^1.12`

`TDEV = 2.5 × (MM)^0.35`

#### Embedded
`MM = 3.6 × (KDSI)^1.20`

`TDEV = 2.5 × (MM)^0.32`

## 17. Putnam 모형

> **Rayleigh-Norden + 생명주기 노력 분포 + SLIM**

- Putnam 제안
- 생명주기 예측 모형
- 대형 프로젝트
- 자동화 도구: **SLIM**

---

## 18. 기능 점수(FP)

> **Albrecht 제안**

기능 증가 요인별 가중치 합산 후 영향도 적용

공식:

`FP = 총 기능 점수 × [0.65 + (0.01 × 총 영향도)]`

#### 가중치

| 항목 | 단순 | 보통 | 복잡 |
|---|---:|---:|---:|
| 자료 입력 | 3 | 4 | 6 |
| 정보 출력 | 4 | 5 | 7 |
| 명령어/질의 | 3 | 4 | 6 |
| 데이터 파일 | 7 | 10 | 15 |
| 외부 인터페이스 | 5 | 7 | 10 |

**암기:**  
`입 3·4·6 / 출 4·5·7 / 질 3·4·6 / 파일 7·10·15 / 인터 5·7·10`

자동화 도구:
- SLIM → Putnam
- ESTIMACS → FP

## 20. PERT ★★★

> **3점 추정 + Network**

사용:
- 낙관치
- 기대치
- 비관치

작업 예측치:

`(비관치 + 4×기대치 + 낙관치) / 6`

평방 편차:

`[(비관치 - 낙관치) / 6]²`

**암기:** `PERT = 낙·기·비 3점 추정`

## 27. CMMI ★★★

> 조직의 SW 프로세스 **성숙도 5단계**

1. Initial → 정의된 Process 거의 없음 / 개인 능력 의존
2. Managed → 특정 Project 내 규칙화된 Process

- Botnet → 다수 Zombie 집합
- Worm → 스스로 복제·전파
- Zero Day → **Patch 전에 공격**
- Key Logger → Keyboard 입력 탈취
- Ransomware → 암호화·잠금 후 금전 요구
- Back Door → **숨겨진 접근 통로**
- Logic Bomb → **특정 조건 만족 시 실행**
- Pharming → DNS 등 조작해 가짜 Site 유도
