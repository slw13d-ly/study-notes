## 2. Scrum

### Scrum 구성원

#### Product Owner
- 요구사항
- Product Backlog
- 우선순위 결정
- 최종 의사결정

→ **요구사항·우선순위 = PO**

#### Scrum Master
- 가이드
- 조력자
- 장애 제거
- 일일 스크럼 주관

→ **관리자가 아니라 조력자**

#### Development Team
- 실제 개발 참여자
- 디자이너·테스터 등 포함

### Scrum 순서

**제품 백로그 → 스프린트 계획 → 스프린트 → 일일 스크럼 → 검토 → 회고**

**암기:** `백계스일검회`

### 키워드

| 키워드 | 정답 |
|---|---|
| 모든 요구사항 + 우선순위 | Product Backlog |
| 이번 Sprint에서 할 일 | Sprint Backlog |
| 2~4주 | Sprint |
| 매일 약 15분 | Daily Scrum |
| 남은 작업량 | Burn-down Chart |
| 결과물 시연 | Sprint Review |
| 개선점 확인 | Sprint Retrospective |

## 3. XP

### XP 5대 가치

**의사소통 / 단순성 / 용기 / 존중 / 피드백**

**암기:** `의·단·용·존·피`

### XP 프로세스

**사용자 스토리 → 릴리즈 계획 → 스파이크 → 이터레이션 → 승인 검사 → 소규모 릴리즈**

### XP 실천법

| 지문 키워드 | 정답 |
|---|---|
| 2명이 같이 코딩 | **Pair Programming** |
| 모든 팀원이 소스 공동 소유 | **Collective Ownership** |
| 테스트 케이스 먼저 | **TDD** |
| 고객을 팀에 포함 | **Whole Team** |
| 지속적으로 코드 통합 | **Continuous Integration** |
| 기능 변경 없이 내부 구조 개선 | **Refactoring** |
| 짧은 릴리즈 반복 | **Small Releases** |

- **TDD = 테스트 먼저**
- **Refactoring = 기능은 그대로, 구조만 개선**

## 16. UML 관계

### Association 연관
→ 그냥 서로 관련

- **실선**

### Aggregation 집합
→ 전체-부분인데 **부분이 독립적으로 존재 가능**

- **빈 마름모**

### Composition 포함
→ 강한 전체-부분

- **전체가 사라지면 부분도 사라짐**
- **채운 마름모**

**핵심**
- Aggregation = 독립 가능
- Composition = 생명주기 종속

### Generalization 일반화
→ **상속**

- 빈 삼각형 화살표

### Dependency 의존
→ 일시적으로 사용

- 점선 화살표

### Realization 실체화
→ **Interface 구현**

- 점선 + 빈 화살표

## 36. 결합도

좋은 모듈:

> **결합도 ↓ / 응집도 ↑**

결합도 약 → 강:

**자료 → 스탬프 → 제어 → 외부 → 공통 → 내용**

**암기:** `자·스·제·외·공·내`

### 가장 좋은 결합도
**자료 결합도**

필요한 자료만 매개변수로 전달

### 가장 나쁜 결합도
**내용 결합도**

다른 모듈 내부를 직접 참조·수정

---

## 37. 응집도

약 → 강:

**우연 → 논리 → 시간 → 절차 → 통신 → 순차 → 기능**

**암기:** `우·논·시·절·통·순·기`

### 가장 좋음

**기능적 응집도**

모든 요소가 하나의 목적 수행

## 38. 결합도/응집도 낚시 정리

- 배열·레코드 전체 전달 → **스탬프 결합도**
- 제어 플래그 전달 → **제어 결합도**
- 전역 데이터 공동 사용 → **공통 결합도**
- 같은 시간에 실행되는 작업 → **시간적 응집도**
- 같은 입력/출력 사용 → **통신적 응집도**
- 앞 작업 출력 → 다음 작업 입력 → **순차적 응집도**

## 45. 구조 패턴 7개

- Bridge
- Composite
- Decorator
- Facade
- Flyweight
- Proxy

### 키워드

- 호환 안 되는 인터페이스 변환 → **Adapter**
- 추상부와 구현부 분리 → **Bridge**
- 트리 / 부분-전체 → **Composite**
- 동적으로 기능 추가 → **Decorator**
- 복잡한 시스템에 단순 인터페이스 → **Facade**
- 공통 데이터 공유 / 메모리 절약 → **Flyweight**
- 대리 객체 → **Proxy**

## 46. 행위 패턴

### Chain of Responsibility
요청을 **Chain 따라 전달**

### Command
요청 자체를 **객체로 캡슐화**

### Interpreter
언어 문법·해석

### Iterator
내부 구조 노출 X, 요소 순차 접근

### Mediator
중재자

### Memento
**상태 저장 → 이전 상태 복구**

### Observer
상태 변경 → 의존 객체에 **자동 통지**

### State
객체 **상태에 따라 행동 변경**

### Strategy
알고리즘을 캡슐화하여 **교환**

### Template Method
상위에서 알고리즘 골격, 일부를 하위에서 구현

### Visitor
객체 구조 변경 없이 **새 연산 추가**
