## 4. 소프트웨어 개발 보안

- **기밀성(Confidentiality(기밀성))** - 허가된 사용자만 정보에 접근할 수 있도록 보호.
- **무결성(Integrity(무결성))** - 정보가 임의로 변경·훼손되지 않고 정확하게 유지되도록 보호.
- **가용성(Availability(가용성))** - 허가된 사용자가 필요할 때 시스템·정보를 사용할 수 있도록 보장.


목적:

> **보안 취약점 최소화**

보안 3대 목표:

- 기밀성(Confidentiality(기밀성))
- 무결성(Integrity(무결성))
- 가용성(Availability(가용성))

**암기:** `기·무·가`

# SECTION 096. 배치 프로그램

## 7. 배치 프로그램

> 사용자와 상호작용 없이 **정해진 순서대로 일괄 처리**

### 종류

| 종류 | 키워드 |
|---|---|
| 정기 배치 | 일정 기간마다 / 일·주·월 |
| 이벤트성 배치 | 특정 조건 충족 시 |
| On-Demand 배치 | 사용자 요청 시 |

## 8. 배치 프로그램 필수 요소

- **대용량 데이터** - 많은 양의 데이터를 처리할 수 있어야 함.
- **자동화** - 사용자 개입 없이 정해진 절차대로 수행되어야 함.
- **견고성** - 잘못되거나 중복된 데이터가 있어도 전체 작업이 쉽게 중단되지 않아야 함.
- **안정성/신뢰성** - 오류 발생 위치와 시간을 추적할 수 있어야 함.
- **성능** - 다른 작업을 방해하지 않고 지정된 시간 안에 완료되어야 함.


- 대용량 데이터 → 대량 처리
- 자동화 → 사용자 개입 없이 수행
- 견고성 → 잘못된·중복 데이터에도 중단 X
- 안정성/신뢰성 → 오류 위치·시간 추적
- 성능 → 다른 프로그램 방해 X + 지정 시간 내 완료

## 9. Batch(배치/일괄 처리) Scheduler(배치 스케줄러) / Job(작업) Scheduler(작업 스케줄러)

### Batch(배치/일괄 처리) Scheduler(배치 스케줄러)
> 설정된 **주기**에 맞춰 자동 수행

### Job(작업) Scheduler(작업 스케줄러)
> Job을 원하는 **시간**에 처리

예:
- Spring(스프링) Batch(배치/일괄 처리)
- Quartz

# SECTION 114. 기억장치 관리의 개요

## 71. 기억장치 계층

- **기억장치 계층** - 속도·용량·비용이 다른 기억장치를 계층적으로 구성한 구조.


속도:

**Register(레지스터) > Cache(캐시) > Main Memory(주기억장치) > Secondary Storage(보조기억장치)**

위로 갈수록:
- 빠름
- 접근 시간 짧음
- 비용 ↑
- 용량 ↓

아래로 갈수록:
- 느림
- 접근 시간 김
- 비용 ↓
- 용량 ↑

## 72. 기억장치 관리 전략

- 반입(Fetch(반입)) → **언제**
- 배치(Placement(배치)) → **어디에**
- 교체(Replacement(교체)) → **무엇을**

**암기:** `반입=언제 / 배치=어디 / 교체=무엇`

## 73. Fetch(반입) 전략

### Demand Fetch(요구 반입)
> 실제 참조가 요구될 때 적재

### Anticipatory Fetch(예상 반입)
> 앞으로 쓸 것으로 예상 → 미리 적재

## 74. Placement(배치) 전략 ★★★

### First Fit(최초 적합)
> 들어갈 수 있는 **첫 번째** 영역

### Best Fit(최적 적합)
> 들어갈 수 있는 영역 중 **가장 작은** 영역

### Worst Fit(최악 적합)
> 들어갈 수 있는 영역 중 **가장 큰** 영역

**암기:** `First 처음 / Best 최소 / Worst 최대`

# SECTION 115. 가상기억장치 구현 기법 / 페이지 교체 알고리즘

## 75. 가상기억장치

> 보조기억장치 일부를 **주기억장치처럼 사용**

- 실제 RAM보다 큰 프로그램 실행 가능
- 구현:
  - Paging(페이징)
  - Segmentation(세그먼테이션)

## 76. Paging(페이징) vs Segmentation(세그먼테이션) ★★★★★

## Paging(페이징)

> **고정 크기**

- 프로그램 → Page(페이지)
- Main Memory(주기억장치) → Page(페이지) Frame(페이지 프레임)
- 내부 단편화 가능
- 외부 단편화 X
- Page(페이지) Map Table(페이지 맵 테이블) 필요

## Segmentation(세그먼테이션)

> **가변 크기 / 논리적 단위**

- Segment(세그먼트)
- Base Address(기준 주소)
- Limit(한계값)
- 외부 단편화 가능
- 공유·보호 유리

**암기:**  
`Paging(페이징) = 고정·내부`  
`Segmentation(세그먼테이션) = 가변·외부`

## 77. 페이지 교체 알고리즘 ★★★★★

- **페이지 교체 알고리즘** - 주기억장치에 새 페이지를 적재할 때 제거할 페이지를 결정하는 방법.


### OPT
> **미래에 가장 오랫동안 사용되지 않을 Page(페이지)**

- Page(페이지) Fault(페이지 부재) 가장 적은 이상적 알고리즘
- 실제 구현 어려움

### FIFO
> **가장 먼저 들어온 Page(페이지)**

- 구현 간단
- **Belady Anomaly(벨레이디의 모순)**

### LRU
> **최근 사용 시점이 가장 오래된 Page(페이지)**

### LFU
> **사용 횟수가 가장 적은 Page(페이지)**

### NUR
> Reference Bit(참조 비트) + Modified Bit(변경 비트)

교체 순서:
`00 → 01 → 10 → 11`

### SCR
> Second Chance(두 번째 기회)  
> 오래된 Page라도 최근 사용됐으면 **한 번 더 기회**

## 78. 페이지 크기

### 작은 Page(페이지)

- 단편화 ↓
- Page(페이지) Table(페이지 테이블) 크기 ↑
- Mapping(매핑) 속도 ↓
- Disk(디스크) 접근 ↑

### 큰 Page(페이지)

- 단편화 ↑
- Page(페이지) Table(페이지 테이블) 크기 ↓
- Mapping(매핑) 속도 ↑
- Disk(디스크) 접근 ↓

예:
- Loop(반복문)

예:

**암기:** `시간 = 다시 / 공간 = 근처`

## 80. Working Set(워킹 세트)

> 일정 시간 동안 **자주 참조하는 Page들의 집합**

- Page(페이지) Fault(페이지 부재) 감소
- 시간에 따라 변화

## 81. PFF

> **Page(페이지) Fault(페이지 부재) Frequency(페이지 부재 빈도)**로 Frame(프레임) 수 조절

- Page(페이지) Fault(페이지 부재) ↑ → Frame(프레임) 추가
- Page(페이지) Fault(페이지 부재) ↓ → Frame(프레임) 회수

## 82. Prepaging(프리페이징/선행 페이징)

> 앞으로 필요할 것으로 예상되는 Page를 **미리 적재**

예측 실패:
> 불필요 Page(페이지) 적재 → 효율↓

## 83. Thrashing(스래싱) ★★★

- 전체 성능 저하

방지:
- 다중 프로그래밍 정도 낮춤
- PFF 조절
- Working Set(워킹 세트) 유지
- 자원 확보
- 일부 Process(프로세스) 중단

# SECTION 117. 프로세스의 개요

## 84. 프로세스(Process(프로세스))

- **프로세스(Process(프로세스))** - 운영체제가 관리하며 CPU를 할당받아 실행 중인 프로그램.


> **실행 중인 프로그램**

동의 표현:
- Job(작업)
- Task(태스크/작업)

특징:
- PCB 보유
- CPU 할당 대상
- OS가 관리하는 실행 단위

## 85. PCB ★★★

> OS가 Process를 관리하기 위한 정보 묶음

저장:
- Process(프로세스) 상태
- Pointer
- PID
- Scheduling(스케줄링) / Priority
- CPU Register(레지스터)
- Memory 관리
- I/O 상태
- 계정 정보

**암기:** `PCB = 프로세스 관리 정보`

## 86. 프로세스 상태 전이 ★★★★★

- **Ready(준비)** - CPU만 할당받으면 바로 실행할 수 있는 상태.
- **Run(실행)** - CPU를 할당받아 실제 실행 중인 상태.
- **Wait(대기)** - 입·출력이나 특정 사건의 완료를 기다리는 상태.
- **Terminated(종료)** - 실행이 끝나 프로세스 자원이 해제되는 상태.


주요 상태:
- Ready(준비)
- Run(실행)
- Wait(대기)
- Terminated(종료)

### Ready(준비) → Run(실행)
> **Dispatch(디스패치/할당)**

### Run(실행) → Ready(준비)
> 할당 시간 종료 등

### Run(실행) → Wait(대기)
> I/O 요청

### Wait(대기) → Ready(준비)
> **Wake Up(웨이크업/깨우기)**

**암기:**  
`Dispatch(디스패치/할당) = Ready(준비) → Run(실행)`  
`Wake Up(웨이크업/깨우기) = Wait(대기) → Ready(준비)`

## 87. Spooling(스풀링)

> I/O 데이터를 보조기억장치에 저장 후 처리

목적:
> CPU와 I/O 장치의 **속도 차이 완화**

## 88. Thread(스레드)

- **Thread(스레드)** - 하나의 프로세스 안에서 독립적으로 수행되는 작업 단위.


> Process(프로세스) 내부의 **작업 단위**

- Light Weight Process(경량 프로세스)
- Scheduling(스케줄링) 최소 단위
- 하나의 Process에 여러 Thread(스레드) 가능

### 장점
- 병렬 처리
- 응답 시간 단축
- 자원 절약
- 통신 향상
- 공유 Memory 사용

## 89. 사용자 수준 / 커널 수준 Thread(스레드)

### 사용자 수준

- 사용자 Library(라이브러리)
- Kernel(커널) 직접 관여 X
- Overhead(오버헤드) 적음
- 빠름
- 구현 어려움

### Kernel(커널) 수준

- Kernel이 직접 관리
- 독립 Scheduling(스케줄링) 가능
- 구현 비교적 쉬움

# SECTION 118. 스케줄링

## 90. Scheduling(스케줄링) 종류

- **Scheduling(스케줄링)** - 실행할 프로세스에 시스템 자원과 CPU를 할당하는 작업.


### 장기 Scheduling(스케줄링)
> 어떤 Program을 시스템의 **작업으로 받아들일지**

### 중기 Scheduling(스케줄링)
> Process(프로세스) 일부를 **보류·활성화**해 부하 조절

### 단기 Scheduling(스케줄링)
> Ready(준비) Process(프로세스) 중 **CPU를 줄 Process(프로세스) 선택**

## 91. Context Switching(문맥 교환)

> CPU가 한 Process에서 다른 Process로 전환

- 현재 Process(프로세스) 상태 → PCB 저장
- 새 Process(프로세스) 상태 → PCB에서 복원
- 실제 업무 X → **Overhead(오버헤드)**

**암기:** `PCB 저장 ↔ 복원`

## 92. 비선점 / 선점 Scheduling(스케줄링) ★★★

## 비선점

> CPU **강제 회수 X**

- Process가 반납할 때까지 사용
- 예측 쉬움
- Batch에 유리
- FCFS / SJF / Priority / HRN 등

## 선점

> CPU **강제 회수 O**

- 응답 빠름
- 대화식 시분할에 적합
- Overhead(오버헤드) 큼
- Round Robin / SRT / 선점 Priority 등

# SECTION 119. 주요 스케줄링 알고리즘

## 93. FCFS / SJF / HRN ★★★★★

### FCFS

> **먼저 온 Process(프로세스) 먼저**

- 비선점
- 공평
- 긴 작업 때문에 짧은 작업 대기 가능

대기 시간:
> Ready에서 기다린 시간

반환 시간:
> 대기 시간 + 실행 시간

### SJF

> **실행 시간 가장 짧은 Process(프로세스) 먼저**

- 비선점
- 평균 대기 시간 감소
- 긴 작업 → **Starvation(기아 현상)**

### HRN

> SJF의 Starvation(기아 현상) 보완

공식:

`우선순위 = (대기 시간 + 서비스 시간) / 서비스 시간`

> 오래 기다릴수록 우선순위 ↑

> `IP주소/Network(네트워크) bit 수`

**암기:** `Subnet Mask(서브넷 마스크) 1=Network(네트워크) / 0=Host(호스트)`

# SECTION 125. TCP/IP

## 113. TCP/IP

- **TCP/IP** - 인터넷 통신에 사용되는 TCP와 IP를 중심으로 한 표준 프로토콜 집합.


> TCP + IP Protocol(프로토콜) 집합

### 4계층

**응용 → 전송 → 인터넷 → 네트워크 액세스**

## 114. TCP vs IP

### TCP

> **연결형 / 신뢰성**

- 패킷 순서 제어
- 오류 제어
- 흐름 제어
- Stream(스트림)
- Connection-Oriented(연결 지향)

### IP

> **비연결형 / 주소 지정 / 경로 선택**

- Datagram(데이터그램)
- Best Effort(최선형 서비스)

**암기:** `TCP=연결·신뢰 / IP=비연결·주소·경로`
