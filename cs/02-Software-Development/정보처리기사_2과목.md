# 정보처리기사 2과목

# SECTION 028. 자료 구조

## 1. 자료 구조

> **자료를 효율적으로 저장·처리하기 위한 저장 방법과 자료 간 관계를 다루는 구조**

### 자료 구조 분류

#### 선형 구조
- 배열(Array)
- 선형 리스트
- 스택(Stack)
- 큐(Queue)
- 데크(Deque)

#### 비선형 구조
- 트리(Tree)
- 그래프(Graph)

**암기:**  
`선형 = 배열·리스트·스택·큐·데크 / 비선형 = 트리·그래프`

## 2. 배열(Array)

문제 키워드:
- **같은 자료형**
- **Index(첨자)**
- **크기 고정**
- 정적 자료 구조
- 반복 처리에 적합

→ **배열(Array)**

**핵심:** `같은 자료형 + Index(인덱스) + 크기 고정`

## 3. 선형 리스트

### 연속 리스트(Contiguous List)

키워드:
- 연속된 기억장소
- 기억장소 이용 효율 좋음
- 삽입·삭제 시 **자료 이동 필요**
- 중간 삽입 시 연속 빈 공간 필요

→ **연속 리스트**

### 연결 리스트(Linked List)

키워드:
- **Node(노드) + Pointer(포인터, Link(링크))**
- 비연속 기억장소 가능
- 삽입·삭제 쉬움
- 포인터 저장 공간 필요
- 접근 속도 느림

→ **연결 리스트**

**암기:**  
`연속 = 메모리 연속·이동 필요`  
`연결 = Node(노드)+Pointer(포인터)·삽입삭제 쉬움`

## 4. 스택(Stack)

> **LIFO(후입선출) = Last In First Out(후입선출) = 후입선출**

- 삽입 → **PUSH(삽입)**
- 삭제 → **POP(삭제)**
- 마지막 삽입 위치 → **TOP(최상단)**
- 맨 아래 → Bottom(최하단)

#### Overflow(오버플로) / Underflow(언더플로)

- 가득 차서 삽입 불가 → **Overflow(오버플로)**
- 비어서 삭제 불가 → **Underflow(언더플로)**

#### 스택 활용

- 함수 호출 순서
- 인터럽트 처리
- 수식 계산
- 괄호 검사
- 작업 스케줄링

**암기:**  
`Stack(스택) = LIFO(후입선출) / Push(삽입) 넣기 / Pop(삭제) 빼기`

## 5. 큐(Queue)

> **FIFO(선입선출) = First In First Out(선입선출) = 선입선출**

- **Front(앞쪽) = 삭제**
- **Rear(뒤쪽) = 삽입**

**암기:**  
`Queue(큐) = FIFO(선입선출) / Front(앞쪽) 삭제 / Rear(뒤쪽) 삽입`

## 6. 데크(Deque)

> **양쪽 끝에서 삽입·삭제 가능**

#### 입력 제한 데크
- **Scroll(스크롤)**
- 입력 한쪽
- 출력 양쪽

#### 출력 제한 데크
- **Shelf(셸프)**
- 입력 양쪽
- 출력 한쪽

**암기:**  
`Scroll(스크롤) = 입력 제한 / Shelf(셸프) = 출력 제한`

## 7. 그래프(Graph)

구성:

> **Vertex(정점) + Edge(간선)**

#### 최대 간선 수

정점이 `n`개일 때:

- 무방향 그래프 → **n(n-1)/2**
- 방향 그래프 → **n(n-1)**

**암기:**  
`무방향 = 반쪽 / 방향 = 두 배`

#### 인접 행렬

> 정점 간의 연결 관계를 **행렬(Matrix)**로 표현

- 인접 → **1**
- 비인접 → **0**

# SECTION 029. 트리(Tree)

## 8. 트리(Tree)

> **사이클이 없는 그래프**

- 맨 위 → Root(루트)
- 자식 없음 → Terminal(단말 노드) / Leaf(리프 노드)
- 노드에서 뻗은 가지 수 → Degree(차수)
- 트리의 차수 → **노드 차수 중 최댓값**
- 동일 부모 → Sibling(형제 노드)
- 최대 레벨 → Depth(깊이)

## 9. 트리 운행법 ★★★

| 운행 | 순서 | 암기 |
|---|---|---|
| Preorder(전위) | Root(루트) → Left(왼쪽) → Right(오른쪽) | **루왼오** |
| Inorder(중위) | Left(왼쪽) → Root(루트) → Right(오른쪽) | **왼루오** |
| Postorder(후위) | Left(왼쪽) → Right(오른쪽) → Root(루트) | **왼오루** |

**핵심:**
- Pre(전위) → Root(루트) **먼저**
- In(중위) → Root(루트) **가운데**
- Post(후위) → Root(루트) **마지막**

## 10. 수식 표기법

예: `A + B`

- Prefix(전위 표기법) → `+AB`
- Infix(중위 표기법) → `A+B`
- Postfix(후위 표기법) → `AB+`

**암기:**
- Prefix(전위 표기법) = 연산자 **앞**
- Infix(중위 표기법) = 연산자 **중간**
- Postfix(후위 표기법) = 연산자 **뒤**

# SECTION 030. 정렬(Sort)

## 11. 정렬(Sort) ★★★

| 정렬 | 문제 키워드 | 평균 | 최악 |
|---|---|---:|---:|
| Insertion(삽입 정렬) | 앞쪽 정렬 영역에 **삽입** | O(n²) | O(n²) |
| Shell(셸 정렬) | Insertion(삽입 정렬) 확장 / **간격 h** | O(n^1.5) | O(n²) |
| Selection(선택 정렬) | 매 회 **최솟값 선택** | O(n²) | O(n²) |
| Bubble(버블 정렬) | **인접** 자료 비교·교환 | O(n²) | O(n²) |
| Quick(퀵 정렬) | **Pivot(피벗) / 분할정복** | O(n log n) | O(n²) |
| Heap(힙 정렬) | **완전 이진 트리** | O(n log n) | O(n log n) |
| Merge(합병 정렬) | 정렬된 **두 파일 합병** | O(n log n) | O(n log n) |
| Radix(기수 정렬) | **자릿수 / Bucket(버킷) / Queue(큐)** | O(dn) | O(dn) |

#### 바로 찍기

- `앞의 키들과 비교해 알맞은 위치에 끼움` → **Insertion(삽입 정렬)**
- `간격 h를 줄여가며` → **Shell(셸 정렬)**
- `최솟값 찾아 앞에 배치` → **Selection(선택 정렬)**
- `이웃끼리 교환` → **Bubble(버블 정렬)**
- `Pivot(피벗) / Divide & Conquer(분할 정복) / Stack(스택)` → **Quick(퀵 정렬)**
- `Complete Binary Tree(완전 이진 트리)` → **Heap(힙 정렬)**
- `정렬된 파일 합침` → **Merge(합병 정렬)**
- `Bucket(버킷) / Queue(큐) / Digit(자릿수)` → **Radix(기수 정렬)**

#### 복잡도 핵심

- 빠른 평균 → **Quick(퀵 정렬) / Heap(힙 정렬) / Merge(합병 정렬) = O(n log n)**
- 최악까지 O(n log n) → **Heap(힙 정렬) / Merge(합병 정렬)**
- Quick(퀵 정렬) 최악 → **O(n²)**

# SECTION 031. 검색 - 이분 검색 / 해싱

## 12. 이분 검색(Binary Search)

키워드:
- **정렬 필수**
- 중간값과 비교
- 검색 범위를 절반씩 줄임

→ **Binary Search(이분 검색)**

중간 위치:

`M = (F + L) / 2`

**암기:** `정렬 + 절반`

## 13. 해싱(Hashing)

> **Key(키) → Hash Function(해시 함수) → Address(주소)**

#### 용어

- Bucket(버킷) → 하나의 주소가 가리키는 구역
- Slot(슬롯) → 레코드 하나 저장 공간
- Collision(충돌) → **서로 다른 Key(키)가 같은 주소**
- Synonym(동의어) → 충돌로 같은 Home Address(홈 주소)를 갖는 레코드
- Overflow(오버플로) → 해당 Bucket(버킷)에 **빈 Slot(슬롯) 없음**

## 14. 해싱 함수

| 키워드 | 정답 |
|---|---|
| 나머지 이용 | **제산법(Division)** |
| Key(키) 제곱 후 중간 부분 | **제곱법(Mid-Square)** |
| Key(키)를 나눠 더하거나 XOR | **폴딩법(Folding)** |
| 진수 변환 | **기수 변환법(Radix)** |
| 다항식 계수 | **대수적 코딩법** |
| 자릿수 분포 분석 | **숫자 분석법** |
| 난수 발생 | **무작위법(Random)** |

**암기:** `제산·제곱·폴딩·기수·대수·숫자·무작위`

## 15. Collision(충돌) 해결

- **Chaining(체이닝)** → Linked List(연결 리스트)로 연결
- **Open Addressing(개방 주소법)** → 다음 빈 주소 탐색
- **Rehashing(재해싱)** → 다른 Hash Function(해시 함수) 사용

**암기:**  
`체인 = 연결 리스트`  
`오픈 = 빈 자리`  
`재해싱 = 다른 함수`

# SECTION 032. 데이터베이스 개요

## 16. 데이터베이스(Database)

> 특정 조직의 업무 수행에 필요한 **상호 관련된 데이터들의 모임**

DB(데이터베이스) 정의 4개:

- 통합된 데이터(Integrated) - **중복을 최소화한 데이터**
- 저장된 데이터(Stored) - **컴퓨터가 접근 가능한 저장 매체에 저장된 데이터**
- 운영 데이터(Operational) - **조직의 고유 업무 수행에 필요한 데이터**
- 공용 데이터(Shared) - **여러 응용 시스템이 공동으로 사용하는 데이터**

**암기:** `통·저·운·공`

## 17. DBMS(데이터베이스 관리 시스템) 필수 기능 ★★★

> **사용자와 데이터베이스 사이에서 DB(데이터베이스)를 구축·접근·관리하는 소프트웨어**

#### 정의(Definition)
- 데이터 Type(자료형)
- 구조
- 이용 방식
- 제약 조건

#### 조작(Manipulation)
- 검색
- 삽입
- 삭제
- 갱신

#### 제어(Control)
- 무결성
- 보안·권한
- 병행 제어

**암기:** `정·조·제`

## 18. DBMS(데이터베이스 관리 시스템) 장·단점

#### 장점

- 데이터 독립성
- 중복 감소
- 공유 가능
- 일관성·무결성
- 보안
- 표준화
- 통합 관리

#### 단점

- 전문가 필요
- 비용 증가
- 시스템 복잡
- Backup(백업) / Recovery(회복) 어려움
- 집중 Access(접근) 과부하

## 19. 데이터 독립성

#### 논리적 독립성

> DB(데이터베이스) **논리 구조 변경** → 응용 프로그램 영향 X

#### 물리적 독립성

> 저장장치·저장 방식 등 **물리 구조 변경** → 응용 프로그램 영향 X

## 20. 스키마(Schema) ★★★

> 데이터베이스의 **구조와 제약 조건에 관한 전반적인 명세**

#### 외부 스키마

> **사용자 / 응용 프로그램 View(뷰)**

- Sub Schema(서브 스키마)

#### 개념 스키마

> **DB(데이터베이스) 전체의 논리 구조**

- 모든 사용자·프로그램의 데이터 종합
- **하나만 존재**

#### 내부 스키마

> **실제 물리 저장**

- 레코드 형식
- 저장 순서
- 저장 방법

**암기:**  
`외부 = 사용자 View(뷰) / 개념 = 전체 논리 / 내부 = 실제 물리`

# SECTION 033. 절차형 SQL(구조화 질의어)

## 21. 절차형 SQL(구조화 질의어)

> 일반 프로그래밍 언어처럼 **연속 실행·분기·반복 제어가 가능한 SQL(구조화 질의어)**

#### Procedure(프로시저)

> **호출하면 실행**

#### Trigger(트리거)

> 삽입·갱신·삭제 등 **이벤트 발생 시 자동 실행**

#### 사용자 정의 함수

> 종료 시 **RETURN(반환)으로 값 반환**

**암기:**  
`프로시저 = 호출 / 트리거 = 자동 / 함수 = RETURN(반환)`

## 22. 절차형 SQL(구조화 질의어) 테스트·디버깅

- **테스트** → 오류 존재 여부 확인
- **디버깅** → 오류의 원인을 찾아 **수정**

#### 쿼리 최적화 순서

**성능 측정 → 대상 쿼리 선정 → 실행 계획 검토 → SQL(구조화 질의어)·Index(인덱스) 재구성**

- **Optimizer(옵티마이저)** - 쿼리를 효율적으로 수행하기 위한 **실행 계획을 수립**

# SECTION 034. 단위 모듈 구현

## 23. 단위 모듈(Unit Module)

> 하나의 기능을 수행하는 작은 모듈

좋은 단위 모듈:

- 결합도 ↓
- 응집도 ↑
- 독립적 컴파일 가능

#### 구현 순서

**단위 기능 명세 → 입·출력 기능 → 알고리즘**

**암기:** `명세 → 입출력 → 알고리즘`

#### 단위 기능 명세

- **추상화** - 복잡한 시스템을 단순하게 표현
- **구조화** - 시스템을 단위 기능별로 분해하고 계층화
- **정보 은닉** - 모듈 내부 정보가 다른 모듈에 영향을 주지 않도록 숨김

**암기:** `추상화 + 구조화 + 정보 은닉`

## 24. IPC(Inter-Process Communication, 프로세스 간 통신)

> **프로세스 간 통신**

종류:
- Shared Memory(공유 메모리)
- Socket(소켓)
- Semaphore(세마포어)
- Pipes & Named Pipes(파이프 및 명명된 파이프)
- Message Queue(메시지 큐)

#### 바로 찍기

- 공유 메모리 영역 → **Shared Memory(공유 메모리)**
- 네트워크 소켓 → **Socket(소켓)**
- 공유 자원 접근 제어 → **Semaphore(세마포어)**
- FIFO(선입선출) 형태 메모리 → **Pipe(파이프)**
- 메시지 전달 → **Message Queue(메시지 큐)**

## 25. 단위 기능 구현 모듈 종류

| 키워드 | 모듈 |
|---|---|
| 하드웨어 주변 장치 | **디바이스 드라이버 모듈** |
| 네트워크 장비·통신 | **네트워크 모듈** |
| 내부 데이터 구조 접근 | **파일 모듈** |
| 가상 메모리 매핑·해제 / IPC(프로세스 간 통신) | **메모리 모듈** |
| 다른 프로세스 생성 | **프로세스 모듈** |

#### Test Case(테스트 케이스)

## 27. ISO/IEC/IEEE 29119-3 Test Case(테스트 케이스) 구성

# SECTION 038. 디지털 저작권 관리(DRM)

## 36. DRM(디지털 저작권 관리)

> **디지털 콘텐츠의 생성 → 유통 → 이용 전 과정의 저작권 보호**

#### 중요 구성 요소

| 키워드 | 정답 |
|---|---|
| 권한·라이선스·암호화 키·결제 | **Clearing House(클리어링 하우스)** |
| 저작권자 | **Contents Provider(콘텐츠 제공자)** |
| 콘텐츠 암호화·포장 | **Packager(패키저)** |
| 암호화 콘텐츠 유통 | **Contents Distributor(콘텐츠 유통자)** |
| 콘텐츠 구매·사용 | **Customer(고객)** |
| 이용 권한 통제 | **DRM Controller(DRM 제어기)** |
| 원본 안전 유통 보안 장치 | **Security Container(보안 컨테이너)** |

**핵심:**  
`Clearing House(클리어링 하우스) = 권한·라이선스·키·결제`  
`Packager(패키저) = 암호화 포장`  
`DRM Controller(DRM 제어기) = 이용 권한 통제`

## 37. DRM(디지털 저작권 관리) 기술 요소

- 암호화(Encryption) - **콘텐츠·라이선스 암호화 및 전자서명**
- 키 관리(Key Management) - **암호화 키 저장·분배**
- 암호화 파일 생성(Packager) - **콘텐츠를 암호화된 형태로 생성**
- 식별 기술(Identification) - **콘텐츠 식별 체계 표현**
- 저작권 표현(Right Expression) - **라이선스 내용 표현**
- 정책 관리(Policy Management) - **라이선스 발급·사용 정책 관리**
- 크랙 방지(Tamper Resistance) - **불법 크랙에 의한 사용 방지**
- 인증(Authentication) - **사용자 인증**

**암기:** `암·키·패·식·권·정·크·인`

# SECTION 042. 소프트웨어 버전 관리 도구

## 42. 버전 관리 방식

| 방식 | 저장 위치 | 핵심 |
|---|---|---|
| 공유 폴더 | 로컬 공유 폴더 | 파일 직접 복사 |
| Client/Server(클라이언트/서버) | 중앙 서버 | 중앙 통합 관리 |
| 분산 저장소 | 원격 + Local(로컬) | Local(로컬)에서도 버전 관리 |

#### 대표

- SVN → **Client/Server(클라이언트/서버)**
- Git → **분산 저장소**

## 43. SVN

키워드:
- CVS 개선
- Client/Server(클라이언트/서버)
- **trunk(트렁크) / branches(브랜치)**
- Commit(커밋)마다 **Revision(리비전) +1**

#### SVN 명령어

- add → 등록
- commit → 서버 반영
- update → 서버 최신 내용 → Client(클라이언트) 반영
- checkout → 서버에서 받아오기
- diff → 차이
- merge → 병합
- lock/unlock → 잠금/해제
- import → 최초 저장
- export → 버전 정보 제외 순수 소스 받기

**암기:** `SVN = 중앙 + Revision(리비전)`

## 44. Git

키워드:
- Linus Torvalds
- 2005
- **분산 버전 관리**
- Local(로컬) + Remote(원격)
- Snapshot(스냅샷)
- Branch(브랜치)

#### Git 명령어

- add → **Staging Area(스테이징 영역)**
- commit → **Local(로컬) 저장**
- push → **Local(로컬) → Remote(원격)**
- fetch → **Remote(원격) → Local(로컬)**
- branch → Branch(브랜치) 생성/삭제
- checkout → Branch(브랜치) 이동
- merge → 병합
- init → Local Repository(로컬 저장소) 생성
- remote add → 원격 저장소 연결

**암기:**  
`add = Stage(스테이지)`  
`commit = Local(로컬)`  
`push = Remote(원격) 반영`  
`fetch = Remote(원격) → Local(로컬)`

## 45. SVN vs Git

| 구분 | SVN | Git |
|---|---|---|
| 방식 | Client/Server(클라이언트/서버) | **분산** |
| 저장소 | 중앙 | Local(로컬) + Remote(원격) |
| Commit(커밋) | 서버 반영 | Local(로컬) 우선 |
| 오프라인 | 제한적 | 가능 |
| 특징 | Revision(리비전) | Snapshot(스냅샷) / Branch(브랜치) |

**암기:** `SVN = 중앙 / Git = 분산`

## 48. 애플리케이션 테스트 기본

> 애플리케이션에 잠재된 **결함을 찾고 요구사항 충족 여부와 기능 수행을 확인하는 테스트 절차**

#### Verification(검증)

> **개발자 관점 / 명세대로 만들었는가?**

#### Validation(확인)

> **사용자 관점 / 요구사항을 만족하는가?**

**암기:**  
`Verification(검증) = 개발자·명세`  
`Validation(확인) = 사용자·요구`

## 49. 테스트 기본 원리 ★★★

#### Pareto Principle(파레토 원리)

> **20% 코드 → 80% 결함**

#### Pesticide Paradox(살충제 패러독스)

> 같은 Test Case(테스트 케이스)를 계속 반복하면 **새로운 결함 발견 능력 ↓**

→ 테스트 케이스 지속 개선 필요

#### Absence of Errors Fallacy(오류 부재의 궤변)

> 결함이 없어도 **사용자 요구를 만족하지 못하면 실패**

## 50. 정적 테스트 vs 동적 테스트

#### 정적(Static)

> **실행 X**

- Walkthrough(워크스루)
- Inspection(인스펙션)
- Code Inspection(코드 인스펙션)

#### 동적(Dynamic)

> **실행 O**

- White Box(화이트박스)
- Black Box(블랙박스)

## 51. 테스트 기반에 따른 분류

#### 명세 기반
> 사용자 요구사항·명세

- 동등 분할
- 경계값 분석

#### 구조 기반
> 내부 논리 구조

- 구문
- 결정
- 조건 기반

#### 경험 기반
> 테스터 경험

- 에러 추정
- 체크리스트
- 탐색적 테스트

## 52. 목적에 따른 테스트

| 지문 키워드 | 정답 |
|---|---|
| 장애 후 정상 복구 | **Recovery(회복)** |
| 불법 접근 방지 | **Security(보안)** |
| 과도한 부하 | **Stress(강도)** |
| 응답시간·처리량 | **Performance(성능)** |
| 내부 경로·복잡도 | **Structure(구조)** |
| 수정 후 새 결함 여부 | **Regression(회귀)** |
| 신·구 시스템 동일 데이터 결과 비교 | **Parallel(병행)** |

# SECTION 046. 테스트 기법에 따른 애플리케이션 테스트

## 53. White Box Test(화이트박스 테스트) ★★★

> **내부 구조 / 논리 경로 / 구조 기반**

#### 제어 구조 검사

- 조건 검사 - **모듈 내 논리적 조건을 테스트**
- 루프 검사 - **반복 구조에 초점을 맞춰 테스트**
- 데이터 흐름 검사 - **변수의 정의·사용 위치를 중심으로 테스트**

#### Coverage(커버리지)

- Statement Coverage(문장 커버리지) → **모든 문장 1회 이상**
- Branch/Decision Coverage(분기/결정 커버리지) → 결정 결과 **True(참) / False(거짓)**
- Condition Coverage(조건 커버리지) → **개별 조건** True(참) / False(거짓)
- Branch/Condition Coverage(분기/조건 커버리지) → 분기 + 개별 조건 T/F

## 54. Black Box Test(블랙박스 테스트) ★★★

> **내부 코드 X / 기능·입출력 중심**

종류:

- 동치 분할
- 경계값 분석
- 원인-효과 그래프
- 오류 예측
- 비교 검사

**암기:** `동·경·원·오·비`

#### 바로 찍기

- 입력 범위를 같은 성격의 그룹으로 → **동치 분할**
- 경계에서 오류 확률 높음 → **경계값**
- 입력 조건과 출력 결과의 관계 → **원인-효과 그래프**
- 경험·감각 → **오류 예측**
- 여러 버전 같은 데이터 결과 비교 → **비교 검사**

# SECTION 047. 개발 단계에 따른 애플리케이션 테스트

## 55. V-Model(V 모델) ★★★

개발 단계 ↔ 테스트 단계

- 구현 → **단위 테스트**
- 설계 → **통합 테스트**
- 분석 → **시스템 테스트**
- 요구사항 → **인수 테스트**

**암기:**  
`구단 / 설통 / 분시 / 요인`

## 56. 개발 단계별 테스트

#### Unit Test(단위 테스트)

- 최소 단위 모듈
- 구조 기반 + 명세 기반
- 알고리즘·반복·계산 오류 발견

#### Integration Test(통합 테스트)

- 모듈 간 **상호작용·인터페이스 오류**

#### System Test(시스템 테스트)

- 전체 시스템
- 기능 요구사항 + 비기능 요구사항

#### Acceptance Test(인수 테스트)

- 사용자의 요구사항 충족 여부
- 사용자가 직접 확인

## 57. 인수 테스트

- 사용자 인수 → 사용 적절성
- 운영상 인수 → 백업·복원·재난 복구·사용자 관리
- 계약 인수 → 계약 조건
- 규정 인수 → 법규·지침

#### Alpha(알파 테스트)

> **개발자 장소 + 사용자와 개발자가 함께**

#### Beta(베타 테스트)

> **실제 사용 환경 + 실제 사용자 + 개발자 없이**

# SECTION 049. 테스트 케이스 / 테스트 시나리오 / 테스트 오라클

## 61. Test Case(테스트 케이스) 작성

Test Case(테스트 케이스):

> **입력값 + 실행 조건 + 기대 결과**

작성 순서:

1. 테스트 계획 검토·자료 확보
2. 위험 평가·우선순위
3. 테스트 요구사항 정의
4. 테스트 구조·방법 결정
5. 테스트 케이스 정의
6. 타당성 확인·유지보수

## 62. Test Scenario(테스트 시나리오) / Test Oracle(테스트 오라클)

#### Test Scenario(테스트 시나리오)

> **여러 Test Case(테스트 케이스)의 실행 순서**

#### Test Oracle(테스트 오라클)

> 실제 결과와 비교할 **참값**

## 63. Test Oracle(테스트 오라클) 종류 ★★★

- **True Oracle(참 오라클)** → 모든 입력에 기대 결과 제공
- **Sampling Oracle(샘플링 오라클)** → 일부 입력에만 제공
- **Heuristic Oracle(휴리스틱 오라클)** → 일부는 정확 + 나머지 추정
- **Consistent Oracle(일관성 오라클)** → 변경 전·후 결과 비교

**암기:**  
`True(참) = 전부 / Sampling(샘플링) = 일부 / Heuristic(휴리스틱) = 일부+추정 / Consistent(일관성) = 전후 비교`

**암기:** `정적 / 케이스 / 실행 / 성능 / 통제 / 하네스`

- Mock Object(목 객체) - **미리 정한 조건에 따라 예정된 행위를 수행하는 객체**

# SECTION 051. 결함 관리

## 66. 결함(Fault)

> **예상 결과 ≠ 실제 결과**

## 67. 결함 관리 프로세스

**계획 → 기록 → 검토 → 수정 → 재확인 → 상태 추적·모니터링 → 최종 분석·보고**

- 계획 - **일정·인력·업무 절차 수립**
- 기록 - **발견 결함을 관리 DB(데이터베이스)에 등록**
- 검토 - **등록된 내용이 실제 결함인지 확인**
- 수정 - **개발자가 결함 수정**
- 재확인 - **수정 후 다시 테스트**
- 상태 추적·모니터링 - **결함 상태와 발생 추이를 지속 확인**
- 최종 분석·보고 - **결함 정보를 분석해 보고서 작성**

## 68. 결함 상태 ★★★

기본 흐름:

**Open(등록) → Reviewed(검토) → Assigned(할당) → Resolved(해결) → Closed(종료)**

- Deferred(보류) → **보류**
- Clarified(결함 아님) → **결함 아님**

## 69. 결함 지표

- 결함 분포 → **어디에 많은가**
- 결함 추세 → **시간에 따라 어떻게 변하는가**
- 결함 에이징 → **얼마나 오래 남아 있는가**

## 70. 결함 심각도 vs 우선순위

#### 심각도(Severity)

> **시스템에 미치는 영향 크기**

- High(높음) → 핵심 요구 미구현·시스템 실패
- Medium(중간) → 시스템 흐름 영향
- Low(낮음) → GUI(그래픽 사용자 인터페이스)·메시지 등 영향 적음

#### 우선순위(Priority)

> **얼마나 빨리 고칠 것인가**

**암기:**  
`심각도 = 영향 / 우선순위 = 속도`

## 71. 결함 관리 도구

- Mantis - **결함·이슈 추적**
- Trac - **결함 추적과 작업을 통합 관리**
- Redmine - **프로젝트 관리 + 결함 추적**
- Bugzilla - **결함 신고·확인·처리 및 우선순위 관리**

# SECTION 052. 복잡도

## 72. 점근 표기법

- Big-O → **최악**
- Big-Θ → **평균**
- Big-Ω → **최상**

**암기:** `O 최악 / Θ 평균 / Ω 최상`

## 73. 시간 복잡도

> 알고리즘을 수행하기 위해 필요한 **연산 횟수를 수치화한 것**

효율 좋은 순:

`O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)`

#### 대표

- O(1) → Stack(스택) Push(삽입)/Pop(삭제)
- O(log n) → Binary Search(이분 검색)
- O(n) → 단일 반복
- O(n log n) → Heap(힙 정렬) / Merge(합병 정렬)
- O(n²) → 이중 반복 / 삽입·선택·버블 등
- O(2ⁿ) → Fibonacci(피보나치) 계열

## 74. 순환 복잡도(Cyclomatic Complexity) ★★★

> 프로그램의 **독립적인 경로 수**

- 제어 흐름도의 영역 수
- 모든 경로를 테스트하기 위한 최소 테스트 횟수의 상한선

공식:

`V(G) = E - N + 2`

- E = Edge(간선) 수
- N = Node(노드) 수

- 수신 / 사후 조건 → **내부 모듈**

# SECTION 055. 모듈 연계를 위한 인터페이스 기능 식별

## 79. EAI(기업 애플리케이션 통합) ★★★

> **기업 내 Application(애플리케이션) 간 연계·통합**

#### 구축 유형

##### Point-to-Point(포인트 투 포인트)
- 1:1 직접 연결
- 단순
- 연결 많아지면 관리 어려움

##### Hub & Spoke(허브 앤 스포크)
- 중앙 **Hub(허브)**
- 유지보수·확장 쉬움
- Hub(허브) 장애 → 전체 영향

##### Message Bus(메시지 버스)
- 미들웨어 **Bus(버스)**
- 확장성 높음
- 대용량 처리

##### Hybrid(하이브리드)
> **Hub & Spoke(허브 앤 스포크) + Message Bus(메시지 버스)**

- 데이터 병목 최소화

## 80. ESB(엔터프라이즈 서비스 버스)

> **Service(서비스) 중심 + 표준 기반 + Loose Coupling(느슨한 결합)**

#### EAI(기업 애플리케이션 통합) vs ESB(엔터프라이즈 서비스 버스)

- EAI(기업 애플리케이션 통합) → **Application(애플리케이션) 통합 중심**
- ESB(엔터프라이즈 서비스 버스) → **Service(서비스) 통합 중심 / 느슨한 결합**

## 81. 연계 기능 시나리오

구성:

**사전 조건 → 기능 동작 → 사후 조건**

#### 외부·내부 모듈

- 외부 모듈 → 요청·결과 전달
- 내부 모듈 → 처리 + 결과 반환

# SECTION 057. 인터페이스 구현

## 83. 인터페이스 구현

> 송·수신 시스템 간 **데이터 교환과 처리를 실제로 구현하는 작업**

대표 방식:

1. **데이터 통신 방식** - JSON(자바스크립트 객체 표기법)·XML(확장 마크업 언어) 등의 데이터 포맷을 전송하고 수신 측에서 Parsing(파싱)
2. **인터페이스 엔티티(Entity) 방식** - 별도의 인터페이스 테이블을 두고 Write(쓰기) / Read(읽기)

## 84. JSON(자바스크립트 객체 표기법) / XML(확장 마크업 언어) / AJAX(비동기 자바스크립트 및 XML) ★★★

#### JSON(자바스크립트 객체 표기법)

> **Key-Value(키-값, Attribute-Value Pair(속성-값 쌍))**

- 사람이 읽기 쉬움
- 기계도 분석하기 쉬움

#### XML(확장 마크업 언어)

> **Markup(마크업) 기반 데이터 표현·전송**

#### AJAX(비동기 자바스크립트 및 XML)

> JavaScript(자바스크립트)를 이용한 **비동기 통신**

- 페이지 전체 새로고침 없이 필요한 데이터만 교환

**암기:**  
`JSON(자바스크립트 객체 표기법) = Key-Value(키-값) / XML(확장 마크업 언어) = Markup(마크업) / AJAX(비동기 자바스크립트 및 XML) = 비동기`

## 85. JSON(자바스크립트 객체 표기법) 인터페이스 구현 순서

**데이터 선택 → JSON(자바스크립트 객체 표기법) 생성 → 전송 → Parsing(파싱)·처리 → 결과 반환**

## 86. 인터페이스 엔티티 방식

> **Interface Table(인터페이스 테이블) + Write(쓰기) / Read(읽기)**

순서:

1. 송신 데이터 발생
2. 송신 측 Table(테이블)에 Write(쓰기)
3. 정해진 주기로 전달
4. 수신 측 Table(테이블)에서 Read(읽기)
5. 트랜잭션 수행
