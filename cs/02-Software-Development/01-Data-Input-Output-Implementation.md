# 01. 데이터 입·출력 구현

## SECTION 028. 자료 구조

### 1. 자료 구조의 정의
- **자료 구조(Data Structure)** - 프로그램에서 사용하기 위한 자료를 기억장치의 공간 내에 **저장하는 방법**과 저장된 그룹 내에 존재하는 **자료 간의 관계**, 처리 방법 등을 연구·분석하는 것
- 자료를 효율적으로 저장·처리하기 위해 사용
- 프로그램의 **실행 시간 단축**과 **기억장소의 효율적인 이용**에 영향을 줌

### 2. 자료 구조의 분류

```text
자료 구조
├─ 선형 구조(Linear Structure)
│  ├─ 배열(Array)
│  ├─ 선형 리스트(Linear List)
│  │  ├─ 연속 리스트(Contiguous List)
│  │  └─ 연결 리스트(Linked List)
│  ├─ 스택(Stack)
│  ├─ 큐(Queue)
│  └─ 데크(Deque)
└─ 비선형 구조(Non-Linear Structure)
   ├─ 트리(Tree)
   └─ 그래프(Graph)
```

> ⭐ `선형 = 배열 / 리스트 / 스택 / 큐 / 데크`  
> ⭐ `비선형 = 트리 / 그래프`

### 3. 배열(Array)
- **동일한 자료형의 데이터**가 같은 크기로 나열되어 순서를 갖는 집합
- 정적인 자료 구조이므로 **기억장소의 추가가 어렵고**, 데이터 삭제 시 공간이 그대로 남아 **메모리 낭비**가 발생할 수 있음
- **첨자(Index)**를 이용하여 데이터에 접근
- 반복문을 이용한 처리에 적합
- 데이터마다 동일한 이름의 변수를 사용하는 것보다 처리가 간편
- 사용하는 첨자의 개수에 따라 **n차원 배열**이라고 함

> ⭐ `배열 = 같은 자료형 / Index 접근 / 크기 고정`

### 4. 선형 리스트(Linear List)
- 일정한 순서에 의해 나열된 자료 구조
- **연속 리스트(Contiguous List)**와 **연결 리스트(Linked List)**로 구분

#### 연속 리스트(Contiguous List)
- 배열과 같이 **연속되는 기억장소**에 저장
- 기억장소 이용 효율은 좋음
- 중간에 데이터를 삽입하려면 연속된 빈 공간이 필요하며, 삽입·삭제 시 자료를 이동해야 함

> ⭐ `연속 리스트 = 연속 메모리 / 삽입·삭제 시 이동 필요`

#### 연결 리스트(Linked List)
- 자료를 반드시 연속된 기억장소에 저장하지 않고 **노드(Node)** 단위로 저장
- 각 노드는 데이터 부분과 다음 노드를 가리키는 **포인터(Link)** 부분으로 구성
- 삽입·삭제가 쉬움
- 기억 공간이 연속적이지 않아도 저장 가능
- 연결을 위한 포인터 공간이 추가로 필요
- 포인터를 찾는 시간이 필요하므로 접근 속도가 느림
- 중간 노드의 연결이 끊어지면 다음 노드를 찾기 어려움

```text
[Data | Link] → [Data | Link] → [Data | Link] → ...
```

> ⭐ `연결 리스트 = Node + Pointer / 삽입·삭제 쉬움 / 추가 포인터 공간 필요`

### 5. 스택(Stack)
- 리스트의 **한쪽 끝에서만 삽입과 삭제**가 이루어지는 자료 구조
- **후입선출(LIFO, Last In First Out)**
  - 가장 나중에 삽입된 자료가 가장 먼저 삭제

#### 주요 연산
- **PUSH** - 자료 삽입
- **POP** - 자료 삭제

#### 주요 용도
- 함수 호출의 순서 제어
- 인터럽트 처리
- 수식 계산 및 수식 표기법
- 컴파일러의 괄호 검사
- 운영체제 작업 스케줄링

#### TOP
- 스택에서 **가장 마지막으로 삽입된 자료의 위치**를 가리키는 포인터
- 스택의 가장 밑바닥 → **Bottom**

#### Overflow / Underflow
- **Overflow** - 스택이 가득 차 더 이상 자료를 삽입할 수 없는 상태
- **Underflow** - 스택이 비어 있어 더 이상 자료를 삭제할 수 없는 상태

> ⭐ `Stack = LIFO`  
> ⭐ `PUSH = 삽입 / POP = 삭제`  
> ⭐ `가득 참 = Overflow / 비어 있음 = Underflow`

### 6. 큐(Queue)
- 리스트의 한쪽에서는 **삽입**, 다른 한쪽에서는 **삭제**가 이루어지는 자료 구조
- **선입선출(FIFO, First In First Out)**
  - 가장 먼저 삽입된 자료가 가장 먼저 삭제
- 시작과 끝을 표시하는 두 개의 포인터를 사용

#### 포인터
- **Front(F)** - 가장 먼저 삽입된 자료의 위치를 가리킴 / 삭제 작업에 사용
- **Rear(R)** - 가장 마지막에 삽입된 자료의 위치를 가리킴 / 삽입 작업에 사용

#### 용도
- 운영체제의 **작업 스케줄링**

> ⭐ `Queue = FIFO`  
> ⭐ `Front = 삭제 / Rear = 삽입`

### 7. 데크(Deque)
- **삽입과 삭제가 양쪽 끝에서 모두 가능한 자료 구조**
- **Double Ended Queue**
- Stack과 Queue의 장점만 따서 구성

#### 종류
- **입력 제한 데크(Scroll)** - 입력은 한쪽에서만, 출력은 양쪽에서 가능
- **출력 제한 데크(Shelf)** - 입력은 양쪽에서 가능, 출력은 한쪽에서만 가능

> ⭐ `Deque = 양쪽 삽입·삭제 가능`  
> ⭐ `Scroll = 입력 제한 / Shelf = 출력 제한`

### 8. 그래프(Graph)
- **정점(Vertex)과 간선(Edge)**의 집합으로 이루어진 자료 구조
- 간선의 방향 유무에 따라
  - **방향 그래프(Directed Graph)**
  - **무방향 그래프(Undirected Graph)**

  로 구분
- 통신망(Network), 교통망, 이항관계, 연립방정식 등에 활용
- **트리는 사이클이 없는 그래프**

#### 최대 간선 수
- 정점이 `n`개일 때

| 그래프 | 최대 간선 수 |
|---|---|
| **무방향 그래프** | `n(n-1) / 2` |
| **방향 그래프** | `n(n-1)` |

> ⭐ `무방향 = n(n-1)/2`  
> ⭐ `방향 = n(n-1)`

### 9. 인접 행렬(Adjacency Matrix)
- 그래프에서 정점 간의 연결 관계를 **행렬(Matrix)**로 표현
- 방향 그래프에서 `Vi → Vj` 간선이 있으면 `Pij = 1`, 없으면 `0`
- 무방향 그래프에서는 두 정점이 인접하면 `1`, 아니면 `0`

> ⭐ `인접 = 1 / 비인접 = 0`

## SECTION 029. 트리(Tree)

### 1. 트리의 개요
- **트리(Tree)** - 노드(Node)와 가지(Branch)를 이용하여 사이클을 이루지 않도록 구성한 **그래프의 특수한 형태**
- 트리에는 하나의 **루트 노드(Root Node)**가 존재
- 트리의 노드는 **계층 구조**를 가짐
- 가족의 계보, 조직도 등을 표현하는 데 적합

### 2. 트리의 주요 용어

| 용어 | 의미 |
|---|---|
| **노드(Node)** | 트리의 기본 요소 / 자료 항목과 가지 정보를 가진 요소 |
| **루트 노드(Root Node)** | 트리의 맨 위에 있는 노드 |
| **차수(Degree)** | 각 노드에서 뻗어 나온 가지의 수 |
| **단말 노드(Terminal Node)** | 자식이 하나도 없는 노드 |
| **잎 노드(Leaf Node)** | 단말 노드와 같은 의미 |
| **자식 노드(Son Node)** | 어떤 노드에 연결된 다음 레벨의 노드 |
| **부모 노드(Parent Node)** | 어떤 노드에 연결된 이전 레벨의 노드 |
| **형제 노드(Brother Node, Sibling)** | 동일한 부모를 갖는 노드 |
| **레벨(Level)** | 루트부터 특정 깊이에 해당하는 계층 |
| **깊이(Depth)** | 트리에서 노드가 존재하는 최대 레벨 |
| **트리의 차수** | 노드들의 차수 중 **가장 큰 값** |

> ⭐ `트리 차수 = 각 노드 차수 중 최댓값`

### 3. 트리 운행법(Traversal)
- 트리의 각 노드를 찾아가는 방법
- 이진 트리의 운행법은 세 가지

| 운행법 | 순서 | 암기 |
|---|---|---|
| **Preorder(전위)** | `Root → Left → Right` | **루왼오** |
| **Inorder(중위)** | `Left → Root → Right` | **왼루오** |
| **Postorder(후위)** | `Left → Right → Root` | **왼오루** |

> ⭐ `Pre = Root 먼저`  
> ⭐ `In = Root 가운데`  
> ⭐ `Post = Root 마지막`

### 4. 수식의 표기법
- 산술식을 계산하기 위해 이진 트리를 많이 사용
- 이진 트리로 만들어진 수식을 운행법에 따라 **Prefix / Infix / Postfix**로 표현

| 표기법 | 트리 운행 | 기본 형태 |
|---|---|---|
| **전위 표기법(Prefix)** | Preorder | `연산자 → Left → Right` |
| **중위 표기법(Infix)** | Inorder | `Left → 연산자 → Right` |
| **후위 표기법(Postfix)** | Postorder | `Left → Right → 연산자` |

예)
```text
A + B

Prefix  : +AB
Infix   : A+B
Postfix : AB+
```

> ⭐ `Prefix = 연산자 앞`  
> ⭐ `Infix = 연산자 중간`  
> ⭐ `Postfix = 연산자 뒤`

### 5. Infix → Prefix / Postfix 변환 핵심
- 연산자 우선순위에 따라 괄호를 묶음
- **Prefix**
  - 연산자를 해당 괄호의 **앞쪽**으로 이동
  - 불필요한 괄호 제거
- **Postfix**
  - 연산자를 해당 괄호의 **뒤쪽**으로 이동
  - 불필요한 괄호 제거

### 6. Prefix / Postfix → Infix 변환 핵심
- **Postfix → Infix**
  - 먼저 만나는 연산자의 앞쪽 두 피연산자를 하나의 괄호식으로 묶어 반복
- **Prefix → Infix**
  - 연산자를 기준으로 오른쪽 피연산자들을 묶어 중위식 형태로 변환

> ⭐ 수식 변환 문제에서는 **연산자의 위치와 우선순위**를 먼저 확인

## SECTION 030. 정렬(Sort)

### 1. 삽입 정렬(Insertion Sort)
- 이미 순서화된 파일에 새로운 하나의 레코드를 **적절한 위치에 삽입**하여 정렬
- 두 번째 키부터 앞의 키들과 비교하여 알맞은 위치에 삽입
- 평균·최악 시간 복잡도 → **`O(n²)`**

> ⭐ `삽입 정렬 = 앞쪽 정렬 완료 영역에 끼워 넣기`

### 2. 셸 정렬(Shell Sort)
- **삽입 정렬을 확장**한 방식
- 입력 파일을 일정한 **간격(h)**으로 나눈 서브파일로 구성하여 삽입 정렬 수행
- 간격을 점차 줄여가며 반복
- 입력 파일이 부분적으로 정렬되어 있을 때 유리
- 평균 시간 복잡도 → **`O(n^1.5)`**
- 최악 시간 복잡도 → **`O(n²)`**

> ⭐ `Shell = Insertion 확장 + 간격(h)`

### 3. 선택 정렬(Selection Sort)
- `n`개의 레코드 중 **최솟값을 찾아 첫 번째 위치**에 놓고,
  나머지 중 다시 최솟값을 찾아 다음 위치에 놓는 과정을 반복
- 평균·최악 시간 복잡도 → **`O(n²)`**

> ⭐ `선택 정렬 = 매 회 최솟값 선택`

### 4. 버블 정렬(Bubble Sort)
- 인접한 두 레코드의 키 값을 비교하여 크기에 따라 위치를 서로 교환
- 계속 비교·교환하면서 정렬
- 평균·최악 시간 복잡도 → **`O(n²)`**

> ⭐ `Bubble = 이웃끼리 비교·교환`

### 5. 퀵 정렬(Quick Sort)
- 많은 레코드의 이동 없이 파일을 부분적으로 나누어 정렬
- **분할과 정복(Divide and Conquer)** 방식
- 기준값 → **Pivot**
- 정렬 과정에서 **Stack** 필요

#### 과정
1. **분할(Divide)** - Pivot을 중심으로 두 부분집합으로 분리
2. **정복(Conquer)** - Pivot보다 작은 값은 왼쪽, 큰 값은 오른쪽으로 정렬
3. 부분집합에 대해 재귀적으로 반복

- 평균 시간 복잡도 → **`O(n log n)`**
- 최악 시간 복잡도 → **`O(n²)`**

> ⭐ `Quick = Pivot + Divide & Conquer`  
> ⭐ `평균 O(n log n) / 최악 O(n²)`

### 6. 힙 정렬(Heap Sort)
- 완전 이진 트리(**Complete Binary Tree**)를 이용한 정렬
- 완전 이진 트리를 **Heap Tree**로 변환하여 정렬
- 평균·최악 시간 복잡도 → **`O(n log n)`**

> ⭐ `Heap = Complete Binary Tree`  
> ⭐ `평균·최악 모두 O(n log n)`

### 7. 2-Way 합병 정렬(Merge Sort)
- 이미 정렬되어 있는 두 개의 파일을 **하나의 정렬된 파일로 합병**하는 방식
- 두 파일의 첫 번째 데이터부터 비교해 작은 값을 순서대로 새 파일에 저장
- 한 파일이 끝나면 남은 파일의 데이터를 차례로 저장
- 평균·최악 시간 복잡도 → **`O(n log n)`**

> ⭐ `Merge = 정렬된 두 파일을 합침`  
> ⭐ `평균·최악 모두 O(n log n)`

### 8. 기수 정렬(Radix Sort, Bucket Sort)
- **Queue를 이용**
- 자릿수(Digit)별로 데이터를 분류하여 정렬
- 같은 수 또는 같은 문자가 들어갈 수 있는 **Bucket**을 만들어 분배한 뒤 다시 순서대로 모음
- 평균·최악 시간 복잡도 → **`O(dn)`**

> ⭐ `Radix = Bucket + Queue + 자릿수별 정렬`

### 9. 정렬 알고리즘 비교

| 정렬 | 핵심 | 평균 | 최악 |
|---|---|---:|---:|
| **Insertion** | 앞쪽에 삽입 | `O(n²)` | `O(n²)` |
| **Shell** | 삽입 정렬 확장 / 간격 | `O(n^1.5)` | `O(n²)` |
| **Selection** | 최솟값 선택 | `O(n²)` | `O(n²)` |
| **Bubble** | 인접 교환 | `O(n²)` | `O(n²)` |
| **Quick** | Pivot / 분할정복 | `O(n log n)` | `O(n²)` |
| **Heap** | 완전 이진 트리 | `O(n log n)` | `O(n log n)` |
| **Merge** | 두 파일 합병 | `O(n log n)` | `O(n log n)` |
| **Radix** | 자릿수 / Bucket | `O(dn)` | `O(dn)` |

> ⭐ `빠른 평균 = Quick / Heap / Merge → O(n log n)`  
> ⭐ `최악까지 O(n log n) = Heap / Merge`

## SECTION 031. 검색 - 이분 검색 / 해싱

### 1. 이분 검색(Binary Search)
- 전체 파일을 두 개의 서브파일로 계속 나누면서 **Key 레코드를 검색**하는 방법
- 반드시 파일이 **순서대로 정렬**되어 있어야 함
- 찾을 Key와 중간 레코드의 Key를 비교하며 검색
- 한 번 비교할 때마다 검색 대상 데이터 수가 절반으로 감소하여 탐색 효율이 높음

#### 중간 레코드 번호
```text
M = (F + L) / 2
```

- `F` - 첫 번째 레코드 번호
- `L` - 마지막 레코드 번호

#### 검색 방향
- `Key < 중간값` → 앞쪽 절반 검색
- `Key > 중간값` → 뒤쪽 절반 검색
- `Key = 중간값` → 검색 성공

> ⭐ `Binary Search = 정렬 필수 + 절반씩 검색`

### 2. 해싱(Hashing)
- **해시 테이블(Hash Table)**이라는 기억공간을 할당하고
- **해시 함수(Hash Function)**를 이용하여 레코드의 키를 주소로 변환
- 계산된 주소에 레코드를 저장하고 검색하는 방식
- **직접 접근 방식**

> ⭐ `Hashing = Key → Hash Function → Address`

### 3. 해시 테이블 관련 용어

| 용어 | 의미 |
|---|---|
| **Bucket(버킷)** | 하나의 주소가 가리키는 파일의 한 구역 |
| **Slot(슬롯)** | 한 개의 레코드를 저장할 수 있는 공간 |
| **Collision(충돌)** | 서로 다른 두 개 이상의 레코드가 **같은 주소**를 갖는 현상 |
| **Synonym** | 충돌로 인해 같은 Home Address를 갖는 레코드 |
| **Overflow** | 계산된 Home Address의 Bucket에 레코드를 저장할 공간이 없는 상태 |

> ⭐ `Collision = 서로 다른 Key가 같은 주소`  
> ⭐ `Overflow = 해당 Bucket에 빈 Slot 없음`

### 4. 해싱 함수(Hashing Function)

| 종류 | 핵심 |
|---|---|
| **제산법(Division)** | 키 값을 해시 테이블 크기보다 큰 수 중 가장 작은 소수로 나눈 **나머지 + 1** |
| **제곱법(Mid-Square)** | 레코드 키 값을 제곱한 후 **중간 부분**을 주소로 사용 |
| **폴딩법(Folding)** | 키를 여러 부분으로 나눈 뒤 각 부분을 더하거나 XOR하여 주소 계산 |
| **기수 변환법(Radix)** | 키의 진수를 다른 진수로 변환 후 주소 크기를 넘는 높은 자릿수 절단 |
| **대수적 코딩법(Algebraic Coding)** | 키 값을 다항식 계수로 보고 다항식을 정의한 뒤 값을 계산해 주소 사용 |
| **숫자 분석법(Digit Analysis)** | 키 값의 자릿수 분포를 분석하여 비교적 고른 자릿수를 선택 |
| **무작위법(Random)** | 난수(Random Number)를 발생시켜 주소로 사용 |

> ⭐ 해싱 함수 → `제산 / 제곱 / 폴딩 / 기수 / 대수 / 숫자 / 무작위`

### 5. Collision 해결 방법

| 방법 | 핵심 |
|---|---|
| **체이닝(Chaining)** | 충돌한 레코드를 **연결 리스트**로 연결 |
| **개방 주소법(Open Addressing)** | 충돌 시 순차적으로 다음 빈 주소를 찾아 저장 |
| **재해싱(Rehashing)** | 충돌 시 **다른 해시 함수**를 사용하여 새 주소 계산 |

> ⭐ `Chaining = Linked List`  
> ⭐ `Open Addressing = 빈 자리 탐색`  
> ⭐ `Rehashing = 다른 Hash Function`

## SECTION 032. 데이터베이스 개요

### 1. 데이터 저장소
- 소프트웨어 개발 과정에서 다루어야 할 데이터를 **논리적·물리적으로 구조화한 것**
- **논리 데이터 저장소**와 **물리 데이터 저장소**로 구분

#### 논리 데이터 저장소
- 데이터 및 데이터 간 관계를 **논리적으로 구조화**한 저장소

#### 물리 데이터 저장소
- 논리 데이터 저장소를 소프트웨어가 운용되는 환경의 물리적 특성을 고려하여 **하드웨어 저장장치에 저장**한 것

- 논리 데이터 저장소를 거쳐 물리 데이터 저장소를 구축하는 과정을 **데이터베이스 구축**이라고 함

> ⭐ `논리 = 관계를 논리적으로 구조화`  
> ⭐ `물리 = 실제 저장장치에 저장`

### 2. 데이터베이스(Database)
- 특정 조직의 업무 수행에 필요한 상호 관련된 데이터들의 모임

#### 데이터베이스의 정의

| 정의 | 핵심 |
|---|---|
| **통합된 데이터(Integrated Data)** | 자료의 중복을 최소화한 데이터의 모임 |
| **저장된 데이터(Stored Data)** | 컴퓨터가 접근할 수 있는 저장 매체에 저장된 자료 |
| **운영 데이터(Operational Data)** | 조직 고유 업무 수행에 반드시 필요한 자료 |
| **공용 데이터(Shared Data)** | 여러 응용 시스템이 공동으로 소유·유지하는 자료 |

> ⭐ `통·저·운·공`  
> ⭐ `통합 / 저장 / 운영 / 공용`

### 3. DBMS(Database Management System)
- 사용자와 데이터베이스 사이에서 사용자의 요구에 따라 정보를 생성하고 데이터베이스를 관리하는 **소프트웨어**
- 기존 파일 시스템의 **데이터 종속성과 중복성 문제**를 해결하기 위해 제안
- 모든 응용 프로그램이 데이터베이스를 공용할 수 있도록 관리
- 데이터베이스의 구축·접근·유지관리에 대한 모든 책임을 가짐

### 4. DBMS의 필수 기능

| 기능 | 핵심 |
|---|---|
| **정의(Definition)** | 데이터 형(Type), 구조, 이용 방식, 제약 조건 등을 명시 |
| **조작(Manipulation)** | 데이터 검색·갱신·삽입·삭제 등을 위한 인터페이스 제공 |
| **제어(Control)** | 데이터 정확성·무결성 유지 / 보안·권한 / 병행 제어 |

#### 제어 기능
- 데이터베이스 접근 시 갱신·삽입·삭제가 정확하게 수행되어 **무결성 유지**
- 권한이 있는 사용자만 접근할 수 있도록 **Security / Authority** 관리
- 여러 사용자가 동시에 접근할 때 결과의 정확성을 유지하도록 **Concurrency Control** 수행

> ⭐ `DBMS 필수 기능 = 정·조·제`  
> ⭐ `정의 / 조작 / 제어`

### 5. DBMS의 장·단점

#### 장점
- 데이터의 **논리적·물리적 독립성** 보장
- 데이터 중복을 줄여 기억 공간 절약
- 저장된 자료 공동 이용 가능
- 데이터 일관성 유지
- 데이터 무결성 유지
- 보안 유지
- 데이터 표준화 가능
- 통합 관리 가능
- 항상 최신 데이터 유지
- 데이터의 실시간 처리 가능

#### 단점
- 데이터베이스 전문가 필요
- 전산화 비용 증가
- 대용량 Disk 집중 Access로 과부하 발생 가능
- 파일의 예비(Backup)와 회복(Recovery)이 어려움
- 시스템 복잡

> ⭐ `장점 핵심 = 독립성 / 중복 감소 / 일관성·무결성 / 보안 / 공유`  
> ⭐ `단점 핵심 = 비용 / 전문가 / 복잡 / Backup·Recovery`

### 6. 데이터 독립성
- DBMS의 중요한 특성
- 데이터 구조가 변경되더라도 **응용 프로그램이 영향을 받지 않도록** 하는 성질

#### 논리적 독립성
- 데이터베이스의 **논리적 구조 변경**이 응용 프로그램에 영향을 주지 않음

#### 물리적 독립성
- 저장장치·저장 방식 등 **물리적 구조 변경**이 응용 프로그램에 영향을 주지 않음

> ⭐ `논리 구조 변경에도 프로그램 독립 = 논리적 독립성`  
> ⭐ `물리 저장 방식 변경에도 프로그램 독립 = 물리적 독립성`

### 7. 스키마(Schema)
- 데이터베이스의 **구조와 제약 조건에 관한 전반적인 명세**
- 개체(Entity), 속성(Attribute), 관계(Relationship), 데이터 조작 시 제약 조건 등을 정의
- 사용자의 관점에 따라
  - **외부 스키마**
  - **개념 스키마**
  - **내부 스키마**

  로 구분

| 스키마 | 핵심 |
|---|---|
| **외부 스키마** | 사용자나 응용 프로그램 관점에서 필요한 DB의 논리적 구조 / **서브 스키마** |
| **개념 스키마** | DB 전체의 논리적 구조 / 모든 응용 프로그램·사용자가 필요로 하는 데이터를 종합 / 하나만 존재 |
| **내부 스키마** | 물리적 저장장치 관점 / 실제 데이터의 저장 방법·레코드 형식·저장 순서 등을 표현 |

> ⭐ `외부 = 사용자 View`  
> ⭐ `개념 = 전체 논리 구조`  
> ⭐ `내부 = 실제 물리 저장`

## SECTION 033. 절차형 SQL

### 1. 절차형 SQL의 개요
- **절차형 SQL** - C, Java 등의 프로그래밍 언어처럼 **연속적인 실행이나 분기·반복 등의 제어가 가능한 SQL**
- 일반 SQL보다 효율은 떨어질 수 있지만 단순 SQL만으로 처리하기 어려운 **연속 작업**에 적합
- 절차형 SQL을 사용하면 다양한 기능을 수행하는 **저장 모듈**을 생성 가능
- DBMS 엔진에서 직접 실행되므로 **입·출력 패킷이 적어 효율적**
- `BEGIN ~ END` 형식의 **Block 구조**로 구성되어 기능별 모듈화 가능

### 2. 절차형 SQL의 종류

| 종류 | 핵심 |
|---|---|
| **프로시저(Procedure)** | 특정 기능을 수행하는 일련의 트랜잭션 언어 / 호출을 통해 실행 / 미리 저장 |
| **트리거(Trigger)** | 데이터 삽입·갱신·삭제 등의 **이벤트 발생 시 자동 수행** |
| **사용자 정의 함수** | 프로시저와 유사하지만 종료 시 **RETURN**으로 하나의 값을 반환 |

> ⭐ `프로시저 = 호출`  
> ⭐ `트리거 = 이벤트 시 자동`  
> ⭐ `함수 = RETURN`

### 3. 절차형 SQL 테스트 및 디버깅
- **테스트** - 오류 존재 여부를 검증하고 실행을 통해 결과를 확인하는 과정
- **디버깅(Debugging)** - 오류를 찾아 수정하는 작업

#### 테스트 과정
- 소스를 직접 실행하여
  - **구문 오류(Syntax Error)**
  - 참조 오류

  존재 여부 확인
- 오류 및 경고 메시지가 출력되면 소스 내용을 확인하고 수정
- 정상 생성된 절차형 SQL은 테스트를 통해 **로직 검증**
- 결과를 확인하여 최종적으로 확인

#### 디버깅 목적
- 실제 데이터베이스에 영향을 줄 수 있는
  - 삽입
  - 변경

  관련 SQL을 주석 처리한 뒤 출력문을 사용하여 확인 가능

> ⭐ `테스트 = 오류 여부 확인`  
> ⭐ `디버깅 = 오류 원인 찾고 수정`

### 4. 쿼리 성능 최적화
- 데이터 입·출력 애플리케이션의 성능 향상을 위해 SQL 코드를 최적화
- 최적화 전에 **APM(Application Performance Management)** 등의 성능 측정 도구를 활용하여 최적화 대상 쿼리를 선정
- 최적화할 쿼리에 대해 **옵티마이저(Optimizer)**가 수립한 실행 계획을 검토
- SQL 코드와 인덱스를 재구성하여 성능 개선

> ⭐ `성능 측정 → 대상 쿼리 선정 → 실행 계획 검토 → SQL·Index 재구성`
