# 05. 인터페이스 구현

## SECTION 054. 모듈 간 공통 기능 및 데이터 인터페이스 확인

### 1. 모듈 간 공통 기능 및 데이터 인터페이스의 개요
- **공통 기능** - 모듈의 기능 중에서 **공통적으로 제공되는 기능**
- **데이터 인터페이스** - 모듈 간 교환되는 데이터가 저장될 **파라미터(Parameter)**
- 모듈 간 공통 기능 및 데이터 인터페이스는 **인터페이스 설계서에 정의된 모듈의 기능을 기반으로 확인**
- 확인된 공통 기능 및 데이터 인터페이스는 모듈 간 연계가 필요한 인터페이스의 **기능을 식별하는 데 사용**

#### 확인 순서
```text
인터페이스 설계서별 모듈 기능 확인
→ 외부·내부 모듈의 공통 기능 확인
→ 필요한 데이터 인터페이스 확인
```

> ⭐ `공통 기능 = 여러 모듈에서 함께 사용하는 기능`  
> ⭐ `데이터 인터페이스 = 모듈 간 전달 데이터의 Parameter`

---

### 2. 인터페이스 설계서
- 시스템 사이의 **데이터 교환 및 처리**를 위해
  - 교환 데이터
  - 관련 업무
  - 송신 시스템
  - 수신 시스템

  등에 대한 내용을 정의한 문서
- 인터페이스 설계서는 크게
  - **일반적인 인터페이스 설계서**
  - **정적·동적 모형을 통한 인터페이스 설계서**

  로 구분

---

### 3. 일반적인 인터페이스 설계서

#### 시스템 인터페이스 설계서
- 시스템 인터페이스 목록을 작성
- 각 인터페이스 목록에 대한 **상세 데이터 명세**를 정의

#### 상세 기능별 인터페이스 명세서
- 각 기능의 **세부 인터페이스 정보** 정의
- 주요 내용
  - 기능 개요
  - 기능 수행 전 필요한 **사전 조건**
  - 기능 수행 후 필요한 **사후 조건**
  - 인터페이스 데이터
  - 호출 후 결과를 확인하기 위한 **반환값**

> ⭐ `상세 기능별 인터페이스 = 기능 개요 + 사전/사후 조건 + 데이터 + 반환값`

---

### 4. 정적·동적 모형을 통한 인터페이스 설계서
- 시스템을 구성하는 주요 구성 요소를 표현한 **다이어그램**을 이용하여 작성
- 시스템 구성 요소 간의 연관 관계를 바탕으로
  - 인터페이스가 시스템의 어느 부분에 속하는지
  - 인터페이스를 통해 상호 교환되는 데이터
  - 인터페이스 처리 방법

  등을 확인할 수 있음

> ⭐ `정적·동적 모형 = Diagram을 이용해 인터페이스 관계 확인`

---

### 5. 인터페이스 설계서별 모듈 기능 확인
- 인터페이스 설계서에 정의된 모듈을 기준으로 각 모듈의 기능을 확인

#### 시스템 인터페이스 목록
- **송신 및 전달 부분** → 외부 모듈
- **수신 부분** → 내부 모듈

#### 시스템 인터페이스 설계서
- 데이터 **송신 시스템** 부분 → 외부 모듈
- 데이터 **수신 시스템** 부분 → 내부 모듈

#### 상세 기능 인터페이스 명세서
- 오퍼레이션(Operation)과 **사전 조건** → 외부 모듈
- **사후 조건** → 내부 모듈

#### 정적·동적 모형
- 인터페이스 영역을 기준으로
  - 상위 모듈
  - 하위 모듈
  - 내부 모듈

  을 확인

> ⭐ `송신·사전 조건 = 외부 모듈`  
> ⭐ `수신·사후 조건 = 내부 모듈`

---

### 6. 모듈 간 공통 기능 및 데이터 인터페이스 확인
- 외부 모듈과 내부 모듈이 **공통으로 제공하는 기능**을 확인
- 확인된 공통 기능을 기반으로 필요한 **데이터 인터페이스 항목**을 확인

#### 예시
| 외부 모듈(인사) | 내부 모듈(회계) | 공통 기능 |
|---|---|---|
| 인사 발령 | 전표 발생 | **전표 발생** |
| 전표 발생 | 지출 결의서 확인 | - |
| 급여 계산 | 지출 처리 | - |
| 급여 결과 확인 | - | - |

- 공통 기능을 수행하는 과정에서 필요한
  - 급여 코드
  - 급여 일자
  - 급여 계산 결과
  - 계정 정보

  등의 데이터를 인터페이스 항목으로 정의

> ⭐ `공통 기능 확인 → 필요한 인터페이스 데이터 항목 추출`

---

## SECTION 055. 모듈 연계를 위한 인터페이스 기능 식별

### 1. 모듈 연계의 개요
- **모듈 연계** - 내부 모듈과 외부 모듈 또는 내부 모듈 간 **데이터 교환을 위해 관계를 설정하는 것**
- 대표적인 모듈 연계 방식
  - **EAI**
  - **ESB**

---

### 2. EAI(Enterprise Application Integration)
- 기업 내 각종 애플리케이션 및 플랫폼 간의
  - 정보 전달
  - 연계
  - 통합

  등 상호 연동을 가능하게 해주는 **솔루션**
- 각 시스템의 효율성과 **결정성(Determinacy)**을 높여 줌

> ⭐ `EAI = 기업 내 Application 간 연계·통합`

### 3. EAI 구축 유형

| 유형 | 핵심 |
|---|---|
| **Point-to-Point** | 가장 기본적인 방식 / 애플리케이션을 **1:1로 직접 연결** / 변경·재사용 어려움 |
| **Hub & Spoke** | 단일 접점인 **허브 시스템**을 통해 데이터 전달 / 중앙 집중형 / 확장·유지보수 쉬움 / Hub 장애 시 전체 영향 |
| **Message Bus** | 애플리케이션 사이에 **미들웨어(Bus)**를 두어 처리 / 확장성 높고 대용량 처리 가능 |
| **Hybrid** | **Hub & Spoke + Message Bus** 혼합 / 그룹 내부와 그룹 간 방식 혼합 / 데이터 병목 최소화 |

#### Point-to-Point
- 애플리케이션 간 직접 연결
- 구축이 단순하지만 연결이 많아질수록 관리가 어려움

#### Hub & Spoke
- 모든 연결이 중앙의 **Hub**를 거침
- 중앙 집중형으로 유지보수·확장이 용이
- Hub 장애 시 전체 시스템에 영향을 줄 수 있음

#### Message Bus
- 애플리케이션 사이에 **미들웨어를 두어 처리**
- 확장성이 높음
- 대용량 처리 가능

#### Hybrid
- 그룹 내에서는 **Hub & Spoke**
- 그룹 간에는 **Message Bus**
- 필요에 따라 한 가지 방식으로 구성 가능
- 데이터 병목 현상을 최소화할 수 있음

> ⭐ EAI 유형 → `Point-to-Point / Hub & Spoke / Message Bus / Hybrid`  
> ⭐ `Hybrid = Hub & Spoke + Message Bus`

---

### 4. ESB(Enterprise Service Bus)
- 애플리케이션 간
  - 연계
  - 데이터 변환
  - 웹 서비스 지원

  등을 **표준 기반 인터페이스**로 제공
- EAI와 유사하지만 애플리케이션보다는 **서비스 중심의 통합**
- 특정 서비스에 국한되지 않고 범용적으로 사용하기 위해 애플리케이션과의 결합도(Coupling)를 **느슨하게(Loosely)** 유지
- 관리 및 보안 유지가 쉽고 **높은 수준의 품질 지원 가능**

> ⭐ `ESB = Service 중심 + 표준 기반 + Loose Coupling`

---

### 5. EAI와 ESB 비교

| 구분 | EAI | ESB |
|---|---|---|
| 중심 | 애플리케이션 통합 | **서비스 중심 통합** |
| 목적 | 기업 내 시스템 연계 | 표준 기반 서비스 연계 |
| 결합도 | 상대적으로 높을 수 있음 | **Loose Coupling** |
| 특징 | 다양한 구축 유형 | 관리·보안·확장성에 유리 |

---

### 6. 모듈 간 연계 기능 식별
- 앞에서 확인한 **공통 기능 및 데이터 인터페이스**를 기반으로 모듈과 연계할 기능을 **시나리오 형태로 구체화하여 식별**
- 식별된 연계 기능은 **인터페이스 기능을 식별하는 데 사용**

#### 연계 기능 시나리오의 구성
```text
사전 조건
→ 기능 동작
→ 사후 조건
```

예)
- 급여 계산
  - 사전 조건 → 급여 일자가 확정되어야 함
  - 기능 동작 → 사원별 급여 계산
  - 사후 조건 → 전표 발생을 위한 정보 생성

> ⭐ `연계 기능 = 공통 기능 + 데이터 인터페이스 → 시나리오화`

---

### 7. 모듈 간 인터페이스 기능 식별
- 식별된 모듈 간 관련 기능을 검토하여 **인터페이스 동작에 필요한 기능을 식별**
- 대부분의 인터페이스 동작은 외부 모듈의 결과 또는 요청에 의해 수행되므로
  - **외부 모듈의 기능**
  - 해당 기능을 실행하기 위한 **데이터 인터페이스 기능**

  을 식별
- 내부 모듈은 외부 모듈에서 호출된 인터페이스의 결과를 처리하고, 처리 결과를 외부 모듈에 다시 전달하는 기능을 식별
- 필요한 인터페이스 기능을 **최종적으로 선별**
- 선정된 인터페이스 기능은 인터페이스 기능 구현을 정의하는 데 사용

> ⭐ `외부 모듈 = 요청·결과 전달`  
> ⭐ `내부 모듈 = 처리 + 결과 반환`

---

## SECTION 056. 모듈 간 인터페이스 데이터 표준 확인

### 1. 인터페이스 데이터 표준의 개요
- **인터페이스 데이터 표준** - 모듈 간 인터페이스에서 사용하는 데이터의 형식을 **표준화**하는 것
- 기존 데이터에서 **공통 영역을 추출**하거나 한쪽 인터페이스의 데이터를 **변환하여 정의**
- 인터페이스 기능 구현을 정의할 때 사용

#### 데이터 표준 확인 순서
```text
데이터 인터페이스를 통해 인터페이스 데이터 표준 확인
→ 인터페이스 기능을 통해 인터페이스 표준 확인
→ 두 결과를 검토
→ 최종 인터페이스 데이터 표준 정의
```

> ⭐ `데이터 표준 = 공통 데이터 형식을 정해 모듈 간 데이터 표현을 통일`

---

### 2. 데이터 인터페이스 확인
- 데이터 표준을 위해 식별된 데이터 인터페이스에서
  - **입·출력값의 의미**
  - 데이터의 **특성**

  등을 구체적으로 확인
- 확인된 데이터 인터페이스의 각 항목을 통해 데이터 표준을 확인

#### 확인 항목 예시
| 구분 | 파라미터 | 데이터 표준 예 |
|---|---|---|
| 입력값 | 급여 코드 | 급여 지급 연월의 숫자 6자리 |
| 입력값 | 급여 계산 결과 | 항목·사번·소속·직급·지급액·공제액 등 |
| 출력값 | 전표 정보 | 발생 시기 `YYYYMMDD` 형식, 전표 구분 코드 등 |
| 출력값 | 차·대변 | 계정별 금액·계정 정보 등 |

> ⭐ `데이터 인터페이스 확인 = 입력·출력의 의미 + 특성 확인`

---

### 3. 인터페이스 기능 확인
- 데이터 표준을 위해 식별된 인터페이스 기능을 기반으로 **인터페이스 기능 구현에 필요한 데이터 항목 확인**
- 확인된 데이터 항목과 기존 데이터 표준에서 **수정·추가·삭제할 항목이 있는지 확인**

#### 예
| 인터페이스 기능 | 필요한 데이터 항목 |
|---|---|
| 외부 모듈로부터 전표 발생을 위한 급여 정보를 수신 | 전표 일자 / 계정 / 금액 / 발생 부서 / 지급 부서 / 거래처 등 |
| 회계 시스템에서 발생된 전표 정상 여부 확인 | 전표 발생 여부 / 차·대변 검증 여부 / 부서별 금액 / 계정별 금액 등 |

> ⭐ `기능 확인 → 실제 구현에 필요한 데이터 항목 추출`

---

### 4. 인터페이스 데이터 표준 확인
- 데이터 인터페이스에서 확인된 데이터 표준과 인터페이스 기능을 통해 확인된 데이터 항목을 **검토하여 최종 데이터 표준을 정의**
- 데이터 표준이 서로 다르거나 중복될 경우
  - 인터페이스 기능 기준으로 검토
  - 공통적으로 사용할 수 있도록 데이터 형태를 정리
- 최종 데이터 표준은 항목별로
  - 데이터 인터페이스에서 확인한 것인지
  - 인터페이스 기능에서 확인한 것인지

  **출처를 구분하여 기록**

> ⭐ `데이터 인터페이스 + 인터페이스 기능 → 검토·통합 → 최종 데이터 표준`

## SECTION 057. 인터페이스 구현

### 1. 인터페이스 구현
- **인터페이스 구현** - 송·수신 시스템 간의 **데이터 교환 및 처리를 실현하는 작업**
- 정의된 인터페이스 기능 구현을 기반으로 구현 범위와 방법을 고려하여 구현 방법을 분석
- 분석된 인터페이스 정의를 기반으로 인터페이스 구현
- 대표적인 구현 방법
  - **데이터 통신을 이용**
  - **인터페이스 엔티티(Entity)를 이용**

> ⭐ `인터페이스 구현 = 데이터 통신 방식 / 인터페이스 엔티티 방식`

---

### 2. 데이터 통신을 이용한 인터페이스 구현
- 애플리케이션 영역에서 **인터페이스 형식에 맞춘 데이터 포맷**을 인터페이스 대상으로 전송하고 이를 수신 측에서 **파싱(Parsing)**하여 해석하는 방식
- 주로
  - `JSON`
  - `XML`

  형식 사용

### 3. JSON을 이용한 인터페이스 구현 순서
```text
1. 인터페이스 객체를 생성할 데이터 선택
2. 선택 데이터를 JSON 형태의 인터페이스 객체로 생성
3. AJAX 등을 이용해 송신 측 → 수신 측 전송
4. 수신 측에서 객체 수신 후 Parsing·처리
5. 수신 측 → 송신 측으로 처리 결과 전송
```

> ⭐ `JSON 인터페이스 = 데이터 선택 → JSON 생성 → 전송 → Parsing → 결과 반환`

---

### 4. JSON / XML / AJAX

#### JSON(JavaScript Object Notation)
- 속성-값(Attribute-Value Pair) 형태의 데이터 객체 전달을 위한 개방형 표준 포맷
- 사람이 읽고 쓰기 쉬우며 기계도 분석·생성하기 쉬움
- JavaScript에서 파생되었지만 다양한 언어에서 사용

#### XML(eXtensible Markup Language)
- 특수한 목적을 갖는 **마크업 언어를 만들기 위한 다목적 마크업 언어**
- 데이터 표현·전송에 널리 사용

#### AJAX(Asynchronous JavaScript and XML)
- JavaScript를 이용해 클라이언트와 서버가 **비동기적으로 데이터를 교환**하는 기술
- 페이지 전체를 다시 불러오지 않고 필요한 데이터만 교환 가능

> ⭐ `JSON = Key-Value`  
> ⭐ `XML = Markup 기반 데이터 표현`  
> ⭐ `AJAX = 비동기 통신`

---

### 5. 인터페이스 엔티티를 이용한 인터페이스 구현
- 필요한 시스템 사이에 **별도의 인터페이스 엔티티를 두어 통신**
- 일반적으로 **인터페이스 테이블**을 엔티티로 활용
- 송신 측과 수신 측의 인터페이스 테이블을 각각 둘 수 있음
- 송·수신 인터페이스 테이블 구조는 대부분 같지만 상황에 따라 다르게 설계 가능

#### 인터페이스 테이블을 이용한 구현 순서
```text
1. 송신 데이터 발생
2. 송신 측 인터페이스 테이블에 데이터 기록(Write)
3. 정해진 주기에 따라 송신 데이터를 수신 측으로 전달
4. 수신 측 인터페이스 테이블에서 데이터 조회(Read)
5. 수신 데이터로 트랜잭션 수행
```

> ⭐ `Entity 방식 = Interface Table + Write/Read`

## SECTION 058. 인터페이스 보안

### 1. 인터페이스 보안의 개요
- 인터페이스는 시스템 모듈 간 통신 및 정보 교환을 위한 **통로**
- 충분한 보안 기능이 없으면 인터페이스의 취약점이 시스템 전체에 영향을 줄 수 있음
- 인터페이스 보안을 위해 구현 단계의 **보안 취약점을 분석하고 적절한 보안 기능을 적용**

> ⭐ `인터페이스 = 시스템 연결 통로 → 취약점이 전체 시스템으로 확산 가능`

---

### 2. 인터페이스 보안 취약점 분석
- 인터페이스가 수행되는 각 구간의 구현 현황을 확인하고 **보안 취약점이 있는지 분석**
- 각 구간의 송·수신 영역 구현 기술과 특징을 구체적으로 확인
- 확인된 인터페이스 기능을 기반으로
  - 송신 데이터 선택
  - 송신 객체 생성
  - 인터페이스 송·수신
  - 데이터 처리

  과정에서 발생할 수 있는 보안 취약점을 분석

---

### 3. 인터페이스 보안 기능 적용

| 영역 | 보안 기능 |
|---|---|
| **네트워크 영역** | Sniffing 등을 이용한 데이터 탈취·변조 방지를 위해 네트워크 트래픽 암호화 / `IPSec`, `SSL`, `S-HTTP` 등 |
| **애플리케이션 영역** | 소프트웨어 개발 보안 가이드를 참고하여 코드상의 보안 취약점 분석·보완 |
| **데이터베이스 영역** | 민감한 데이터의 암호화 / Procedure·Trigger·DB 암호화 기능 사용 / 필요 시 암·복호화 API 사용 |

> ⭐ 인터페이스 보안 → `네트워크 / 애플리케이션 / 데이터베이스`

### 4. IPSec / SSL / S-HTTP

#### IPSec(IP Security)
- 네트워크 계층에서
  - 데이터 변조 방지
  - 원본 인증

  등의 보안 기능 제공
- 암호화와 인증 기능 제공
- 주요 프로토콜
  - **AH(Authentication Header)**
  - **ESP(Encapsulating Security Payload)**
- 운영 모드
  - **Tunnel Mode**
  - **Transport Mode**

> ⭐ `IPSec = AH + ESP / Tunnel + Transport`

#### SSL(Secure Sockets Layer)
- TCP/IP 계층에서 서버와 클라이언트 사이의 통신을
  - 인증
  - 암호화
  - 무결성

  기능으로 보호

#### S-HTTP(Secure HyperText Transfer Protocol)
- 클라이언트와 서버 간에 전송되는 **모든 메시지를 암호화**

> ⭐ `IPSec / SSL / S-HTTP = 네트워크 구간 암호화`
