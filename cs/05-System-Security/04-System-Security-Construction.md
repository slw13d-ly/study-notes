# 04. 시스템 보안 구축

## SECTION 153. 서비스 공격 유형

### 1. 서비스 거부 공격(DoS; Denial of Service)
- **DoS 공격** - 표적이 되는 서버의 자원을 고갈시키거나 네트워크에 과도한 트래픽을 발생시켜 **정상적인 서비스를 제공하지 못하도록 하는 공격**
- 공격자가 직접 공격하거나, 다른 시스템을 공격에 이용하기도 함
- 대표 유형
  - Ping of Death
  - SMURFING
  - SYN Flooding
  - TearDrop
  - Land
  - DDoS

> ⭐ `DoS = 서버 자원·네트워크를 고갈시켜 서비스 불능`

### 2. Ping of Death(죽음의 핑)
- **ICMP 패킷을 정상 크기보다 크게 만들어 전송**하는 공격
- 인터넷 프로토콜의 패킷 크기 제한(65,536바이트)을 초과하는 데이터를 여러 IP 패킷으로 분할하여 전송
- 공격 대상은 분할된 패킷을 재조립하는 과정에서
  - 메모리 오류
  - 시스템 장애
  - 재부팅

  등이 발생할 수 있음
- 방어
  - 비정상적으로 큰 ICMP 패킷 차단
  - 패킷 크기 검사

> ⭐ `Ping of Death = 비정상적으로 큰 ICMP Packet`

### 3. SMURFING(스머핑)
- **ICMP의 특성을 악용하여 엄청난 양의 데이터를 피해 시스템에 집중적으로 전송**하는 공격
- 공격자는 송신 주소(Source IP)를 **공격 대상의 IP 주소로 위조**
- 위조한 ICMP Echo Request를 특정 네트워크의 **Broadcast 주소**로 전송
- 네트워크의 여러 호스트가 응답을 공격 대상에게 보내면서 트래픽이 폭증

#### 방어
- 라우터에서 다른 네트워크로부터 들어오는 **Directed Broadcast 패킷 차단**
- ICMP Echo Request 관련 필터링

> ⭐ `Smurf = Victim IP 위조 + Broadcast + ICMP 응답 폭주`

### 4. SYN Flooding
- TCP의 **3-Way Handshake**를 악용
- 공격자가 존재하지 않거나 사용할 수 없는 IP 주소로 **SYN 패킷을 대량 전송**
- 서버는 `SYN + ACK`를 전송한 후 클라이언트의 `ACK`를 기다리며 연결 자원을 점유
- ACK가 오지 않는 반쯤 열린 연결(**Half-Open Connection**)이 쌓이면서 서버 자원이 고갈

```text
정상
Client ─ SYN ─────→ Server
Client ← SYN+ACK ─ Server
Client ─ ACK ─────→ Server

공격
공격자 ─ SYN 대량 전송 → Server
                      ↓
               ACK를 기다리며 자원 점유
```

#### 방어
- SYN Flooding 탐지·차단 시스템
- SYN Cookie 등의 기법 활용

> ⭐ `SYN Flooding = 3-Way Handshake 악용 + Half-Open Connection`

### 5. TearDrop
- IP 패킷의 **Fragment Offset(분할 순서 정보)** 값을 조작하여 전송
- 수신 시스템이 분할된 패킷을 재조립할 때 오류를 일으켜 시스템을 다운시키는 공격

#### 방어
- Fragment Offset이 잘못된 패킷을 폐기

> ⭐ `TearDrop = Fragment Offset 조작 → 재조립 오류`

### 6. Land
- 패킷의 **송신 IP와 수신 IP를 공격 대상의 IP 주소와 동일하게 설정**
- 공격 대상이 자기 자신에게 응답을 반복하게 만들어 시스템을 마비

#### 방어
- 송신 IP와 수신 IP의 적절성 검사

> ⭐ `Land = Source IP = Destination IP = Victim IP`

### 7. DDoS(Distributed Denial of Service, 분산 서비스 거부)
- 여러 대의 공격 시스템을 이용하여 **동시에 하나의 대상 시스템을 공격**
- DoS보다 대규모 공격이 가능
- 공격자는 감염된 여러 PC를 원격에서 제어하여 공격 수행

#### 구성
```text
공격자
  ↓
Master / Handler
  ↓
Agent(좀비 PC) 다수
  ↓
공격 대상 서버
```

- 공격 범위를 확대하기 위해 여러 공격 시스템을 제어할 수 있는 **Handler(Master)**와 실제 공격을 수행하는 **Agent** 사용

> ⭐ `DDoS = 여러 Agent가 동시에 공격`  
> ⭐ `공격자 → Master/Handler → Agent → Victim`

### 8. 네트워크 침해 공격 관련 용어

| 용어 | 핵심 |
|---|---|
| **스미싱(Smishing)** | 문자메시지(SMS)의 링크를 이용해 악성 앱 설치·개인정보 탈취 |
| **스피어 피싱(Spear Phishing)** | 특정 개인·조직을 표적으로 신뢰할 만한 발신자인 것처럼 위장하는 피싱 |
| **APT(Advanced Persistent Threat)** | 특정 대상을 장기간 지속적으로 공격하여 내부 침투·정보 탈취 |
| **무차별 대입 공격(Brute Force Attack)** | 가능한 모든 값을 반복 입력하여 비밀번호 등을 알아냄 |
| **큐싱(Qshing)** | QR Code를 이용하여 악성 사이트·악성 앱으로 유도 |
| **피싱(Phishing)** | 금융기관 등으로 위장한 가짜 사이트·메일로 개인정보 탈취 |
| **Ping Flood** | ICMP Echo Request를 대량 전송하여 시스템 자원 고갈 |
| **Evil Twin Attack** | 정상 무선 AP와 유사한 가짜 AP를 만들어 사용자 정보 탈취 |
| **스위치 재밍(Switch Jamming)** | Switch의 MAC Address Table을 가짜 MAC 주소로 가득 채워 Dummy Hub처럼 동작하게 함 |

> ⭐ `Smishing = SMS` / `Qshing = QR` / `Phishing = 위장 사이트·메일`

### 9. 블루투스(Bluetooth) 관련 공격

| 용어 | 핵심 |
|---|---|
| **BlueBug** | 블루투스 장치 사이의 취약한 연결을 공격하여 휴대폰 원격 조종·정보 감청 |
| **BlueSnarf** | 블루투스 취약점을 이용해 장치의 OPP를 사용하여 연락처 등 정보에 접근 |
| **BluePrint** | 블루투스 장치의 종류·서비스 등을 식별 |
| **BlueJacking** | 블루투스를 이용해 스팸 메시지를 익명으로 전송 |

> ⭐ `BlueSnarf = 정보 탈취`  
> ⭐ `BlueJacking = Spam Message`

### 10. 기타 보안 침해 공격 관련 용어

| 용어 | 핵심 |
|---|---|
| **좀비(Zombie) PC** | 악성코드에 감염되어 공격자의 명령에 따라 원격 제어되는 PC |
| **C&C 서버(Command & Control)** | 해커가 감염된 좀비 PC에 명령을 내리고 제어하는 서버 |
| **봇넷(Botnet)** | 다수의 Zombie PC를 하나의 네트워크처럼 구성한 집합 |
| **웜(Worm)** | 네트워크를 통해 스스로 복제·전파되는 악성 프로그램 |
| **Zero Day Attack** | 보안 취약점의 패치가 나오기 전에 해당 취약점을 이용한 공격 |
| **Key Logger Attack** | 사용자의 키보드 입력을 몰래 기록하여 계정·비밀번호 등 탈취 |
| **Ransomware** | 파일을 암호화하거나 시스템을 잠근 뒤 금전을 요구 |
| **Back Door / Trap Door** | 정상 인증 절차를 거치지 않고 시스템에 접근할 수 있도록 숨겨 놓은 통로 |
| **Logic Bomb** | 특정 조건이 만족되면 악성 동작을 수행하도록 삽입된 코드 |
| **Pharming** | DNS 등을 조작하여 사용자를 가짜 사이트로 유도 |

> ⭐ `Zero Day = Patch 전에 공격`  
> ⭐ `Back Door = 숨겨진 접근 통로`  
> ⭐ `Logic Bomb = 조건 만족 시 실행`

## SECTION 154. 서버 인증

### 1. 보안 서버의 개념
- **보안 서버** - 인터넷을 통해 개인정보를 암호화하여 송·수신할 수 있는 기능을 갖춘 서버
- 개인정보 보호를 위해 보안 서버를 구축
- 대표 방식
  - **SSL(Secure Socket Layer) 인증서**
  - **암호화 응용 프로그램**

#### SSL 인증 방식
- 서버에 SSL 인증서를 설치하여 전송 정보를 암호화
- 별도 프로그램 설치 없이 웹 브라우저와 서버 사이의 통신을 보호

#### 암호화 응용 프로그램 방식
- 서버에 암호화 응용 프로그램을 설치하여 개인정보 암호화 후 송·수신

> ⭐ `보안 서버 = 개인정보 송·수신을 암호화`

### 2. 인증(Authentication)의 개념
- 시스템 또는 네트워크에 로그인을 요청한 사용자가 **합법적인 사용자인지 확인하는 과정**
- 인증된 사용자에게 요청한 자원의 접근 가능 여부를 결정하는 것 → **인가(Authorization)**

> ⭐ `Authentication = 누구인가?`  
> ⭐ `Authorization = 무엇을 사용할 수 있는가?`

### 3. 인증 수단
- **지식 기반 인증(Something You Know)**
- **소유 기반 인증(Something You Have)**
- **생체 기반 인증(Something You Are)**
- 추가
  - 행위 기반 인증(Something You Do)
  - 위치 기반 인증(Somewhere You Are)

> ⭐ 인증 유형 → `Know / Have / Are / Do / Where`

### 4. 지식 기반 인증(Something You Know)
- 사용자가 **기억하고 있는 정보**를 기반으로 인증

#### 고정된 패스워드(Fixed Password)
- 사용자가 입력한 패스워드를 시스템의 저장된 값과 비교
- 반복 사용되므로 노출 시 위험

#### 패스 프레이즈(Passphrase)
- 일반 패스워드보다 길고 기억하기 쉬운 **문장 형태의 비밀번호**

#### 아이핀(i-PIN)
- 인터넷상에서 주민등록번호 대신 사용하는 **사이버 신원 확인 번호**

> ⭐ `Something You Know = Password / Passphrase / i-PIN`

### 5. 소유 기반 인증(Something You Have)
- 사용자가 **소유하고 있는 것**을 기반으로 인증
- 소유 기기는 인증 소유물이 실제로 사용될 수 있으므로 분실·도난에 주의

#### 예
- 신분증
- 메모리 카드
- 스마트 카드
- OTP

#### 메모리 카드
- 카드 내부에 보안 코드를 저장하여 사용
- 카드 리더가 필요

#### 스마트 카드
- 마이크로프로세서와 메모리를 포함한 카드
- 정보를 저장·처리할 수 있음
- 신분 증명, 금융 서비스 등에 활용

#### OTP(One Time Password)
- 인증을 요청할 때마다 **새로운 일회용 비밀번호를 생성**
- 한 번 사용한 패스워드는 폐기

> ⭐ `Something You Have = Card / Token / OTP`

### 6. 생체 기반 인증(Something You Are)
- 사용자의 **고유한 생체 정보**를 이용
- 예
  - 지문
  - 홍채
  - 망막
  - 얼굴
  - 정맥 등

> ⭐ `Something You Are = 생체 정보`

### 7. 기타 인증 기법

| 인증 | 핵심 |
|---|---|
| **행위 기반(Something You Do)** | 사용자의 행동 패턴을 이용 / 예: 서명, 키보드 입력 습관 |
| **위치 기반(Somewhere You Are)** | 현재 사용자의 위치 정보를 이용 |

## SECTION 155. 보안 아키텍처 / 보안 프레임워크

### 1. 보안 아키텍처(Security Architecture)
- 정보 시스템의
  - **무결성(Integrity)**
  - **가용성(Availability)**
  - **기밀성(Confidentiality)**

  을 확보하기 위한 **보안 요소와 보안 체계를 식별하고 관계를 정의한 구조**
- 보안 아키텍처를 통해
  - 관리적 보안
  - 물리적 보안
  - 기술적 보안

  을 통합적으로 구성
- 시스템 요구사항 변화와 추가를 수용할 수 있어야 함
- 대표적인 보안 아키텍처 모델 표준 → **ITU-T X.805**

> ⭐ `보안 아키텍처 = 보안 요소·체계의 전체 구조`  
> ⭐ `기밀성 + 무결성 + 가용성`

### 2. 관리적 / 물리적 / 기술적 보안

| 구분 | 핵심 |
|---|---|
| **관리적 보안** | 정보보호 정책·지침·절차 수립 / 보안 교육 / 인적 보안 등 |
| **물리적 보안** | 건물·전산실·서버실 등의 출입 통제 / 시설 보호 |
| **기술적 보안** | 사용자 인증·접근 제어·PC·서버·네트워크·DB 등 기술적 보호 |

> ⭐ 보안 대책 → `관리적 / 물리적 / 기술적`

### 3. 보안 프레임워크(Security Framework)
- 안전한 정보 시스템 환경을 유지하고 **보안 수준을 향상시키기 위한 체계**
- 보안 활동과 절차를 표준화하여 일관된 보안 관리 가능
- 대표적인 국제 표준 → **ISO/IEC 27001**
- ISO 27001은 영국 BSI(British Standards Institute)의 **BS 7799**를 기반으로 구성
- 조직의 정보보안 관리 체계를 심사·인증하는 데 활용

> ⭐ `Security Framework = 보안 관리 절차의 표준 틀`  
> ⭐ `ISO 27001 ← BS 7799`

## SECTION 156. 로그 분석

### 1. 로그(Log)의 개념
- 시스템 사용과 관련된 **모든 내역을 기록해 놓은 것**
- 로그를 분석하면
  - 시스템 침입 흔적
  - 비정상 동작
  - 장애 발생 원인

  등을 확인할 수 있음
- 보안 사고 발생 시 중요한 분석 자료

> ⭐ `Log = 시스템에서 발생한 사건의 기록`

### 2. 리눅스(LINUX) 로그
- 리눅스의 대부분 로그 파일은 **`/var/log` 디렉터리**에 저장
- 로그 관련 설정은 주로 `syslog.conf` 등을 통해 관리

### 3. 리눅스의 주요 로그 파일

| 로그 | 파일 | 핵심 |
|---|---|---|
| **커널 로그** | `/dev/console` | 커널 관련 내용을 콘솔에 기록 |
| **커널/로그인 로그** | `/var/log/wtmp` | 성공한 로그인·로그아웃, 시스템 시작·종료 등의 기록 |
| **로그인 실패** | `/var/log/btmp` | 실패한 로그인 정보 기록 |
| **마지막 로그인** | `/var/log/lastlog` | 사용자별 마지막 로그인 기록 |
| **부팅 로그** | `/var/log/boot` | 시스템 부팅 과정 기록 |
| **Cron 로그** | `/var/log/cron` | `crond`의 정기 작업 관련 기록 |
| **시스템 로그** | `/var/log/messages` | 시스템 전반의 주요 메시지·정보 기록 |
| **보안 로그** | `/var/log/secure` | 사용자 인증·접근 관련 기록 |
| **FTP 로그** | `/var/log/xferlog` | FTP 사용자의 파일 전송 기록 |

> ⭐ `messages = 시스템 전반`  
> ⭐ `secure = 인증·보안`  
> ⭐ `xferlog = FTP`

### 4. 윈도우(Windows) 로그
- Windows는 **이벤트 로그(Event Log)** 형식으로 시스템 로그 관리
- **이벤트 뷰어(Event Viewer)**를 통해 확인
- 실행
  - Windows의 이벤트 뷰어 이용
  - 제어판의 관리 도구 등에서 이벤트 뷰어 실행

### 5. Windows 이벤트 로그

| 로그 | 핵심 |
|---|---|
| **응용 프로그램(Application)** | 응용 프로그램에서 발생하는 이벤트 기록 |
| **보안(Security)** | 로그인 시도, 파일·객체 접근 등 감사 관련 이벤트 기록 |
| **시스템(System)** | Windows 시스템 구성 요소에서 발생하는 이벤트 기록 |
| **Setup** | 프로그램 설치와 관련된 이벤트 기록 |
| **Forwarded Events** | 다른 컴퓨터에서 수집·전달된 이벤트 기록 |

> ⭐ `Windows Log = Application / Security / System / Setup / Forwarded Events`

## SECTION 157. 보안 솔루션

### 1. 보안 솔루션의 개념
- 컴퓨터 바이러스, 불법 접근, 정보 유출 등 **외부의 불법적인 침입을 막기 위한 시스템·소프트웨어**
- 주요 보안 솔루션
  - 방화벽(Firewall)
  - 침입 탐지 시스템(IDS)
  - 침입 방지 시스템(IPS)
  - 데이터 유출 방지(DLP)
  - 웹 방화벽
  - VPN
  - NAC
  - SSH 등

### 2. 방화벽(Firewall)
- 기업이나 조직의 **내부 네트워크와 인터넷 사이**에 설치
- 외부에서 내부로 들어오는 패킷을 검사하여 허용·차단
- 내부에서 외부로 나가는 정보도 통제 가능
- 해킹 등 외부 공격으로부터 내부 네트워크를 보호

> ⭐ `Firewall = 내부 ↔ 외부 경계에서 Packet 통제`

### 3. 침입 탐지 시스템(IDS; Intrusion Detection System)
- 컴퓨터 시스템의 **비정상적인 사용·오용·남용을 실시간으로 탐지**
- 침입을 발견하면 관리자에게 경고

#### 탐지 방식

##### 오용 탐지(Misuse Detection, Signature-Based)
- 이미 알려진 공격 패턴·Signature와 비교하여 침입 탐지
- 알려진 공격 탐지에 효과적
- 오탐률이 상대적으로 낮음
- 알려지지 않은 새로운 공격 탐지에는 한계

##### 이상 탐지(Anomaly Detection)
- 정상적인 시스템 사용 상태를 기준으로 비정상 행위를 탐지
- 알려지지 않은 새로운 공격 탐지 가능
- 오탐 가능성이 높을 수 있음

> ⭐ `Misuse = 알려진 Signature`  
> ⭐ `Anomaly = 정상 패턴에서 벗어난 행위`

#### IDS 유형

| 유형 | 핵심 |
|---|---|
| **HIDS(Host-Based IDS)** | 시스템 내부 로그·파일 등을 감시하여 해당 호스트의 침입 탐지 |
| **NIDS(Network-Based IDS)** | 네트워크 트래픽을 감시·분석하여 침입 탐지 |

#### 대표 IDS
- OSSEC
- md5deep
- AIDE
- Samhain
- Snort
- Zeek 등

### 4. IDS의 설치 위치
- **패킷이 라우터로 들어오기 전**
  - 네트워크에 시도되는 모든 공격 탐지 가능
- **라우터 뒤**
  - 라우터 필터링을 통과한 공격 탐지
- **방화벽 뒤**
  - 방화벽을 통과한 공격 탐지
- **내부 네트워크**
  - 내부 사용자에 의한 공격 탐지
- **DMZ**
  - 외부에 공개된 서버에 대한 공격 탐지

> ⭐ IDS는 **보호 목적에 따라 여러 위치에 설치 가능**

### 5. 침입 방지 시스템(IPS; Intrusion Prevention System)
- 방화벽과 침입 탐지 시스템의 장점을 결합한 개념
- 비정상적인 트래픽을 탐지한 후 **자동으로 차단**
- 패킷을 실시간 검사하여 악성 패킷 발견 시 차단·폐기

> ⭐ `IDS = 탐지·경고`  
> ⭐ `IPS = 탐지 + 차단`

### 6. 데이터 유출 방지(DLP; Data Leakage/Loss Prevention)
- 조직 내부의 중요 자료가 외부로 유출되는 것을 방지
- 사내 직원이 사용하는 PC·네트워크의 정보를 검색·분류하고
  - 메일
  - 메신저
  - 웹하드
  - 이동식 저장장치

  등을 통한 중요 정보 유출을 탐지·차단

> ⭐ `DLP = 내부 중요 정보의 외부 유출 방지`

### 7. 웹 방화벽(Web Firewall)
- 일반 방화벽이 탐지하기 어려운 **웹 기반 공격**을 탐지·차단
- 웹 서버 앞단에 설치
- 대표 공격 방어
  - SQL Injection
  - Cross-Site Scripting(XSS) 등
- 공격이 웹 서버에 도달하기 전에 차단

> ⭐ `Web Firewall = Web Attack(SQL Injection, XSS 등) 방어`

### 8. VPN(Virtual Private Network, 가상 사설 통신망)
- 인터넷 등 **공중망을 전용 회선처럼 안전하게 이용**할 수 있도록 하는 기술
- 암호화된 통신 구간을 만들어 데이터 보호
- 별도 전용 회선을 구축하는 것보다 비용 절감
- 멀리 떨어진 지사·영업소·출장자 등이 안전하게 내부 네트워크에 접속 가능

> ⭐ `VPN = Public Network 위에 암호화된 Private Tunnel`

### 9. NAC(Network Access Control)
- 네트워크에 접속하는 내부 PC의 **MAC 주소·IP 등을 등록하여 허용된 사용자만 접근**
- 내부 PC의 소프트웨어 사용 현황을 관리하여 불법 소프트웨어 설치 방지
- 일관성 없는 패치·바이러스 감염 등 보안상 문제가 있는 PC를 네트워크에서 격리 가능
- 네트워크에 접속한 비인가 시스템을 자동 검출·관리

> ⭐ `NAC = Network 접속 단말을 인증·통제`

### 10. SSH(Secure Shell)
- 다른 컴퓨터에
  - 로그인
  - 원격 명령 실행
  - 파일 복사

  등을 안전하게 수행할 수 있도록 하는 **암호화 원격 접속 프로토콜**
- 데이터 암호화와 강력한 인증을 사용
- 보안성이 낮은 원격 접속 방식의 대안
- 기본 포트 → **22번**

> ⭐ `SSH = Secure Remote Login / Port 22`
