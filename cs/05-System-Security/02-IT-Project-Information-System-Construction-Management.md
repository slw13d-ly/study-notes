# 02. IT 프로젝트 정보시스템 구축 관리

## SECTION 135. 네트워크 관련 신기술

### 1. 지능형 초연결망
- 스마트 시티, 스마트 스테이션 등 **4차 산업혁명 시대의 다양한 서비스를 수용하기 위한 네트워크**
- 국가 전체 망에 소프트웨어 정의 기술(SDE)을 적용하여
  - 네트워크
  - 데이터센터
  - 컴퓨팅
  - 스토리지

  등 정보 인프라를 효율적으로 사용할 수 있도록 함
- 기존의 초고속 정보통신망, 광대역 통합망 등을 기반으로 발전

> ⭐ `지능형 초연결망 = 국가 정보 인프라에 Software Defined 기술 적용`

### 2. 소프트웨어 정의 기술(SDx; Software-Defined Everything)
- 네트워크, 데이터센터 등에서 소유한 자원을 **가상화하여 개별 사용자에게 제공**
- 중앙에서 **통합적으로 제어**할 수 있도록 하는 기술

| 기술 | 핵심 |
|---|---|
| **SDN(Software Defined Networking)** | 네트워크를 컴퓨터처럼 모델링하여 여러 사용자가 각각의 SW로 네트워크를 가상화·제어 / **제어부와 데이터 전달부 분리** |
| **SDDC(Software Defined Data Center)** | 데이터센터의 모든 자원을 가상화하여 인력 개입 없이 **SW 조작만으로 관리·제어** |
| **SDS(Software Defined Storage)** | 물리적 데이터 스토리지를 가상화하여 여러 스토리지를 하나처럼 관리하거나 하나를 여러 스토리지처럼 사용 |

> ⭐ `SDN = Network`  
> ⭐ `SDDC = Data Center`  
> ⭐ `SDS = Storage`


### 3. IoT(Internet of Things, 사물 인터넷)
- 정보통신 기술을 기반으로 **실세계와 가상세계의 다양한 사물을 인터넷으로 연결**하여 진보된 서비스를 제공하기 위한 서비스 기반 기술
- 기존의 **M2M(Machine to Machine)** 개념을 인터넷으로 확장
- 사물과 사물뿐 아니라 **사람과 사물까지 연결**
- 주요 기술
  - 스마트 센싱
  - 유무선 통신 및 네트워크 인프라
  - IoT 서비스 인터페이스
  - 정보 보안
- 개방형 아키텍처가 필요하므로 정보 공유에 대한 **부작용·보안 문제**를 고려해야 함

> ⭐ `IoT = M2M을 인터넷으로 확장 → 사물·사람 모두 연결`


### 4. IoT 관련 용어

| 용어 | 핵심 |
|---|---|
| **AllJoyn** | 오픈 소스 기반의 사물인터넷 플랫폼 / 서로 다른 OS·하드웨어 간 통신·제어 |
| **Mesh Network** | 여러 노드를 그물망처럼 연결하여 다수 경로로 통신 / 대규모 디바이스 네트워크에 적합 |
| **Wi-SUN** | 스마트 그리드 등 장거리 무선 통신을 요구하는 IoT 서비스에 활용 |
| **UWB(Ultra WideBand)** | 매우 넓은 대역의 주파수를 이용하는 근거리 무선 기술 |
| **PICONET** | 여러 개의 독립된 통신장치가 블루투스 등을 이용해 네트워크 형성 |
| **USN(Ubiquitous Sensor Network)** | 센서 네트워크를 통해 사물·환경 정보를 수집하고 관리 |
| **Ubiquitous Computing** | 언제 어디서나 컴퓨터를 사용할 수 있는 환경 |
| **BLE(Bluetooth Low Energy)** | 일반 블루투스보다 저전력으로 동작하는 근거리 통신 |
| **NFC(Near Field Communication)** | 약 10cm 이내에서 사용하는 근거리 무선 통신 |
| **Zing** | 약 10cm 이내 거리에서 고속 데이터 전송이 가능한 초고속 근거리 무선 기술 |
| **NDN(Named Data Networking)** | 콘텐츠 자체의 이름을 기반으로 정보를 검색·전송하는 네트워크 |
| **Web Crawling** | 웹에서 자동화 프로그램을 이용하여 데이터를 수집하는 작업 |
| **All-IP** | 유무선 통신망을 하나의 IP 기반 망으로 통합 |
| **WBAN(Wireless Body Area Network)** | 웨어러블·인체 부착 장치를 무선으로 연결하는 개인 영역 네트워크 |
| **GIS(Geographic Information System)** | 지리 정보를 수집·저장·분석·출력하는 시스템 |
| **Ad-hoc Network** | 고정된 기반망 없이 이동 단말끼리 임시로 구성하는 네트워크 |
| **Network Slicing** | 하나의 물리적 네트워크를 여러 개의 독립적인 가상 네트워크로 분할 |
| **WDM(Wavelength Division Multiplexing)** | 서로 다른 파장의 광신호를 하나의 광섬유에 다중화 |
| **LOD(Linked Open Data)** | 누구나 사용할 수 있도록 웹상에 공개하고 서로 연결한 데이터 |
| **SSO(Single Sign On)** | 한 번의 로그인으로 여러 시스템을 이용 |
| **Smart Grid** | 전력망에 정보통신 기술을 적용하여 전력 공급자와 소비자가 실시간으로 정보를 교환 |
| **Metaverse** | 현실·가상을 결합한 3차원 가상 세계 |

> ⭐ IoT·네트워크 신기술은 **용어 ↔ 핵심 키워드**로 짝지어 암기


### 5. 클라우드 컴퓨팅(Cloud Computing)
- 각종 컴퓨팅 자원을 중앙 컴퓨터에 두고 **인터넷 기능을 갖는 단말로 언제 어디서나 이용**할 수 있도록 하는 기술
- 중앙 컴퓨터는
  - 데이터 저장
  - 응용 프로그램
  - 보안

  등 필요한 컴퓨팅 자원을 제공

#### 인터클라우드 컴퓨팅(Inter-Cloud Computing)
- 여러 클라우드 서비스 간에 자원을 공유하고 연동
- 대표 형태
  - **대등 접속(Peering)**
  - **연합(Federation)**
  - **중개(Intermediary)**

#### 클라우드 HSM(Cloud-based Hardware Security Module)
- 클라우드 환경에서 암호키를 안전하게 생성·처리·저장하기 위한 보안 기술

#### PaaS-TA
- 소프트웨어 개발 환경을 제공하기 위한 **개방형 클라우드 플랫폼**



### 6. 클라우드 서비스 유형

| 서비스 | 제공 범위 | 핵심 |
|---|---|---|
| **IaaS(Infrastructure as a Service)** | 서버·스토리지·네트워크 등 인프라 | **인프라 제공** |
| **PaaS(Platform as a Service)** | 개발 플랫폼·미들웨어·OS 등 | **개발 환경 제공** |
| **SaaS(Software as a Service)** | 사용자가 필요한 소프트웨어 | **SW를 서비스 형태로 제공** |

> ⭐ `IaaS = Infrastructure`  
> ⭐ `PaaS = Platform`  
> ⭐ `SaaS = Software`

## SECTION 136. 네트워크 구축

### 1. 네트워크 설치 구조
- 네트워크는 단말장치가 연결되는 **형태(Topology)**에 따라 분류
- 대표 구조
  - 성형
  - 링형
  - 버스형
  - 계층형
  - 망형



### 2. 성형(Star, 중앙 집중형)
- 중앙에 **중앙 컴퓨터 또는 허브**가 존재하고 단말장치가 중앙에 연결
- Point-to-Point 방식
- 중앙 장치를 통해 데이터 교환

#### 장점
- 단말 추가·제거가 쉬움
- 하나의 단말 장애가 다른 단말에 미치는 영향이 적음
- 유지보수·관리가 쉬움

#### 단점
- 중앙 장치가 고장 나면 전체 통신망에 영향
- 중앙 집중식이라 통신량이 많으면 병목 가능

> ⭐ `Star = 중앙 장치 중심`



### 3. 링형(Ring, 루프형)
- 컴퓨터와 단말장치를 서로 이웃한 장치끼리 **Point-to-Point로 연결하여 원형 구성**
- 분산 및 집중 제어 모두 가능
- 단말 추가·제거 및 기밀 보호가 어려움
- 각 단말에서 전송 지연이 발생할 수 있음
- 중계기 수가 많아질 수 있음
- 데이터는 한 방향 또는 양방향으로 전송 가능

> ⭐ `Ring = 원형 연결 / 각 노드를 순차 통과`



### 4. 버스형(Bus)
- 하나의 통신 회선에 여러 단말을 연결
- 물리적 구조가 간단하고 단말 추가·제거가 쉬움
- 단말 장애가 다른 단말에 영향을 거의 주지 않음
- 기밀 보장이 어려움
- 통신 회선 길이에 제한이 있음

> ⭐ `Bus = 하나의 공통 회선`



### 5. 계층형(Tree, 분산형)
- 중앙 컴퓨터와 일정 지역의 단말장치까지 하나의 통신 회선으로 연결하고, 다시 지역별로 분기
- **분산 처리 시스템**을 구성하는 방식

> ⭐ `Tree = 계층적 분기`



### 6. 망형(Mesh)
- 모든 지점의 컴퓨터와 단말장치를 서로 연결
- 노드의 연결성이 높음
- 많은 단말에서 많은 양의 통신을 수행하는 경우 유리
- 특정 공중 데이터 통신망에 사용
- 통신 회선 장애 시 다른 경로를 이용할 수 있어 신뢰성 높음

#### 회선 수
```text
회선 수 = n(n-1) / 2
```

#### 포트 수
```text
포트 수 = n - 1
```

> ⭐ `Mesh = 모든 노드 연결 / 신뢰성↑ / 회선 수↑`



### 7. 네트워크 분류

| 구분 | 핵심 |
|---|---|
| **LAN(Local Area Network)** | 회사·학교·연구소 등 비교적 가까운 지역 / 전송 속도 빠름 / 오류 발생률 낮음 |
| **WAN(Wide Area Network)** | 국가·대륙 등 넓은 지역 / 여러 LAN 연결 / LAN보다 속도 느리고 오류 발생률 높음 |

#### VLAN(Virtual LAN)
- 물리적 배치와 관계없이 LAN을 **논리적으로 분리**하는 기술
- 접속 장비의 성능·보안 등을 향상 가능

> ⭐ `LAN = 근거리` / `WAN = 광대역` / `VLAN = 논리적 LAN 분할`



### 8. LAN 표준 - IEEE 802

| 규격 | 핵심 |
|---|---|
| **802.1** | 전체 OSI 참조 모델과 통신망 관리 |
| **802.2** | LLC(Logical Link Control) |
| **802.3** | CSMA/CD 방식 LAN |
| **802.4** | Token Bus |
| **802.5** | Token Ring |
| **802.6** | MAN |
| **802.9** | 종합 음성/데이터 네트워크 |

### 9. IEEE 802.11 주요 버전

| 규격 | 핵심 |
|---|---|
| **802.11(초기)** | 2.4GHz / CSMA/CA / 최대 약 2Mbps |
| **802.11a** | 5GHz / OFDM / 최대 54Mbps |
| **802.11b** | 2.4GHz / 최대 11Mbps |
| **802.11e** | QoS 향상을 위한 MAC 기능 |
| **802.11g** | 2.4GHz / 802.11a와 동일한 최대 54Mbps |
| **802.11i** | 무선 보안 / WPA·WPA2 |
| **802.11n** | 2.4GHz·5GHz / 최대 600Mbps |

> ⭐ `802.11i = 보안`  
> ⭐ `802.11n = 2.4/5GHz + 최대 600Mbps`



### 10. CSMA/CD와 CSMA/CA

#### CSMA/CD(Carrier Sense Multiple Access / Collision Detection)
- 유선 LAN에서 사용
- 통신 회선의 사용 여부를 확인한 후 데이터 전송
- 충돌 발생 시 전송을 중단하고 일정 시간 후 재전송
- **Collision Detection**

#### CSMA/CA(Carrier Sense Multiple Access / Collision Avoidance)
- 무선 LAN에서 사용
- 데이터 전송 전에 회선 상태를 확인
- 충돌을 **회피(Avoidance)**하는 방식

> ⭐ `CSMA/CD = 유선 / 충돌 검출`  
> ⭐ `CSMA/CA = 무선 / 충돌 회피`

## SECTION 137. 경로 제어 / 트래픽 제어

### 1. 경로 제어(Routing)의 개요
- 송·수신 측 간 전송 경로 중 **최적 패킷 교환 경로를 결정**
- 최적 경로란 가장 경제적이고 효율적으로 데이터를 전달할 수 있는 경로
- 라우터의 **Routing Table**을 이용
- 경로 제어 요소
  - 성능 기준
  - 경로 결정 시간·장소
  - 정보 발생지
  - 경로 정보 갱신 시간



### 2. 경로 제어 프로토콜(Routing Protocol)

#### IGP(Interior Gateway Protocol)
- 하나의 자율 시스템(AS) 내부에서 사용
- 대표 프로토콜
  - **RIP**
  - **OSPF**

##### RIP(Routing Information Protocol)
- 거리 벡터 라우팅 프로토콜
- **Bellman-Ford** 알고리즘 사용
- 인접 라우터와 라우팅 정보 교환
- 최대 홉 수 **15**, 16 이상은 도달 불가로 판단
- 비교적 소규모 네트워크에 적합

> ⭐ `RIP = Distance Vector + Bellman-Ford + 최대 15 Hop`

##### OSPF(Open Shortest Path First)
- RIP의 단점을 개선
- 대규모 네트워크에서 많이 사용
- 라우팅 정보 변화 시 관련 정보만 전달
- **Dijkstra** 알고리즘 사용

> ⭐ `OSPF = Link State + Dijkstra`

#### EGP(Exterior Gateway Protocol)
- 자율 시스템(AS)과 자율 시스템 사이의 라우팅 프로토콜

#### BGP(Border Gateway Protocol)
- 자율 시스템 간에 사용하는 대표적인 라우팅 프로토콜
- 초기에는 전체 라우팅 정보를 교환하고 이후에는 변경된 정보만 교환

> ⭐ `IGP = AS 내부` / `EGP·BGP = AS 간`


### 3. 트래픽 제어(Traffic Control)의 개요
- 네트워크의 보호, 성능 유지, 네트워크 자원의 효율적 이용을 위해
  - 전송되는 패킷의 흐름
  - 패킷의 양

  등을 조절
- 주요 기능
  - 흐름 제어
  - 폭주(혼잡) 제어
  - 교착상태 방지



### 4. 흐름 제어(Flow Control)
- 송·수신 측 사이에 전송되는 패킷의 양·속도를 조절
- 송신 측이 수신 측보다 너무 빠르게 데이터를 보내서 발생하는 **Overflow 방지**

#### Stop-and-Wait
- 한 번에 하나의 패킷을 전송한 뒤 수신 측의 **ACK를 기다림**
- ACK를 받은 후 다음 패킷 전송

#### Sliding Window
- ACK를 기다리지 않고 여러 프레임을 연속적으로 전송
- 수신 측이 한 번에 받을 수 있는 프레임 수를 **Window Size**로 설정
- ACK 상태에 따라 Window를 이동하며 전송

> ⭐ `Stop-and-Wait = 1개 보내고 ACK 대기`  
> ⭐ `Sliding Window = 여러 개 연속 전송`



### 5. 폭주(혼잡) 제어(Congestion Control)
- 네트워크 내 패킷 수를 조절하여 **Overflow 방지**

#### Slow Start
- Window 크기를 1, 2, 4, 8...처럼 점차 증가
- 초기에는 느리지만 혼잡이 없으면 빠르게 증가

#### Congestion Avoidance
- Slow Start 이후 혼잡 가능성을 고려해 Window 크기를 **완만하게 증가**

> ⭐ `Slow Start = 급격한 증가`  
> ⭐ `Congestion Avoidance = 완만한 증가`



### 6. 교착상태(Dead Lock) 방지
- 교환기 내부에 패킷이 축적되어 기억 공간이 부족하고 패킷이 움직이지 못하는 상태를 방지
- 교착상태 발생 시 교착상태에 있는 단말장치를 선택하여 **패킷 버퍼를 제거**

## SECTION 140. HW 관련 신기술

### 1. 고가용성 솔루션(HACMP; High Availability Clustering Multi Processing)
- 긴 시간 동안 안정적인 서비스 운영을 위해 장애 발생 시 다른 시스템으로 **즉시 대체**
- 각 시스템 간 공유 디스크를 중심으로 클러스터링
- 두 개 이상의 서버를 연결하여 **이중화**
- 서비스 안정성 향상

> ⭐ `HACMP = 서버 이중화 + 장애 시 즉시 대체`



### 2. 3D Printing
- 대상을 평면에 출력하는 것이 아니라 **손으로 만질 수 있는 실제 물체로 제작**
- 얇은 두께의 층을 반복 적층하여 하나의 형태를 생성
- 의료·자동차·항공우주·전자·공구 제작·디자인 등 다양한 분야 활용


### 3. 4D Printing
- 3D Printing으로 만든 제품이 시간이나 환경 조건에 따라 **형태를 변화시키거나 스스로 조립**
- 특정 환경
  - 열
  - 진동
  - 습도
  - 중력

  등에 반응하는 스마트 소재 활용

> ⭐ `3D = 입체 출력`  
> ⭐ `4D = 환경·시간에 따라 형태 변화`



### 4. RAID(Redundant Array of Inexpensive/Independent Disk)
- 여러 하드디스크로 하나의 논리적 디스크를 구성
- 데이터를 여러 디스크에 분산 저장하여
  - 속도 향상
  - 신뢰성 향상
  - 장애 복구

  를 지원
- 장애 발생 시 다른 디스크의 데이터를 이용해 복구
- 구성 방법에 따라 **RAID 0 ~ RAID 5** 등 다양한 수준 존재

> ⭐ `RAID = 여러 Disk를 묶어 성능·신뢰성 향상`


### 5. N-Screen
- 여러 종류의 단말기에서 **동일한 콘텐츠를 끊김 없이 자유롭게 이용**할 수 있는 서비스
- PC, TV, 휴대폰 등 서로 다른 기기에서 연속적으로 콘텐츠 이용

> ⭐ `N-Screen = 여러 Screen에서 동일 콘텐츠`

## SECTION 141. Secure OS

### 1. Secure OS의 개요
- 기존 운영체제의 보안 취약점을 보완하기 위해 **커널에 보안 기능을 추가한 운영체제**
- 외부 침입으로부터 시스템 자원을 보호
- 보안 기능을 갖춘 커널을 **보안 커널(Security Kernel)**이라고 함
- 보안 커널의 보호 대상
  - 메모리
  - 보조기억장치
  - 저장 자료
  - 하드웨어 장치
  - 자료 구조
  - 명령어
  - 각종 보호 메커니즘 등


### 2. 보호 방법

| 보호 방법 | 핵심 |
|---|---|
| **암호적 분리(Cryptographic Separation)** | 내부 정보를 암호화하여 보호 |
| **논리적 분리(Logical Separation)** | 프로세스의 논리적 구역을 지정하여 다른 프로세스의 접근을 제한 |
| **시간적 분리(Temporal Separation)** | 동일 시간에 하나의 프로세스만 수행되도록 하여 동시 접근 방지 |
| **물리적 분리(Physical Separation)** | 사용자별로 특정 장비만 사용하도록 제한 |

> ⭐ Secure OS 보호 → `암·논·시·물`



### 3. 참조 모니터(Reference Monitor)
- 보호 대상 객체에 대한 **접근 통제**를 수행하는 추상적 개념
- 보안 커널 데이터베이스(SKDB)를 참조하여 객체 접근 허가 여부 결정

#### 참조 모니터의 3대 특징
- **격리성(Isolation)** - 부정 조작이 불가능
- **검증 가능성(Verifiability)** - 적절하게 구현되었음을 확인 가능
- **완전성(Completeness)** - 모든 접근 요청을 검사

> ⭐ Reference Monitor = `격·검·완`



### 4. Secure OS의 보안 기능

| 기능 | 핵심 |
|---|---|
| **식별 및 인증** | 각 접근 주체에 대한 안전한 식별·인증 |
| **임의적 접근 통제(DAC)** | 소유자 또는 권한을 가진 주체가 객체 접근 권한 설정 |
| **강제적 접근 통제(MAC)** | 보안 등급·정책에 따라 강제로 접근 통제 |
| **객체 재사용 보호** | 메모리·디스크 등 재사용 시 이전 정보 노출 방지 |
| **완전한 조정** | 우회할 수 없도록 모든 접근 경로 통제 |
| **신뢰 경로** | 비밀번호 변경 등 보안 작업을 위한 안전한 경로 제공 |
| **감사 및 감사기록 축소** | 보안 관련 사건 기록 및 분석 지원 |

> ⭐ `DAC = 소유자 중심`  
> ⭐ `MAC = 보안 정책·등급 중심`

## SECTION 142. DB 관련 신기술

### 1. 빅데이터(Big Data)
- 기존 관리·분석 방법으로 처리하기 어려울 정도로 **대량 또는 비정형 데이터의 집합**
- 기업·정부 등에서 대량 데이터를 분석해 새로운 가치와 미래 경쟁력을 확보하는 데 활용



### 2. 브로드 데이터(Broad Data)
- 다양한 채널에서 소비자와 상호작용을 통해 생성된 **다양한 데이터**
- 빅데이터처럼 단순히 대량 자료만 뜻하는 것이 아니라, 다양한 정보와 기존 데이터까지 포함하여 활용

> ⭐ `Big Data = 대량 중심`  
> ⭐ `Broad Data = 다양한 채널·종류의 데이터`



### 3. 메타 데이터(Meta Data)
- **데이터에 대한 데이터**
- 데이터의 속성·구조·위치·작성자 등을 설명
- 빠른 검색과 체계적인 관리를 위해 사용

> ⭐ `Meta Data = Data를 설명하는 Data`



### 4. 디지털 아카이빙(Digital Archiving)
- 디지털 정보 자원을 장기적으로 보존하기 위한 작업
- 디지털 자료를 일정한 구조와 규칙에 따라 분류하여 저장

> ⭐ `Digital Archiving = 디지털 자료의 장기 보존`



### 5. 하둡(Hadoop)
- 오픈 소스 기반의 **분산 컴퓨팅 플랫폼**
- 일반 PC급 컴퓨터들로 가상화된 대형 스토리지를 구성
- 대용량 데이터를 분산 저장·처리
- 주요 기술
  - **HDFS**
  - **MapReduce**
- DB와 대용량 데이터 전송 시 **Sqoop** 등의 도구 사용

> ⭐ `Hadoop = HDFS + MapReduce`  
> ⭐ `Sqoop = Hadoop ↔ 관계형 DB 데이터 전송`

---

### 6. 맵리듀스(MapReduce)
- 대용량 데이터를 분산 처리하기 위한 프로그래밍 모델
- 데이터를 분산 처리하는 **Map**
- 필요한 결과를 모아 추출하는 **Reduce**

> ⭐ `Map = 분산 처리` / `Reduce = 결과 집계`



### 7. 타조(Tajo)
- 오픈 소스 기반 분산 컴퓨팅 플랫폼
- 아파치 하둡 기반의 **분산 데이터 웨어하우스 프로젝트**
- HDFS를 이용
- MapReduce를 사용하지 않고 **SQL을 이용하여 데이터 처리**
- 대규모 데이터 처리와 실시간 상호 분석에 활용

> ⭐ `Tajo = Hadoop 기반 + SQL 분석`


### 8. 데이터 다이어트(Data Diet)
- 데이터를 삭제하는 것이 아니라
  - 압축
  - 중복 정보 제거
  - 새로운 기준으로 재구성

  하여 데이터 양을 줄이는 작업

> ⭐ `Data Diet = 삭제 X / 압축·중복 제거`



### 9. 데이터 마이닝(Data Mining)
- 대량의 데이터에서 **사용자의 요구에 따라 유용한 정보를 추출**
- 데이터 속에 내재한 변수 사이의 상호관계를 규명하여 일정한 패턴을 찾아냄

> ⭐ `Data Mining = 대량 데이터 → 패턴·유용 정보 추출`


### 10. OLAP(Online Analytical Processing)
- 다차원 데이터로부터 **통계적 요약 정보를 분석하여 의사결정에 활용**
- 데이터 마트 등과 연관된 정보 시스템

#### OLAP 연산
- **Roll-up** - 상세 데이터 → 요약 데이터
- **Drill-down** - 요약 데이터 → 상세 데이터
- **Drill-through** - OLAP에서 원천 상세 데이터까지 접근
- **Drill-across** - 다른 큐브·사실 테이블 간 비교
- **Pivoting** - 분석 관점을 회전
- **Slicing** - 한 차원의 특정 값으로 잘라 보기
- **Dicing** - 여러 차원의 범위를 선택하여 부분 큐브 생성

> ⭐ `Roll-up = 요약`  
> ⭐ `Drill-down = 상세`

## SECTION 143. 회복 / 병행제어

### 1. 회복(Recovery)
- 트랜잭션 수행 중 장애가 발생하여 DB가 손상되었을 때 **정상 상태로 복구하는 작업**

#### 장애 유형

| 장애 | 핵심 |
|---|---|
| **트랜잭션 장애** | 입력 오류, 불명확한 데이터, 시스템 자원 요구 과다 등으로 트랜잭션이 비정상 종료 |
| **시스템 장애** | 하드웨어 오동작, 운영체제 오류, 전원 장애 등으로 트랜잭션 수행 장애 |
| **미디어 장애** | 디스크 손상·헤드 충돌 등으로 DB 일부 또는 전체가 물리적으로 손상 |


### 2. 회복 관리자(Recovery Management)
- DBMS의 구성 요소
- 트랜잭션 실행 도중 장애가 발생하면
  - 로그
  - 백업

  등을 이용하여 DB를 복구
- **Redo, Undo**를 이용

> ⭐ `Undo = 이전 상태로 취소`  
> ⭐ `Redo = 정상적으로 완료된 작업을 다시 실행`


### 3. 회복 기법

#### 연기 갱신 기법(Deferred Update)
- 트랜잭션이 **성공적으로 완료될 때까지 DB 갱신을 연기**
- 트랜잭션 수행 중에는 갱신 내용을 **Log에 기록**
- Commit 이후 실제 DB에 반영
- 장애 발생 시 **Redo** 작업 필요
- Commit 전 DB에 반영하지 않았으므로 일반적으로 Undo 불필요

> ⭐ `Deferred = Commit 후 DB 반영 → Redo 중심`

#### 즉각 갱신 기법(Immediate Update)
- 트랜잭션 수행 중 갱신 결과를 **즉시 DB에 반영**
- 변경 내용을 Log에 기록
- 장애 발생 시 상황에 따라 **Undo / Redo** 사용

> ⭐ `Immediate = 즉시 반영 → Undo + Redo`

#### 그림자 페이지 대체 기법(Shadow Paging)
- DB를 일정 크기의 페이지 단위로 구성
- 현재 페이지와 복사본인 **Shadow Page**를 유지
- 장애 발생 시 Shadow Page를 이용해 복구
- Log를 사용하지 않고 복구 가능

> ⭐ `Shadow Paging = 페이지 복사본 이용 / Log 없이 복구`

#### 검사점 기법(Check Point)
- 트랜잭션 실행 중 일정 시점에 **Checkpoint**를 생성
- 장애 발생 시 Checkpoint 이후의 처리만 회복
- 회복 작업의 양을 줄임

> ⭐ `Checkpoint = 특정 시점 저장 → 이후만 복구`

### 4. 병행제어(Concurrency Control)
- 여러 개의 트랜잭션을 **동시에 실행하면서도 DB의 일관성을 유지**하도록 제어

#### 목적
- 데이터베이스의 공유 최대화
- 시스템 활용도 최대화
- DB 일관성 유지
- 사용자 응답 시간 최소화

> ⭐ 병행제어 = `공유↑ / 활용도↑ / 일관성 유지 / 응답시간↓`

### 5. 병행제어 기법

#### 로킹(Locking)
- 트랜잭션이 데이터에 접근하기 전에 **Lock을 요청**
- Lock을 획득한 후 사용
- 사용이 끝나면 Unlock
- 대표적인 병행제어 기법

#### 타임 스탬프 순서(Time Stamp Ordering)
- 트랜잭션 처리 순서를 결정하기 위해 **고유한 Timestamp**를 부여
- 시간 순서대로 처리하여 직렬성 보장

#### 최적 병행 수행/검증 기법(Validation)
- 트랜잭션 수행 중에는 별도 검사를 하지 않고
- Commit 직전에 검증하여 DB 반영 여부 결정

#### 다중 버전 기법(MVCC; Multi-Version Concurrency Control)
- 하나의 데이터에 대해 여러 버전을 유지
- 트랜잭션별로 적절한 버전을 읽도록 하여 병행성 향상

> ⭐ `Locking / Timestamp / Validation / MVCC`

### 6. 로킹 단위(Locking Granularity)
- 한 번에 Lock을 설정할 수 있는 **객체의 크기**

#### 로킹 단위가 큰 경우
- Lock 수 감소
- 관리가 쉬움
- 병행성 수준 **감소**
- DB 공유도 감소

#### 로킹 단위가 작은 경우
- Lock 수 증가
- 관리 부담 증가
- 병행성 수준 **증가**
- DB 공유도 증가

> ⭐ `Lock 단위 ↑ → Lock 수 ↓ / 병행성 ↓`  
> ⭐ `Lock 단위 ↓ → Lock 수 ↑ / 병행성 ↑`

## SECTION 144. 교착상태

### 1. 교착상태(Dead Lock)의 개요
- 둘 이상의 프로세스가 자원을 점유한 상태에서 **서로 다른 프로세스가 가진 자원을 기다리며 무한정 대기하는 상태**
- 서로 필요한 자원을 놓지 않아 아무 작업도 진행되지 않음

> ⭐ `Deadlock = 서로 자원을 잡고 상대 자원을 무한 대기`


### 2. 교착상태 발생의 필요 충분 조건
교착상태가 발생하려면 다음 **4가지 조건이 모두 성립**해야 함

| 조건 | 핵심 |
|---|---|
| **상호 배제(Mutual Exclusion)** | 한 번에 한 프로세스만 공유 자원 사용 |
| **점유와 대기(Hold and Wait)** | 자원을 가진 상태에서 다른 자원을 추가로 기다림 |
| **비선점(Non-preemption)** | 다른 프로세스가 가진 자원을 강제로 빼앗을 수 없음 |
| **환형 대기(Circular Wait)** | 프로세스들이 원형으로 서로의 자원을 기다림 |

> ⭐ Deadlock 4조건 → `상·점·비·환`


### 3. 교착상태 해결 방법

| 방법 | 핵심 |
|---|---|
| **예방 기법(Prevention)** | 교착상태 4조건 중 하나가 성립하지 않도록 미리 제거 |
| **회피 기법(Avoidance)** | 교착상태 가능성을 피해 안전한 상태로 자원 할당 / **Banker's Algorithm** 사용 |
| **발견 기법(Detection)** | 교착상태가 발생했는지 주기적으로 검사 |
| **회복 기법(Recovery)** | 교착상태 프로세스를 종료하거나 자원을 선점하여 해결 |

> ⭐ `Prevention = 발생 조건 제거`  
> ⭐ `Avoidance = Banker's Algorithm`  
> ⭐ `Detection = 발생 여부 검사`  
> ⭐ `Recovery = 발생 후 강제 해결`
